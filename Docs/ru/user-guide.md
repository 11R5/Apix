# Руководство пользователя Apix

Apix — настольный API-клиент: вы составляете HTTP-запросы, отправляете их и
читаете ответы. Запросы хранятся в папке как небольшие текстовые файлы, поэтому
коллекция может лежать в git рядом с вашим кодом. Это руководство описывает
приложение; в разделе [сценарии работы](workflows.md) частые задачи разобраны
по шагам, а командная строка `apix` выполняет те же запросы в терминале или в CI.

## Установка Apix

Страница загрузки, **https://11r5.github.io/Apix/**, предлагает последний
выпуск для вашей системы; все файлы есть также на
[странице релизов](https://github.com/11R5/Apix/releases). Каждый файл содержит
настольное приложение и командную строку `apix`.

| Система | Файл | Как установить |
|---|---|---|
| Windows 10/11 | `Apix-<version>-windows-x64-setup.exe` | Запустите его. Он устанавливает Apix для вашего пользователя без прав администратора (или для всех, если вы так выберете), добавляет Apix в меню «Пуск» и может добавить `apix` в PATH и открывать файлы `.apix`. `…-windows-x64.zip` — то же самое без установки. |
| macOS 11+ | `Apix-<version>-macos-universal.dmg` | Откройте его и перетащите Apix в «Программы»; одно приложение для Apple silicon и Intel. Командная строка — `/Applications/Apix.app/Contents/MacOS/apix`. Или `brew install --cask 11r5/apix/apix`, что также добавляет `apix` в PATH. |
| Debian, Ubuntu, Mint, … | `apix_<version>_amd64.deb` | `sudo apt install ./apix_<version>_amd64.deb` |
| Arch, Manjaro, EndeavourOS, … | `apix-<version>-1-x86_64.pkg.tar.zst` | `sudo pacman -U ./apix-<version>-1-x86_64.pkg.tar.zst` или `makepkg -si` с `PKGBUILD` из релиза |
| Другой Linux (glibc 2.35+) | `apix-<version>-linux-x64.tar.gz` | Распакуйте и запустите `./install.sh` (для вашего пользователя; `--system` — для всех, `--uninstall` — удалить) |
| Любой Linux, один файл | `Apix-<version>-x86_64.AppImage` | Сделайте его исполняемым (`chmod +x`) и запустите; `Apix-….AppImage cli …` запускает командную строку |

Сборки не подписаны (подпись кода стоит денег каждый год, поэтому пока она не
планируется). В Windows SmartScreen может остановить установщик: **Подробнее ›
Выполнить в любом случае**. В macOS в первый раз откройте Apix через правый
щелчок › **Открыть** или выполните `xattr -dr com.apple.quarantine
/Applications/Apix.app`. В Linux Apix рисует через Vulkan, поэтому графический
драйвер должен поддерживать Vulkan (в большинстве систем это обеспечивает Mesa).
`SHA256SUMS.txt` в каждом релизе содержит контрольные суммы файлов.

## Открытие коллекции

**Коллекция** — это папка с файлом `apix.toml` и вашими запросами (файлами
`.apix`), при желании разложенными по подпапкам. Откройте её через **Файл ›
Открыть…** (Ctrl+O) или создайте новую через **Файл › Новая коллекция…**. Если
выбранная папка ещё не коллекция, Apix предложит сделать её коллекцией.

Недавно открытые коллекции находятся в **Файл › Открыть недавние**. Если
запустить приложение с папкой (`apix-desktop path/to/collection`), она откроется
сразу.

## Окно

- **Боковая панель (слева):** папки и запросы коллекции. Они читаются из файлов
  на диске и обновляются, когда файлы меняются. Список под именем коллекции
  выбирает активное окружение.
- **Вкладки (сверху):** каждый открытый запрос получает вкладку.
- **Панель запроса:** метод, URL и вкладки «Параметры», «Заголовки»,
  «Авторизация», «Тело» и «Настройки».
- **Панель ответа (справа):** статус, время, размер и тело ответа.
- **Строка состояния (внизу):** коллекция, файл открытого запроса и самые
  полезные сочетания клавиш.
- **Строка меню:** в меню «Файл», «Запрос», «Окружение», «Вид» и «Справка»
  есть все команды.

## Отправка запроса

1. Выберите метод слева от адресной строки (или нажмите Alt+1…7 для GET, POST,
   PUT, PATCH, DELETE, HEAD, OPTIONS).
2. Введите URL. `{{variables}}` можно писать где угодно (см.
   [Переменные](#переменные-и-окружения)).
3. Нажмите **Отправить** или Ctrl+Enter. Esc отменяет запрос, который ещё
   выполняется.

Пока активно окружение, в имени которого есть «prod», Apix спрашивает перед
отправкой DELETE, PUT или PATCH и показывает полный URL, на который уйдёт
запрос. **Настройки › Подтверждение в продакшене** отключает это.

**Новый запрос** (Ctrl+N) открывает запрос GET; меню **+** на боковой панели
предлагает все методы, а POST, PUT и PATCH начинаются с JSON-тела. Сохранение —
Ctrl+S. Точка на вкладке и на боковой панели отмечает несохранённые изменения.

## Параметры и заголовки

**Параметры** — это строка запроса в URL, **Заголовки** отправляются как есть.
Снимите флажок со строки, чтобы она осталась в файле, но не отправлялась. Строка
без ключа игнорируется. `Content-Type` берётся из типа тела, если вы не задали
свой. `{{variables}}` в ключах и значениях показываются как метки, как в
адресной строке; наведите на метку, чтобы увидеть её значение.

Адресная строка и таблица «Параметры» синхронизированы: если ввести
`?page=2&sort=name` в URL, таблица заполнится, а изменение, добавление, снятие
флажка или удаление строки переписывает URL. Значения показываются
декодированными (`%20` становится пробелом) и кодируются при отправке запроса.
В файле URL хранится без строки запроса, а строки — как `[[query]]`.

**Переменные пути.** Сегмент пути вида `:name`, как в
`{{base}}/users/:id/posts`, получает строку в разделе **Переменные пути** на
вкладке «Параметры». При отправке её значение заменяет сегмент и кодируется как
один сегмент (`a b/c` становится `a%20b%2Fc`); `{{variables}}` в нём работают.
Пустая переменная отправляется как написана. Значения хранятся в файле как
`[[path]]`, коллекции Postman приносят свои (и получают их обратно при экспорте).

![Параметры и переменные пути](../en/images/path-variables.png)

**Подсказки заголовков.** Пока вы вводите имя заголовка, под строкой
появляются подходящие стандартные имена (сначала те, что начинаются с
введённого, и ни одного из уже имеющихся в таблице); для значения предлагаются
обычные значения этого заголовка, например `application/json` для
`Content-Type`. Enter берёт первую подсказку, щелчок — любую, а после имени
следующим идёт значение.

![Имена заголовков, предложенные при вводе](../en/images/header-hints.png)

## Тело запроса

Вкладка «Тело» предлагает:

| Тип | Что отправляется |
|---|---|
| Нет | Без тела. |
| JSON, Текст, XML, HTML | Текст как написан, с подсветкой синтаксиса (`application/json`, `text/plain`, `application/xml`, `text/html`, если заголовок не говорит иначе). |
| Форма | Строки ключ–значение `application/x-www-form-urlencoded`. |
| Multipart | `multipart/form-data`. Каждое поле — **Текст** или **Файл**; кнопка с папкой выбирает один или несколько файлов. Поле типа рядом задаёт собственный Content-Type поля (например `application/json` или `image/png`); если оно пустое, Apix выбирает сам. |
| Двоичные данные | Байты одного файла как `application/octet-stream`, если заголовок не говорит иначе. Apix показывает размер файла или «Файл не найден». |
| GraphQL | Редактор запроса и редактор переменных JSON; отправляется как JSON `{"query", "variables"}`. |

![Тело multipart](../en/images/body.png)

Пути к файлам внутри коллекции сохраняются относительно файла запроса, поэтому
коллекция работает и на другом компьютере.

### Схема GraphQL и автодополнение

**Получить схему** над запросом запрашивает у сервера его схему (стандартным
запросом интроспекции) с URL, заголовками, авторизацией и окружением запроса,
так что схема за токеном тоже доступна. Затем:

- При вводе запроса предлагается то, что подходит в позиции курсора: поля
  выбираемого типа (с их типами), аргументы поля после `(`, значения enum и
  `true`/`false` после `:`, поля входного объекта, фрагменты `... on Type` для
  union и интерфейсов и имена типов после `on` или в `$variable: Type`.
  Устаревшие поля идут последними. Ctrl+Space открывает подсказки без ввода.
- При наведении на поле, аргумент или значение enum показываются его тип и
  описание.
- В редакторе переменных ключами предлагаются переменные, объявленные в
  запросе (`$role: Role`), а для значений — поля входных объектов, значения
  enum (как строки JSON) и `true`/`false`.
- **Показать схему** выводит всю схему рядом с запросом в виде SDL.

![Автодополнение по схеме](../en/images/graphql.png)

Apix хранит схему каждого адреса (в папке конфигурации, в `graphql/`) и снова
загружает её, когда вы открываете запрос на этот URL, поэтому **Обновить
схему** нужна только при изменении API. Сервер с отключённой интроспекцией
отвечает ошибкой, и она показывается на месте статуса схемы.

В командной строке `apix schema request.apix` выводит схему в виде SDL
(`--json` выводит ответ сервера как есть).

## Авторизация

Вкладка «Авторизация» задаёт, как запрос подтверждает, кто его отправил:

| Тип | Примечания |
|---|---|
| Наследовать от родителя | По умолчанию: используется авторизация ближайшей папки, коллекции или проекта, где она задана. Вкладка показывает, что это и откуда берётся. |
| Без авторизации | Ничего не отправлять, даже если родитель задаёт авторизацию. |
| Bearer-токен | `Authorization: Bearer <token>`. |
| Basic auth | Имя пользователя и пароль. |
| API-ключ | Заголовок или параметр запроса на ваш выбор. |
| Digest auth | Apix отвечает на Digest-запрос сервера (MD5 или SHA-256). |
| OAuth 1.0 | HMAC-SHA1, HMAC-SHA256 или PLAINTEXT; в заголовке или в строке запроса; при каждой отправке новые nonce и временная метка. |
| OAuth 2.0 | Client credentials, password или authorization code с PKCE. Apix сам получает токен и отправляет его как Bearer-токен. |
| AWS Signature | AWS Signature Version 4 с ключом доступа, секретным ключом, необязательным токеном сессии, регионом и сервисом. |

![OAuth 2.0 на вкладке «Авторизация»](../en/images/auth.png)

**Токены OAuth 2.0.** Первая отправка получает токен; следующие используют его
повторно и обновляют через refresh-токен, когда срок действия истекает.
**Получить новый токен** получает токен сразу, **Забыть** удаляет его. Токены
хранятся только в памяти и никогда не записываются на диск. Для authorization
code Apix открывает страницу входа в вашем браузере и принимает ответ на
`http://127.0.0.1` (на свободном порту или на **URL перенаправления**, который
вы зарегистрировали для клиента).

**Общая авторизация.** Щёлкните правой кнопкой по папке или коллекции и
выберите **Авторизация…**, чтобы один раз задать авторизацию для всего
содержимого; **Окружение › Авторизация проекта…** делает то же для целого
проекта. Её используют запросы с авторизацией *Наследовать от родителя*.

## Настройки запроса

Вкладка «Настройки» управляет тем, как запрос передаётся:

| Настройка | По умолчанию |
|---|---|
| Тайм-аут (секунды) | нет — запрос выполняется, пока не завершится или пока вы его не отмените; `0` тоже означает «без тайм-аута» |
| Следовать перенаправлениям | вкл. |
| Макс. перенаправлений | 10 |
| Проверять сертификат TLS | вкл. — отключайте только для тестовых серверов, которым доверяете |
| Прокси | из окружения (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`); *Выкл.* их игнорирует; URL явно задаёт прокси |
| Клиентский сертификат | нет — файл PEM, ключ в том же файле или в отдельном |
| Доверенный УЦ | только обычные корневые сертификаты — файл PEM добавляет ваши собственные центры сертификации (корпоративный или самоподписанный УЦ), так что сервер всё равно проверяется |
| Отправлять cookie | вкл. |

Каждое пустое поле (или поле в положении *Наследовать*) берёт значение у
ближайшей папки, коллекции или проекта, где оно задано, и в конце — у значений
по умолчанию выше; цепочка та же, что у авторизации. Щёлкните правой кнопкой по
папке или коллекции и выберите **Настройки запросов…**, чтобы один раз задать
их для всего содержимого; **Окружение › Настройки запросов проекта…** делает
то же для целого проекта. Строка под формой показывает, что запрос в итоге
использует. `{{variables}}` работают в полях прокси и сертификатов, а
относительные пути к сертификатам отсчитываются от файла, в котором они заданы.

В файле запроса (а также в `folder.toml`, `apix.toml` и `apix-project.toml`)
настройки — это таблица `[settings]`:

```toml
[settings]
timeout_ms = 5000
tls_verify = false
proxy = ""          # "" = без прокси, даже если окружение его задаёт
client_cert = "certs/client.pem"
ca_cert = "certs/company-ca.pem"
```

**Копировать как** записывает соответствующие флаги curl (`-m`,
`-L --max-redirs`, `-k`, `-x`, `--cert`, `--key`, `--cacert`), а вставка
команды curl с этими флагами заполняет вкладку. У `apix send` и `apix run`
есть `--timeout`, `--insecure`, `--proxy` и `--cacert`, которые перекрывают
файл. Эти настройки действуют и для запросов gRPC. Параметры отдельных
запросов Postman (`protocolProfileBehavior`) импортируются.

## Cookie

Apix хранит одно хранилище cookie: ответы `Set-Cookie` сохраняются
автоматически и отправляются с последующими запросами к тому же сайту, в том
числе после перезапуска (`cookies.json` рядом с настройками приложения;
сеансовые cookie исчезают вместе с приложением). **Запрос › Cookie…** выводит
их список, удаляет отдельные cookie или очищает хранилище. **Отправлять cookie**
на вкладке «Настройки» отключает хранилище для запроса, папки, коллекции или
проекта. CLI при каждом запуске начинает с пустого хранилища.

## Переменные и окружения

Напишите `{{name}}` в URL, заголовке, теле или поле авторизации, и Apix
подставит значение при отправке. В адресной строке каждая переменная — цветная
метка: наведите на неё, чтобы увидеть значение и его источник; красная метка
означает, что переменная нигде не задана.

Значения берутся из слоёв, более поздний побеждает:

1. Переменные **проекта** (общие для всех коллекций проекта)
2. Переменные **коллекции** (`apix.toml`)
3. Активное **окружение** (`environments/<name>.toml`)

Чтобы изменить их, откройте **Окружение › Переменные и окружения…** (Ctrl+E).
Отметьте **Секрет** для токенов и паролей: секретные значения хранятся в
`environments/<name>.local.toml`, который Apix добавляет в `.gitignore`, так
что они никогда не попадают в коммит.

Чтобы они не хранились и на диске, выберите **Настройки › Секреты окружений ›
Системное хранилище ключей**. Тогда значения уходят в системное хранилище
учётных данных (Диспетчер учётных данных в Windows, Связка ключей в macOS,
Secret Service в Linux), а `<name>.local.toml` хранит только идентификатор этой
записи, поэтому переименование окружения или перенос папки ничего не ломают.
Командная строка `apix` читает их так же. Изменение настройки сразу переносит
секреты открытой коллекции или проекта; остальные переносятся при следующем
сохранении. Секреты зашифрованной коллекции всегда остаются внутри неё.

![Диалог «Переменные»](../en/images/variables.png)

**Динамические переменные** получают новое значение при каждом использовании:
`{{$guid}}`, `{{$timestamp}}`, `{{$isoTimestamp}}`, `{{$randomInt}}`,
`{{$randomEmail}}` и другие; страница **Динамические переменные** в диалоге
«Переменные» перечисляет их все с примером значения.

## Ответ

Панель ответа показывает статус, время до первого байта и общее время, а также
размер. **Форматированный** форматирует JSON (блоки сворачиваются стрелками) и
добавляет отступы и цвета в XML и HTML; **Исходный** показывает тело как оно
пришло, **Заголовки** перечисляет заголовки ответа, а **Hex** показывает байты.
Очень большие тела (десятки мегабайт) открываются в быстром просмотрщике,
который рисует только видимые строки.

Apix определяет вид тела по `Content-Type`, а если тип ничего полезного не
говорит, — по байтам. Изображения (PNG, JPEG, GIF, WebP, BMP, SVG)
показываются во вкладке **Форматированный**; для другого двоичного содержимого
(PDF, zip…) вместо нечитаемого текста выводится краткая сводка. HTML, в котором
опущены необязательные закрывающие теги, показывается как пришёл, без
переформатирования.

Кнопка **↓** в конце строки состояния сохраняет тело в файл байт в байт.
Предлагаемое имя берётся из `Content-Disposition` сервера или из URL, с
расширением, подходящим к содержимому.

**Поиск.** Ctrl+F в теле или лупа в строке состояния ищет во вкладках
**Форматированный**, **Исходный** и **Hex** без учёта регистра. Enter (или F3)
переходит к следующему совпадению, а Shift+Enter (Shift+F3) — к предыдущему;
счётчик показывает, где вы находитесь. Быстрый просмотрщик для очень больших
тел ищет по всему телу в фоне и перестаёт считать после 100 000 совпадений.

**Фильтр.** У JSON-ответа над вкладкой **Форматированный** есть поле фильтра.
Выражение, начинающееся с `$`, — это JSONPath (RFC 9535), всё остальное — jq,
поэтому работают оба варианта:

```text
$.users[?@.active].email
.users[] | select(.active) | {name, email}
```

![JSON-ответ, отфильтрованный через JSONPath](../en/images/response-filter.png)

Пока в поле есть выражение, результат заменяет тело на вкладке
**Форматированный** (счётчик рядом показывает число значений); **Исходный** и
**Hex** по-прежнему показывают всё тело, а ✕ возвращает его. JSONPath даёт
список совпадений, jq — свои результаты один за другим. Фильтр сохраняется для
следующего ответа того же запроса, так что можно отправлять запрос снова и
снова, следя за одним значением. `apix send --filter '<expression>'` выводит
только то, что выбрал фильтр.

**Таблица и график.** **Текст**, **Таблица** и **График** в конце строки
фильтра показывают JSON-ответ (или то, что выбрал фильтр) как текст, как
таблицу его записей или как столбчатую диаграмму. Записи — это массив в теле
или самый длинный массив объектов внутри него (`$.items`, `$.data`); каждый
ключ — столбец, вложенные объекты показываются как компактный JSON. График
строит один числовой столбец (**Значение**) по столбцу, который называет строки
(**Подпись**); оба можно выбрать. Тела больше 8 МБ в таблицу не превращаются:
сначала отфильтруйте их. `apix send --table` выводит ту же таблицу в терминале
(с `--filter` — для выбранного фильтром). Шаблоны `pm.visualizer.set` из
Postman не отрисовываются, так как в Apix нет веб-представления; скрипты,
которые их вызывают, получают примечание в консоли.

![Вид «Таблица» для отфильтрованного ответа](../en/images/visual-table.png)

![Вид «График»](../en/images/visual-chart.png)

**Примеры.** Кнопка с лотком в строке состояния сохраняет ответ как пример
запроса: его статус, заголовки и тело, а также запрос, из которого он получен,
в исходном виде (`{{variables}}` остаются, поэтому ни один токен не попадает в
файл). Cookie, которые устанавливает сервер, не сохраняются, а тела больше
2 МБ не принимаются. Вкладка **Примеры** запроса перечисляет их: пример можно
переименовать на месте, ▷ показывает его в панели ответа (с пометкой
«Пример: …»), а корзина удаляет. Примеры — часть запроса, поэтому Ctrl+S
записывает их в его файл как `[[example]]`, а сохранённые ответы Postman при
импорте становятся примерами и при экспорте уходят обратно.
`apix send --save-example '<name>'` сохраняет ответ из командной строки.

![Пример в панели ответа](../en/images/examples.png)

Если панель слишком узкая для всех вкладок запроса, стрелка в конце полосы
вкладок показывает их полный список.

## Вкладка «Сеть»

Вкладка **Сеть** объясняет, на что ушло время и каким было соединение:

- полоса времени, разделённая на DNS, TCP-соединение, рукопожатие TLS, ожидание
  и загрузку
- ответы DNS, адрес сервера и локальный адрес, сетевой интерфейс (с подсказкой,
  если используется VPN), шлюз, DNS-серверы и прокси
- каждое перенаправление
- сжатое тело: его кодировка, размер при передаче и после распаковки
- шифрование: версия TLS, набор шифров, обмен ключами, ALPN (`h2`, когда сервер
  говорит на HTTP/2), отправленное имя сервера (SNI) и длительность рукопожатия
- цепочка сертификатов в том виде, в каком её прислал сервер: для каждого
  сертификата — кому и кем он выдан, срок действия и сколько дней осталось,
  ключ; для собственного сертификата сервера — ещё его имена и отпечаток
  SHA-256

![Вкладка «Сеть»](../en/images/network.png)

![Шифрование и цепочка сертификатов](../en/images/network-tls.png)

Всё это берётся из собственного соединения запроса, а не из второго,
открытого для проверки: каждая отправка открывает новое соединение, и Apix
записывает, о чём договорилось это рукопожатие. Apix запрашивает сжатые ответы
(`gzip`, `deflate`, `br`), если запрос не задаёт свой `Accept-Encoding`, и
показывает заголовки `Content-Encoding` и `Content-Length` так, как их прислал
сервер.

### Маршрут и карта

**Проследить маршрут и показать на карте…** под адресом сервера (или **Вид ›
Маршрут и карта…**) перечисляет маршрутизаторы между этим компьютером и
сервером с временем до каждого и рисует их на карте мира. Узлы берутся из
системной утилиты (`tracert` в Windows, `traceroute` или `tracepath` в других
системах), поэтому права администратора не нужны; маршрутизатор, который не
отвечает, показывается как `*`. Адреса вашей собственной сети помечаются
соответственно.

Местоположение каждого маршрутизатора берётся из базы геолокации IP на этом
компьютере; в сети ничего не запрашивается. Без такой базы список всё равно
работает, а карта остаётся пустой: **Скачать DB-IP Lite** загружает бесплатную
базу DB-IP (около 130 МБ, CC BY 4.0) в `<config>/Apix/geo` (то же делают
окно «Настройка» и `apix geo download`), или положите туда любую городскую базу
`.mmdb` (DB-IP Lite, MaxMind GeoLite2 City). Такие базы в лучшем случае
определяют город адреса и иногда ошибаются для магистральных маршрутизаторов.
В терминале `apix trace <url or host>` выводит тот же список.

![Маршрут на карте](../en/images/route.png)

На снимке экрана используется небольшая демонстрационная база
(`cargo run -p apix-route --example demo_geo`), а не реальные данные.

## WebSocket и события сервера (SSE)

**WebSocket.** Запрос, URL которого начинается с `ws://` или `wss://`, — это
WebSocket: **Отправить** становится **Подключиться**, а вкладка «Тело» —
**Сообщения**. Рукопожатие использует параметры, заголовки и авторизацию
запроса (Bearer, Basic, API-ключ, OAuth 2.0 …), как любой запрос.

![Соединение WebSocket и его вкладка «Сообщения»](../en/images/websocket.png)

- Введите сообщение и нажмите **Отправить** (или Ctrl+Enter). `{{variables}}`
  подставляются при отправке. Если соединения нет, Apix сначала подключается и
  отправляет сообщение, как только соединение откроется.
- **Сохранить сообщение** сохраняет его в файле запроса как `[[message]]`;
  Ctrl+S сохраняет файл. Щёлкните по сохранённому сообщению, чтобы изменить
  его, или по ▷, чтобы отправить как есть.
- Панель ответа — это журнал: ↑ отправлено, ↓ получено, со временем от
  подключения, а также момент подключения и то, как соединение закрылось (код
  и причина). Журнал следует за новыми сообщениями, если вы не прокрутили его
  вверх.
- **Отключиться** (или Esc) закрывает соединение; журнал остаётся до
  следующего подключения. Соединение продолжает работать, пока его вкладка в
  фоне.
- **Двоичные сообщения:** выберите **Base64** или **Hex** рядом с кнопками и
  запишите байты в этом виде (`01 02 ff`, пробелы и `0x` допускаются);
  сообщение, которое не читается как байты, отправить нельзя. Сохранённые
  сообщения сохраняют свой формат. В журнале двоичные сообщения показываются
  размером и первыми байтами.
- **Подпротоколы** (вверху вкладки «Сообщения», через запятую) предлагаются при
  рукопожатии; журнал называет тот, который выбрал сервер. Если сервер не
  выбрал ни одного, соединение отклоняется, как в браузерах.
- **Пинг каждые (с)** под ними отправляет пинг с этим интервалом, пока есть
  соединение (`[websocket] ping_interval` в файле). Каждый ответ показывается в
  журнале как `pong after 2 ms`; если пинг остался без ответа к моменту
  следующего, соединение закрывается с ошибкой, так что тихо умершее соединение
  видно как мёртвое. На пинги самого сервера Apix всегда отвечает.
  `apix send --ping 30` делает то же (`--ping 0` отключает сохранённый
  интервал) и завершается с ненулевым кодом при мёртвом соединении.
- `wss://` следует настройкам запроса: доверенный УЦ, клиентский сертификат
  или отключённая «Проверять сертификат TLS».

**События сервера (SSE).** Когда ответ имеет тип `text/event-stream`, его
события появляются по мере поступления — со временем, типом события, id и
данными. **Остановить** (или Esc) завершает поток и сохраняет то, что пришло;
поток, завершённый сервером, показывает тот же список на вкладке
«Форматированный», а «Исходный», «Заголовки», «Сеть» и «Hex» — как для любого
ответа. Отправьте `Accept: text/event-stream`, если сервер этого требует.
Тайм-аут запроса в «Настройках» тоже завершает поток, поэтому для долгоживущих
потоков оставляйте его пустым.

- Если типов событий больше одного, они показываются над списком с числом
  событий каждого типа; щёлкните по типу, чтобы показать только его, **Все** —
  чтобы показать все события.
- **Переподключаться** (в режиме реального времени) возобновляет поток, когда
  он заканчивается или соединение обрывается: через время `retry:` сервера
  (3 с, если сервер его не указал), с `Last-Event-ID`, равным последнему
  полученному id, как делает браузер. Список отмечает каждое переподключение.
  Ответ, который не является потоком событий, останавливает переподключение,
  как и Esc.

В командной строке `apix send` выводит события по мере поступления
(`--event TYPE`, можно повторять, выводит только эти типы; `--reconnect`
переподключается, пока не нажато Ctrl+C). Для WebSocket он подключается,
отправляет сохранённые сообщения (или тексты `--message`, читаемые как
`--format text|base64|hex`), выводит обе стороны обмена и закрывает соединение
через `--listen` секунд (по умолчанию 3, `0` ждёт сервер). `apix run`
пропускает запросы WebSocket.

## Socket.IO

Запрос Socket.IO общается с серверами Socket.IO 3 и 4 через WebSocket.
Откройте вкладку **Сообщения** запроса (задайте URL `ws://`, чтобы вкладка
появилась) и выберите **Socket.IO** вверху; после этого URL может быть
`http://`, `https://`, `ws://` или `wss://`, как в клиенте Socket.IO. Файл
запроса получает таблицу `[socketio]`, а запрос Socket.IO открывается на
вкладке «Сообщения».

![Соединение Socket.IO: события, подтверждения и двоичное вложение](../en/images/socketio.png)

- **Пространство имён:** то, к которому нужно подключиться, например `/chat`.
  Если поле пустое, это путь из URL (`http://localhost:3000/chat` подключается
  к `/chat`) или `/`. **Путь** — это где слушает сервер, `/socket.io/`, если
  сервер его не перенёс. Адрес, скопированный из вкладки сети браузера
  (`…/socket.io/?EIO=4&transport=websocket`), работает как есть.
- **Авторизация:** JSON-объект, отправляемый при подключении (опция `auth`
  клиента), с подставленными `{{variables}}`. Если сервер отказывает,
  названная им причина показывается как ошибка.
- **Событие** задаёт имя, под которым отправляется сообщение (`message`, если
  пусто). Текст — один аргумент: JSON как есть, любой другой текст как строка,
  и ничего, если текст пуст. **Base64** и **Hex** отправляют байты как двоичное
  вложение. **Запросить подтверждение (ack)** просит сервер подтвердить
  получение. Сохранённые сообщения сохраняют своё событие и ack.
- Журнал показывает каждое событие с его именем: ↑ отправлено (с `ack 0`,
  `ack 1` …, если было запрошено подтверждение), ↓ получено (с `wants ack 9`,
  если сервер просит подтверждение), и ✓ для подтверждений сервера с тем, что
  он ответил. Двоичные вложения показываются размером и первыми байтами.
  Заголовки, параметры и авторизация рукопожатия, а также настройки TLS
  работают как для WebSocket.
- Apix отвечает на пинги сервера. Когда сервер отключает клиента от
  пространства имён, журнал сообщает об этом и соединение закрывается;
  **Отключиться** (или Esc) покидает пространство имён и закрывает соединение.

`apix send` подключается, отправляет сохранённые сообщения и выводит события,
подтверждения и двоичные вложения по мере поступления; `--message TEXT` (можно
повторять) вместо этого отправляет тексты как событие, заданное
`--event NAME` (по умолчанию `message`). `apix run` пропускает запросы
Socket.IO. Полученные вложения записываются как `{"$binary": "<base64>"}`.
Пока не поддерживаются: серверы Socket.IO 2 (Engine.IO 3), транспорт
long-polling и ответ на подтверждение, которое запрашивает сервер.

## MQTT

Запрос, URL которого начинается с `mqtt://` (или `mqtts://` для TLS),
подключается к брокеру MQTT 3.1.1: адресная строка и боковая панель показывают
**MQTT**, **Отправить** становится **Подключиться**, а вкладка «Тело» —
**Сообщения**. Порт — 1883 или 8883 с TLS, если URL не указывает другой.

![Соединение MQTT: подписки, опубликованные и полученные сообщения](../en/images/mqtt.png)

- **Вход:** имя пользователя и пароль из типа Basic на вкладке «Авторизация»
  или из URL (`mqtt://user:password@host`). Другие типы авторизации к MQTT не
  применяются. Если брокер отказывает, он сообщает причину. Пароль из URL не
  попадает в то, что выводит Apix.
- **ID клиента** новый для каждого подключения, если поле пустое.
  **Сохранять сессию** просит брокер хранить сессию между подключениями, для
  этого нужен ID клиента; журнал сообщает, если у брокера ещё была сессия.
  **Keep-alive** — секунды между пингами в простое (по умолчанию 60, 0 —
  без пингов).
- **Подписки** оформляются при подключении, каждая со своим уровнем качества
  обслуживания (QoS); в топиках работают `+` и `#`. Пока соединение открыто, ▷
  сразу подписывается на строку, а ✕ отменяет подписку. Журнал отмечает, что
  брокер принял или отклонил.
- Чтобы опубликовать сообщение, заполните **Топик**, выберите QoS, отметьте
  **Retain**, если брокер должен хранить сообщение для будущих подписчиков, и
  нажмите **Отправить** (или Ctrl+Enter). `{{variables}}` подставляются.
  **Base64** и **Hex** отправляют байты. Пустое сообщение допускается: с
  Retain оно очищает то, что хранил брокер. **Сохранить сообщение** сохраняет
  его в файле запроса.
- Журнал показывает каждое сообщение под его топиком: ↑ опубликовано,
  ↓ получено, с QoS и флагом retain, и ✓, когда брокер подтвердил сообщение с
  QoS 1 или 2. Нетекстовые данные показываются размером и первыми байтами.
- `mqtts://` следует настройкам запроса: доверенный УЦ, клиентский сертификат
  или отключённая «Проверять сертификат TLS». Тайм-аут запроса ограничивает
  подключение (без него — 10 с).

`apix send` подключается, подписывается, публикует сохранённые сообщения и
выводит обмен в обе стороны, закрывая соединение через `--listen` секунд (по
умолчанию 3, `0` ждёт брокера). `--subscribe TOPIC` (можно повторять) добавляет
подписки; `--message TEXT` с `--topic TOPIC` публикует вместо сохранённых
сообщений; к ним применяются `--qos` и `--retain`. Код выхода равен 1, если
брокер отклонил подписку или разорвал соединение, не ответив на подписку или
не подтвердив сообщение. `apix run` пропускает запросы MQTT. Пока не
поддерживаются: MQTT 5, last will и MQTT поверх WebSocket.

## SOAP

Вызов SOAP — это XML-конверт, отправленный методом POST, поэтому запрос SOAP —
обычный запрос: скрипты, тесты, запуски и история работают с ним, как с любым
другим.

**Из WSDL.** Импортируйте файл WSDL 1.1 через **Файл › Импорт…** или его адрес
через **Файл › Импорт по URL…** (`http://host/service?wsdl`). Вы получите
коллекцию с запросом на каждую операцию и папкой на каждый порт, если портов
несколько (обычно один для SOAP 1.1 и один для 1.2). Адрес порта становится
переменной `baseUrl` (по переменной на порт, если адреса различаются);
документы, которые импортирует WSDL, тоже читаются. То, что не удалось
прочитать, и порты, не являющиеся SOAP, перечисляются по окончании импорта.

![Запрос SOAP из WSDL и ошибка (fault), которой ответил сервер](../en/images/soap.png)

- **Заголовки** зависят от версии: SOAP 1.1 отправляет `Content-Type: text/xml`
  и `SOAPAction`; SOAP 1.2 отправляет `application/soap+xml` с действием
  внутри.
- **Тело** — конверт с примерами значений, построенными по схеме: `1` для
  чисел, `string` для текста, первое значение перечисления, первый вариант
  выбора (choice). Комментарии говорят, что необязательно или повторяется и
  какие есть другие значения. Необязательные атрибуты опускаются. Замените
  значения или подставьте в них `{{variables}}` и удалите то, что не нужно.
- Тип, содержащий сам себя, обрывается на втором уровне с комментарием.

**Без WSDL.** Выберите **XML** в качестве тела; пока оно пустое, кнопки
**SOAP 1.1** и **SOAP 1.2** рядом начинают конверт и задают заголовки. Укажите
операцию и действие (`SOAPAction` или `action=` в `Content-Type`).

**Ошибки (faults).** Если ответ содержит SOAP fault, красная строка над ответом
показывает его код и сообщение, а `apix send` выводит его. Запрос без тестов
считается неудачным при fault, даже если статус 200 (некоторые серверы
отправляют его так), — в `apix send`, `apix run` и в Runner. Тестовые скрипты
решают сами.

Пока не поддерживаются: WSDL 2.0 (он отклоняется с указанием этой причины),
WS-Security, вложения MTOM и `xsi:type` в примерах для SOAP encoding, о
котором предупреждает импорт.

## gRPC

Запрос, URL которого начинается с `grpc://` (или `grpcs://` для TLS), вызывает
метод gRPC: адресная строка показывает **gRPC**, а вкладка «Тело» становится
вкладкой **Сообщение**.

![Вызов gRPC](../en/images/grpc.png)

1. Введите адрес, например `grpc://localhost:50051`.
2. **Загрузить методы** спрашивает сервер, что он предлагает (gRPC server
   reflection). Если у сервера нет reflection, **Добавить файл** выбирает файлы
   `.proto` сервиса или наборы дескрипторов (`protoc --descriptor_set_out`,
   `buf build`, двоичные или JSON); импорты ищутся рядом с ними, а
   стандартные типы Google (well-known types) встроены. `protoc` не нужен
   ни для чего. Если такого файла нет, см.
   [Без файла .proto](#без-файла-proto).
3. Выберите метод. Рядом показан его вид: унарный, поток сервера, поток
   клиента или двунаправленный.
4. Напишите сообщение в JSON или нажмите **Пример сообщения**, чтобы получить
   сообщение со всеми полями. Для метода, принимающего поток, JSON-список
   отправляет по сообщению на каждый элемент.
5. **Отправить** (Ctrl+Enter). Панель ответа перечисляет, что ушло (↑) и что
   вернулось (↓), со временем, затем статус (`0 OK` или код вроде
   `5 NOT_FOUND` с сообщением), метаданные ответа и трейлеры. Поток
   показывает сообщения по мере поступления; Esc его останавливает.

Заголовки отправляются как метаданные, а авторизация работает как для HTTP с
Bearer, Basic, API-ключом в заголовке и OAuth 2.0. Действуют тайм-аут,
клиентский сертификат, доверенный УЦ и «Проверять сертификат TLS» из настроек
запроса (если проверка отключена, сертификат сервера `grpcs://` не
проверяется). Заголовок `-bin` читается как base64.

В командной строке `apix send` вызывает метод (потоки выводятся по одному
сообщению в строке по мере поступления; код выхода ненулевой, если статус не
OK), а `apix schema` выводит сервис и его сообщения.

**В запусках и тестах.** `apix run` и Runner тоже вызывают запросы gRPC, и их
тестовые скрипты и проверки видят вызов как HTTP-ответ: статус — это
HTTP-статус, соответствующий коду gRPC (`OK` — 200, `INVALID_ARGUMENT` — 400,
`NOT_FOUND` — 404, `UNAUTHENTICATED` — 401, …), код и сообщение gRPC находятся в
заголовках `grpc-status` и `grpc-message` рядом с метаданными и трейлерами, а
тело — это ответ или JSON-список сообщений для метода, отвечающего потоком.
Поэтому `pm.response.json().message` или проверка `body.message` работают, как
для любого запроса. Одиночная **Отправить** показывает вызов без выполнения
скриптов.

Каждый вызов сохраняется в **Истории** (Ctrl+H) с журналом, статусом и
метаданными; если выбрать его, вызов снова показывается таким, каким
завершился.

### Без файла .proto

В сети gRPC передаёт номера полей, а не имена, и вызывает
`package.Service/Method`. Поэтому, с чего бы вы ни начали, они должны получиться
правильными. Вкладка **Определение** рядом с **Сообщением** создаёт определение
из того, что у вас есть. Вставьте исходник (или **Прочитать файл**, или **Взять
сообщение**), укажите **Вызываемый метод**, если исходник его не называет, и
нажмите **Преобразовать**. Результат — текст `.proto`, который можно
редактировать; он хранится в запросе, а **Сохранить в файл** записывает его в
файл.

![Определение, построенное по примеру JSON, и предупреждение о несовпадении](../en/images/grpc-definition.png)

| Что у вас есть | Что получится |
|---|---|
| Текст `.proto`, набор дескрипторов (двоичный или JSON) | Точно. |
| Сгенерированный код, содержащий описание: `_pb2.py`, внешний класс Java, Kotlin через него, `.cs`, `.pb.cc`, `.pb.go`, `_pb.rb`, `GPBMetadata` для PHP, protobuf-es `_pb.ts` | Точно: читается описание внутри, на каком бы языке ни был код. |
| Код с номерами, но без описания: теги Go `protobuf:"…"`, Rust `#[prost(…)]`, ts-proto, betterproto, `[ProtoMember(n)]`, `@ProtoNumber(n)` | Номера и типы верны; проверьте вызовы, если исходник их не перечисляет. |
| Типы, написанные вручную: TypeScript, Go, Rust, C#, Java, Kotlin, Python, Swift, Dart, C++ | **Предположение.** Поля нумеруются в порядке появления. |
| Пример сообщения в JSON (необязательное второе поле принимает ответ) | **Предположение.** Типы берутся из значений; JSON-список означает поток. |

Предположение хорошо ровно настолько, насколько верны его номера, и **неверные
номера не вызывают ошибку: они заполняют не те поля.** Поэтому Apix никогда
этого не скрывает:

- Если сервер поддерживает reflection, вместо предположения используется его
  описание, а каждое различие перечисляется (`number 1 here, 7 on the server`).
- Если нет, каждый вызов сообщает, что номера не проверены. Поля ответа,
  которых нет в определении, показываются с номерами и значениями
  (`1:"o-1"`) — так же можно разобрать ответ, для которого у вас нет типа.
  Ответ, который совсем не подходит, завершается ошибкой со строкой о том, что
  вероятная причина — определение.

Другие файлы, которые генерирует `protoc`, только используют описание (`.pb.h`,
билдеры Kotlin, `.pyi`), а заглушки gRPC содержат только вызовы; Apix
подсказывает, какой файл взять вместо них. Не читаются: Protobuf editions в
виде текста `.proto` (они остаются набором дескрипторов), oneof из тегов или
типов (их поля становятся обычными полями, которые в сети передаются так же) и
дженерики.

В командной строке:

```bash
apix proto service_pb2.py
```

```bash
apix proto order.json --method shop.v1.Orders/Create --response answer.json --out orders.proto
```

```bash
apix proto types.ts --method shop.v1.Orders/Create --into create.apix
```

`.proto` выводится в стандартный вывод или в `--out`, `--into` сохраняет его в
запросе, а то, что пришлось выбрать, выводится в стандартный поток ошибок.
`apix send`, `apix run` и `apix schema` используют определение так же, а
`apix send` выводит те же предупреждения; в отчёт запуска они не попадают.

## Скрипты и тесты

Вкладка **Скрипты** содержит два скрипта JavaScript для запроса:

- **До запроса** выполняется перед отправкой запроса. Он может изменить запрос
  (`pm.request.headers.upsert(…)`, `pm.request.url.query.add(…)`,
  `pm.request.body.raw = …`) и задать переменные
  (`pm.environment.set("token", …)`).
- **Тесты** выполняется после получения ответа и проверяет его:

```js
pm.test("status is 200", () => pm.response.to.have.status(200));
pm.test("has users", () => {
  const body = pm.response.json();
  pm.expect(body.users).to.be.an("array").that.is.not.empty;
});
```

API — это `pm.*` из Postman (доступен также как `apix.*`), поэтому скрипты,
импортированные из Postman, работают как есть: `pm.environment`,
`pm.collectionVariables`, `pm.globals` (переменные проекта), `pm.variables`,
`pm.request`, `pm.response`, `pm.test`, `pm.expect` с утверждениями в стиле
Chai, `pm.info`, `console.log`, а также старые `tests["…"] = …` и
`postman.setEnvironmentVariable(…)`.

`pm.sendRequest` отправляет из скрипта другой запрос, например чтобы сначала
получить токен; работают оба варианта: `pm.sendRequest(req, (err, res) => …)`
и `const res = await pm.sendRequest(req)`. `require(…)` предоставляет те части
`crypto-js` (MD5, SHA-1, SHA-2 и их HMAC, кодировщики Base64/Hex/UTF-8),
`uuid`, `lodash` (также `_`), `moment`, `ajv`, `tv4` и `chai`, которые
используют скрипты для API; они встроены, поэтому ничего не скачивается.
Функция, которой нет в библиотеке, завершается понятной ошибкой.

Третья часть вкладки «Скрипты», **Проверки**, проверяет ответ без кода: каждая
строка сравнивает цель со значением. Цели — `status`, `time` (мс), `size`
(байты), `body`, путь в JSON-теле, например `body.users[0].id`, или
`header.Content-Type`; сравнения — `==`, `!=`, `>`, `>=`, `<`, `<=`,
`contains`, `not contains`, `exists`, `not exists`, `matches` (регулярное
выражение, например `/^ok/i`) и `is` (тип JSON). В значениях можно использовать
`{{variables}}`. Проверки сохраняются в файле запроса как `[[assert]]` и
отображаются как тесты — в приложении и в `apix run`.

Чтобы сохранить значение из ответа, используйте кнопку **{x}** рядом со
статусом: укажите значение (те же цели, что в проверках) и имя переменной, и
оно сохранится в активном окружении (или, если окружения нет, в переменных
коллекции). Отметьте **Обновлять при каждой отправке**, чтобы также добавить
соответствующую строку `pm.environment.set(…)` в скрипт «Тесты».

Скрипты — это файлы рядом с тем, к чему они относятся:
`<request>.prerequest.js` и `<request>.test.js` рядом с запросом,
`_folder.prerequest.js` / `_folder.test.js` в папке,
`_collection.prerequest.js` / `_collection.test.js` в корне коллекции. Они
выполняются снаружи внутрь: коллекция, папки, затем запрос. Ctrl+S сохраняет
скрипты запроса вместе с ним; текст редактора используется ещё до сохранения.

После отправки панель ответа получает вкладку **Тесты** (✓ пройден, ✗ провален
с причиной) и вкладку **Консоль** с выводом `console.*`. Если скрипт до запроса
выбрасывает исключение, запрос не отправляется, а ошибка указывает, какой файл
не сработал. Скрипты останавливаются через 10 секунд.

Значения, которые задаёт скрипт, не записываются ни в один файл. Они живут,
пока Apix открыт (смена окружения сбрасывает то, что задал
`pm.environment.set`), и показываются в карточках переменных как «Задано
скриптом». `pm.variables.set` действует в пределах одной отправки.

## Runner

**Runner** отправляет много запросов за один раз и проверяет их все. Откройте
его через **Вид › Runner…** или Ctrl+Shift+R для текущей коллекции либо через
**Запустить…** у коллекции или папки на боковой панели — только для этой части.

![Runner после запуска с файлом данных](../en/images/runner.png)

- **Запросы**: все запросы в порядке боковой панели, отмеченные. Снимите
  отметку с тех, которые нужно пропустить, и перемещайте запросы кнопками ↑ ↓,
  чтобы изменить порядок для этого запуска.
- **Окружение**: переменные какого окружения использовать.
- **Итерации**: сколько раз пройти по запросам. Если поле пустое — один раз,
  или по разу на строку, если есть файл данных.
- **Пауза (мс)**: пауза между двумя запросами, для API с ограничением частоты.
- **Одновременно**: сколько итераций выполняется параллельно, как несколько
  пользователей API одновременно. Каждая отправляет свои запросы по порядку
  (так что токен после входа всё равно доходит до следующего запроса) и хранит
  то, что задали её собственные скрипты; результаты перечисляются по итерациям.
  Если поле пустое — одна за другой.
- **Файл данных**: файл CSV или JSON для запуска на данных. Каждая строка —
  одна итерация, а её столбцы — переменные: `{{email}}` в запросе и
  `pm.iterationData.get("email")` в скриптах. CSV нужна строка заголовков;
  кавычки и файлы с разделителем «точка с запятой» (Excel во многих языках)
  понимаются. JSON — массив объектов, например
  `[{"id": 1, "email": "a@x.test"}, …]`.
- **Остановиться на первой ошибке**: завершить запуск на первом неудачном
  запросе.

Запрос проходит, если проходят его тесты (скрипты и проверки); запрос без
тестов проходит при статусе 2xx или 3xx. Во время запуска можно нажать
**Пауза**, **Продолжить** и **Остановить** (после отправляемого запроса).
Закрытие диалога не останавливает запуск: откройте Runner снова, чтобы увидеть
его. Щёлкните по результату, чтобы увидеть его тесты, причину, по которой он
не был отправлен, и строки консоли. `pm.execution
.setNextRequest("name")` переходит к другому запросу запуска, а
`setNextRequest(null)` завершает итерацию, как в Postman.

Runner отправляет сохранённую версию каждого запроса. Значения, заданные
скриптами до запуска, используются; то, что задают скрипты запуска, остаётся
внутри запуска.

Когда запуск закончен, **Сохранить отчёт** записывает его как **JUnit XML**
(для представлений тестов в CI), **JSON** (всё, что произошло) или **HTML**
(страница, которая открывается в любом браузере, в светлом или тёмном
оформлении). `apix run` делает то же из терминала; см.
[Запуск коллекции в CI](workflows.md#запуск-коллекции-в-ci). Пароль, записанный
в URL (`https://user:password@host`), не попадает в отчёты, вывод командной
строки, журналы и сообщения об ошибках. Файл запроса и адресная строка всё
равно его содержат, поэтому для настоящих паролей лучше использовать
переменную или вкладку «Авторизация».

## Сценарии

**Сценарий** объединяет запросы в граф: войти, сохранить токен, опрашивать,
пока задача не завершится, ветвиться по тому, что пришло. Каждый сценарий — это
файл `.flow` в коллекции рядом с запросами, поэтому он попадает в git вместе с
ними. Откройте **Вид › Сценарии…**; чтобы создать новый, введите название и
нажмите **Создать**.

![Окно «Сценарии»](../en/images/flows.png)

Есть четыре вида узлов:

- **Запрос** отправляет запрос коллекции с его скриптами и тестами. Его
  результат — **ok**, если запрос прошёл (успешный статус или все тесты
  пройдены), и **fail** в остальных случаях. **Сохранить из ответа** превращает
  значения ответа в переменные для следующих узлов, по одной в строке:
  `token = $.token`.
- **Проверка** сравнивает субъект со значением: **yes** или **no**. Субъект —
  `status`, `time` (мс), `body`, `header:Name`, JSONPath (`$.items[0].id`) или
  фильтр jq (`.items | length`) по последнему ответу либо текст с
  `{{variables}}`. Сравнения: равно, не равно, содержит, больше, меньше (как
  числа, если обе стороны — числа), есть, нет.
- **Задать переменные** задаёт переменные (строки `name = value`;
  `{{variables}}` работают).
- **Ожидание** делает паузу, для циклов опроса.

Перетащите узел, чтобы переместить его. Чтобы соединить узлы, щёлкните точку
результата справа на узле, затем узел, к которому он ведёт; повторный щелчок по
точке перенаправляет связь, а **×** на панели удаляет её. Панель справа
редактирует выбранный узел: его id, настройки, куда ведёт каждый результат,
**Начинать здесь**, **Удалить узел**. Запуск начинается с узла **Начало** (если
его нет — с первого узла, к которому ничто не ведёт), следует за каждым
результатом и заканчивается на результате, который никуда не ведёт. Он
считается неудачным, если запрос не прошёл и у него нет ребра **fail** или если
значения, которое нужно сохранить, нет. Циклы разрешены; запуск
останавливается после 1000 шагов.

**Запустить** выполняет сценарий с переменными коллекции и выбранным
окружением; каждый узел становится зелёным, жёлтым или красным в зависимости от
результата, а список под холстом показывает каждый шаг с тем, что было
сохранено или сравнено. Изменения сохраняются кнопкой **Сохранить** и при
закрытии окна.

Из терминала тот же сценарий выполняется в CI:

```sh
apix flow list my-api
apix flow run my-api/new-user.flow --env staging --junit flow.xml
```

`--junit`, `--html` и `--markdown` формируют отчёт по запросам сценария, как
`apix run`; `--json` записывает каждый шаг. В примере коллекции есть
`new-user.flow`.

Файл сценария:

```toml
name = "New user"

[[node]]
id = "first-user"
kind = "request"
request = "users/list-users.apix"
x = 40.0
y = 40.0
extract = { user_id = "$[0].id" }

[[node]]
id = "found"
kind = "check"
subject = "{{user_id}}"
op = "exists"
x = 300.0
y = 40.0

[[edge]]
from = "first-user"
port = "ok"
to = "found"
```

## Нагрузочное тестирование

**Запрос › Нагрузочный тест…** (или палитра команд) отправляет открытый запрос
из многих потоков одновременно и показывает, как держится сервер: число
запросов и запросов в секунду, ошибки, 50-й, 95-й и 99-й процентили и самое
долгое время, а также посекундный график запросов (неудачные — красным) со
средней задержкой в виде жёлтой отметки.

![Нагрузочный тест](../en/images/load-test.png)

- **Одновременно**: число запросов, выполняющихся в один момент (от 1 до
  10 000).
- **Запросов**: остановиться после стольких запросов; пусто — без ограничения.
- **В течение**: остановиться через это время (`30s`, `2m`, `1500ms`); если не
  задано ни то, ни другое, — 10 с.
- **В секунду**: не больше стольких запросов в секунду, равномерно; пусто —
  так быстро, как отвечает сервер.

Соединения держатся открытыми и используются повторно, как это делают реальные
клиенты под нагрузкой (одиночная отправка открывает новое соединение, чтобы
вкладка «Сеть» показала рукопожатие). Переменные подставляются один раз;
скрипты не выполняются, OAuth 2.0 получает токен один раз, а Digest auth не
поддерживается. Запрос считается неудачным, если ответа не было или статус 400
и выше. **Остановить** завершает тест; закрытие окна тоже его останавливает.
Тестируйте нагрузкой только те серверы, на которые у вас есть разрешение.

В терминале `apix bench` делает то же и может провалить задачу CI:

```bash
apix bench my-api/users/list.apix -c 50 -d 30s --max-p95 300 --max-failed 1 --json bench.json
```

Он завершается с кодом 1, если 95-й процентиль больше `--max-p95` миллисекунд,
больше `--max-failed` процентов запросов завершились неудачно или ни один не
прошёл успешно.

## Мониторы

**Монитор** запускает коллекцию или её папку либо запрос по расписанию и
сообщает, когда она начинает падать или снова проходит. Откройте **Вид ›
Мониторы…**.

![Мониторы](../en/images/monitors.png)

- **Добавить монитор** запрашивает название, интервал (`30s`, `5m`, `1h`, `1d`
  или вместе, как `1h30m`; не меньше `10s`), папку или запрос (пусто — вся
  коллекция), окружение и вебхук. Кнопка ⚙ изменяет монитор, кнопка ▷
  запускает его сейчас.
- Каждый монитор показывает свой последний результат (пройдено или сколько не
  прошло и первые ошибки) и, пока расписание включено, время следующего
  запуска.
- **Запускать мониторы по расписанию, пока Apix открыт** включает расписание
  (оно выключено, пока вы его не выберете). Тогда Apix запускает мониторы,
  которым подошёл срок, в фоне по одному и показывает уведомление, когда
  какой-то из них начинает падать или снова проходит.
- **Вебхук** получает то же самое: Apix отправляет JSON со строкой `text` (и
  `content`), которую Slack, Discord, Mattermost и Google Chat показывают как
  сообщение, а также подробности (`monitor`, `status`, `passed`, `failed`,
  `failures`). `{{variables}}` подставляются, поэтому адрес может храниться в
  секретах окружения.

Мониторы хранятся в `apix.toml` коллекции, поэтому они расходятся через git:

```toml
[[monitor]]
name = "Health"
every = "5m"
run = "users"            # папка или запрос; не указывайте для всей коллекции
environment = "staging"
webhook = "{{alerts_url}}"
# enabled = false        # в списке, но по расписанию не запускается
```

Чтобы следить за API, когда приложение закрыто, запускайте `apix monitor` в
терминале, из cron или Планировщика заданий либо по расписанию CI; см.
[Наблюдение за API с помощью мониторов](workflows.md#наблюдение-за-api-с-помощью-мониторов).
Приложение и `apix monitor` ведут общий журнал результатов, поэтому каждый из
них показывает то, что нашёл другой.

## Mock-сервер

**Mock-сервер** отвечает примерами, сохранёнными в запросах коллекции (см.
«Примеры»), так что фронтенд можно строить, а тесты запускать ещё до появления
настоящего API. Откройте **Вид › Mock-сервер…**, выберите порт и нажмите
**Запустить**.

![Mock-сервер](../en/images/mock.png)

- Запрос сопоставляется по методу и пути: URL запроса после хоста или после
  начальной `{{variable}}`, так что `{{base_url}}/users/:id` обслуживает
  `/users/7`. Сегменты `:name` и `{{name}}` соответствуют любому одному
  сегменту, а побеждает самый буквальный путь. Пример, сохранённый запрос
  которого имеет другой URL, обслуживает этот URL.
- Если примеров несколько, отвечает первый со статусом 2xx. Запрос может
  выбрать другой заголовком `x-mock-response-name: <example>` или
  `x-mock-response-code: 404` (их же читают mock-серверы Postman).
- Каждый ответ разрешает любой источник (CORS) и сообщает в `X-Apix-Mock`,
  из какого примера он взят; на предварительный запрос `OPTIONS` тоже
  отвечает.
- Если совпадения нет, возвращается `404` с JSON-списком того, что
  обслуживается.
- Окно показывает, что обслуживается, и последние запросы. Добавленные или
  изменённые примеры начинают обслуживаться сразу; сервер продолжает работать
  после закрытия окна, пока вы не нажмёте **Остановить** или не выйдете из
  приложения.

Чтобы использовать его, добавьте окружение (например `mock`), у которого
`base_url` равен `http://127.0.0.1:4010`. Из терминала:
`apix mock my-api --port 4010` (`--host 0.0.0.0`, чтобы сервер был доступен с
других компьютеров, `--delay 300` — для медленного сервера).

## Документация API

**Файл › Экспорт документации…** (или **Экспорт документации…** у коллекции на
боковой панели) записывает коллекцию как документацию API: одну HTML-страницу,
которая открывается в любом браузере, в светлом или тёмном оформлении, с
оглавлением; или Markdown для репозитория, если имя файла оканчивается на
`.md`.

![Сгенерированная документация](../en/images/api-docs.jpg)

Она показывает описание коллекции (Markdown), её переменные и переменные,
закоммиченные в каждом окружении, затем каждый запрос в порядке боковой панели
под его папками: метод, URL, описание, переменные пути, параметры запроса,
заголовки, тип авторизации, тело, проверки и сохранённые примеры. Ничего
секретного не выводится: файлы `.local.toml` и хранилище ключей не читаются,
для авторизации показывается только её вид, а заголовки `Authorization`,
`Cookie` и заголовки с API-ключами показывают значение, только если это
`{{variable}}`. Необработанный HTML в описаниях опускается.

Из терминала: `apix docs my-api --out api.html` (или `--out API.md`; без
`--out` — Markdown в стандартный вывод).

## Прокси для записи

**Прокси для записи** превращает реальный трафик в запросы. Откройте **Вид ›
Прокси для записи…**, выберите порт (8888) и нажмите **Запустить**, затем
укажите `http://127.0.0.1:8888` как прокси браузера, приложения или скрипта
(`HTTP_PROXY` и `HTTPS_PROXY`). Каждый проходящий запрос сохраняется в папку
`captured/` коллекции как файл запроса с ответом в виде примера `Captured` и
показывается в окне.

![Прокси для записи](../en/images/capture.png)

- **Только** ограничивает запись некоторыми хостами (`example.com` включает и
  `api.example.com`); остальное проходит без записи.
- Ничего секретного не записывается: `Cookie` отбрасывается, а значения
  заголовков `Authorization` и заголовков с API-ключами становятся
  переменными (`{{authorization}}`).
- HTTPS идёт через туннель, который прокси не может прочитать, поэтому по
  умолчанию он пропускается дальше, а в списке показывается только его хост.
  Если отмечено **Открывать HTTPS**, Apix отвечает на рукопожатие TLS
  сертификатом для хоста, подписанным локальным центром сертификации
  (`<config>/Apix/capture-ca.pem`), и тоже записывает запросы. Это работает
  только там, где этому центру доверяют: окно показывает команду, которая
  добавляет доверие (в Windows `certutil -user -addstore Root …`); Apix никогда
  не устанавливает его сам, а у Firefox свой список.

Из терминала: `apix capture my-api/captured --port 8888 --only example.com`
(`--https`, чтобы открывать HTTPS, `--no-save`, чтобы только наблюдать).

## Вкладки

Каждая вкладка хранит свои несохранённые изменения, последний ответ и даже
запрос, который ещё выполняется. Ctrl+Tab и Ctrl+Shift+Tab переключают вкладки,
Ctrl+W или щелчок средней кнопкой закрывает вкладку; перед закрытием
несохранённых изменений Apix спрашивает. Открытые вкладки возвращаются, когда
вы в следующий раз открываете ту же коллекцию или проект (вкладки
зашифрованных коллекций не запоминаются, так как имена их файлов тоже
секретны).

## Упорядочивание запросов

**Поиск запросов** вверху боковой панели оставляет только запросы, в имени,
методе или URL которых есть все введённые слова (`get users` находит запрос GET
к `/users`), и раскрывает ведущие к ним папки. Папка, имя которой совпадает,
показывает всё своё содержимое. Esc или ✕ очищает поиск, и папки возвращаются
в прежнее состояние.

Щёлкните правой кнопкой на боковой панели, чтобы создавать, переименовывать,
дублировать или удалять запросы и папки; удалённые файлы попадают в системную
корзину. Перетащите запрос или папку на середину другой папки, чтобы
переместить туда. Если вместо этого отпустить его на верхнем или нижнем краю
строки, он встанет перед этой строкой или после неё; линия показывает, куда
он попадёт. Порядок сохраняется в `apix.toml` (для верхнего уровня коллекции) и
`folder.toml` (для папки) как список `order`, поэтому он расходится через git;
элементы, которых нет в списке, идут следом по имени. Импорт из Postman
сохраняет порядок Postman, а экспорт в Postman следует вашему.

## Проекты

**Проект** объединяет несколько связанных коллекций и делает общими для них
окружения и авторизацию. Создайте его через **Файл › Новый проект…**. В проекте
**Окружение › Группировать боковую панель по** может показывать боковую панель
как Проект › Окружение › Коллекции.

- Перетащите заголовок коллекции выше или ниже другой, чтобы изменить их
  порядок.
- Правый щелчок по коллекции › **Цвет** задаёт ей цвет; точка показывает его
  на боковой панели и на вкладках её запросов. Цвета сохраняются в
  `apix-project.toml`.
- **Файл › Переместить в проект…** (когда открыта одна коллекция) перемещает
  папку этой коллекции в выбранный вами проект. Если открыт проект,
  перетаскивание папки коллекции из файлового менеджера в окно предлагает то
  же самое.

## Git

Коллекция — это обычные файлы, поэтому она живёт в git, как код. Когда открытая
коллекция (или проект) находится в git-репозитории, строка состояния
показывает ветку и сколько её файлов изменилось с последнего коммита, а
боковая панель отмечает каждый изменённый запрос: **M** — изменён (его файл
или его собственные скрипты), **A** — новый. Отметки следуют за каждым
сохранением и каждым изменением на диске и перечитываются, когда окно снова
выходит на передний план, поэтому коммит, сделанный в терминале, их убирает.

![Ветка и изменённые запросы](../en/images/git-status.png)

Щёлкните по ветке в строке состояния (или **Вид › Git…**), чтобы открыть окно
Git. Слева — файлы, изменённые с последнего коммита, и последние коммиты;
выберите файл, чтобы увидеть, что в нём изменилось, так же, как это показывает
`apix diff`: запрос — поле за полем (`query._limit: 5 → 10`, добавленный
заголовок), скрипты и другой текст — построчно, и ничего, если изменилось
только форматирование. Ниже напишите сообщение и нажмите **Коммит**: он берёт
все изменения в открытой папке и ничего за её пределами. Меню веток
переключает ветки, **Новая ветка** создаёт ветку с именем, введённым рядом, и
переключается на неё, а **Pull** (только fast-forward) и **Push** (в первый раз
задаёт upstream) запускают git с вашими собственными настройками, хуками и
учётными данными. Боковая панель сразу следует за переключением ветки.

![Окно Git](../en/images/git-window.png)

В командной строке `apix run --changed` отправляет только запросы, которых
коснулось изменение, а `apix diff` показывает, что в них изменилось, поле за
полем; в pull request GitHub Action может оставить комментарий с результатом.
См. [Только изменённое](workflows.md#только-изменённое-запуски-с-учётом-git).

## Зашифрованные коллекции

Зашифрованная коллекция хранит каждый запрос, окружение и даже имя файла на
диске в запечатанном виде (XChaCha20-Poly1305 с ключом из пароля через
Argon2id). Git видит только, какой зашифрованный блок изменился.

- **Файл › Зашифровать эту коллекцию…** или правый щелчок по коллекции ›
  **Зашифровать…** шифрует существующую коллекцию на месте.
- **Файл › Новая зашифрованная коллекция…** создаёт такую коллекцию внутри
  проекта.
- Вы один раз получаете **ключ восстановления**. Храните его в надёжном
  месте: он открывает коллекцию, если пароль утерян.
- При открытии коллекции запрашивается пароль. Она снова блокируется, когда вы
  выбираете **Файл › Заблокировать зашифрованные коллекции**, выходите из Apix
  или оставляете её без действия на время, заданное в настройках (по умолчанию
  15 минут).
- Отметьте **Запомнить на этом компьютере** в окне разблокировки, чтобы
  сохранить пароль в системном хранилище учётных данных (Диспетчер учётных
  данных в Windows, Связка ключей в macOS, Secret Service в Linux). Тогда
  коллекция открывается без запроса, пока вы вошли в систему, и командная
  строка `apix` тоже использует сохранённый пароль. **Файл › Забыть
  сохранённый пароль** (или правый щелчок по коллекции) удаляет его. Если
  пароль изменили в другом месте, сохранённый отбрасывается, и Apix снова
  спрашивает пароль.

## «Копировать как» и вставка curl

Кнопка копирования рядом с **Отправить** (или **Запрос › Копировать как**)
копирует запрос как `curl` для bash или fish, `curl.exe` для командной строки
Windows, вызов PowerShell `Invoke-RestMethod`, команду HTTPie `http` (HTTPie
3.0 или новее) или команду GNU `wget`, с подставленными переменными. wget не
умеет отправлять формы multipart; скопированная команда сообщает об этом.
Запросы, подписываемые при каждой отправке (OAuth 1.0, AWS для PowerShell и
кода), подписываются в момент копирования.

То же меню копирует запрос как программу: JavaScript `fetch`, Node.js axios,
Python requests, Go `net/http`, Rust reqwest, C# `HttpClient`, Java
`HttpClient`, PHP cURL, Swift `URLSession` или Kotlin OkHttp. Каждая отправляет
то, что отправил бы Apix, — URL, заголовки, авторизацию и тело любого типа, — а
также те настройки запроса, которые язык может выразить (тайм-аут,
перенаправления, проверку TLS, прокси, клиентский сертификат). Настройка, для
которой в языке нет простого переключателя, указывается в комментарии
`Not in this snippet` в начале, а не пропадает молча. На боковой панели
щёлкните правой кнопкой по запросу и выберите **Копировать как код**.

CLI выводит то же: `apix code request.apix --as python` (`apix shell` — та же
команда; `--as` принимает `bash`, `cmd`, `powershell`, `fetch`, `axios`,
`python`, `go`, `rust`, `csharp`, `java`, `php`, `swift` или `kotlin`).

Вставьте команду `curl` (например, из «Copy as cURL» вашего браузера) в поле
URL, и Apix заполнит весь запрос: метод, URL, параметры, заголовки,
авторизацию и тело.

## Импорт из Postman

**Файл › Импорт…** или перетащите экспорт Postman в окно. Поддерживаются
коллекции (v2.0 и v2.1) и окружения. Папки, запросы, тела, авторизация и
переменные переносятся; то, что Apix пока не может перенести, перечисляется в
отчёте. Скрипты до запроса и тестовые скрипты сохраняются как файлы `.js`
рядом со своими запросами, а секреты окружений попадают в `.local.toml`,
игнорируемый git.

**Много файлов за раз.** Откройте или перетащите папку с экспортами Postman —
или zip, который создаёт *Export data* в Postman, — и Apix распознает файлы по
содержимому, а не по именам, и предложит импортировать всё как один проект:
по коллекции на каждую коллекцию Postman, окружения, общие для всех, и globals
как переменные проекта (секретные globals опускаются, так как переменные
проекта коммитятся). Два окружения с одинаковым именем сохраняются как `name` и
`name-2`.

**Экспорт в Postman.** Щёлкните правой кнопкой по коллекции и выберите
**Экспорт в Postman…** (или **Файл › Экспорт в Postman…**), чтобы записать файл
коллекции Postman v2.1 и по файлу окружения на каждое окружение, — так коллеги,
работающие в Postman, смогут продолжить с ней работу. Папки, авторизация, тела,
скрипты, переменные и настройки перенаправлений, TLS и cookie переносятся. В
Postman нет тайм-аута, прокси и клиентского сертификата для отдельного
запроса, а секретные значения окружений экспортируются только с именами;
уведомление перечисляет, что было опущено.

В командной строке: `apix import <file, folder or zip>` и
`apix export <collection> --out <folder>`.

## Импорт из Insomnia, OpenAPI и HAR

**Файл › Импорт…** (или перетаскивание файла в окно) читает и эти форматы;
формат распознаётся по содержимому, а в папке или zip они могут быть
вперемешку:

| Формат | Что вы получаете |
|---|---|
| Insomnia v4 (экспорт JSON) | По коллекции на каждое рабочее пространство, папки с их авторизацией, базовое окружение как переменные коллекции и каждое подокружение как окружение. `{{ _.name }}` становится `{{name}}`. |
| OpenAPI 3 / Swagger 2 (JSON или YAML) | По запросу на каждую операцию, по папке на каждый тег. Сервер становится переменной `baseUrl` (несколько серверов — по окружению на каждый), параметры пути становятся переменными со значениями из примеров, обязательные параметры запроса и заголовков включены, тела берутся из примеров или строятся по схеме, а схемы безопасности становятся авторизацией с пустыми переменными учётных данных (`bearerToken`, `apiKey`, …), которые нужно заполнить в окружении. |
| WSDL 1.1 | По запросу на каждую операцию с примером конверта; см. [SOAP](#soap). |
| HAR («Save all as HAR» в DevTools браузера) | Только вызовы API, по папке на каждый хост. Скрипты, стили, изображения и шрифты, URL `data:` и повторы опускаются, как и заголовки `Cookie`: они несут сеанс браузера. |

Одна коллекция из одного файла импортируется как коллекция; несколько
становятся проектом. Отчёт перечисляет всё, что не удалось перенести.

## История

Каждый отправленный запрос сохраняется вместе с ответом. **Вид › История…**
(Ctrl+H) показывает их, начиная с новейших, с методом, именем, URL, статусом и
временем отправки; вводите текст, чтобы искать по любому из этих полей.
Выберите запись, и запрос вернётся во вкладку, из которой был отправлен, в
виде несохранённых изменений вместе с полученным ответом. Нажмите Ctrl+Enter,
чтобы отправить его снова, Ctrl+S — чтобы сохранить эту версию. Если файла
запроса больше нет, запись открывается в редакторе без вкладки.

История хранится на этом компьютере (папка `history` рядом с настройками) и
никогда — внутри коллекции. Запросы сохраняются как написаны, с
неподставленными `{{variables}}`, поэтому секреты окружений туда не
копируются. Хранятся последние 300 запросов, тела ответов — до 256 КБ каждое.
Запросы из зашифрованных коллекций никогда не записываются в историю.
**Очистить историю** в окне очищает её; **Файл › Настройки… › История**
отключает её.

## Сравнение ответов

**⇄** рядом с ответом (или **Запрос › Сравнить ответы…**) ставит текущий ответ
рядом с другим ответом того же запроса:

- **Прежние ответы**: ответы запроса из истории, начиная с новейших. Выберите
  один, чтобы увидеть, что изменилось с тех пор; так можно вернуться во времени
  ко вчерашнему ответу.
- **Другие окружения**: запрос, отправленный заново в другом окружении
  (staging против продакшена, mock против настоящего API).

Показывается, сколько найдено различий, затем статус, заголовки по именам и
тело: JSON — поле за полем (записи в списках сопоставляются по `id`, `_id`,
`uuid` или `key`, поэтому список в другом порядке не считается изменением, а
`[id=1].email` называет поле), другой текст — построчно. Заголовки, которые
меняются в каждом ответе (Date, идентификаторы запроса, кеширование, способ
передачи тела), не учитываются и перечисляются в конце. **Копировать как текст**
копирует результат.

![Сравнение с прежним ответом](../en/images/compare.png)

В терминале `apix compare <request> --env staging --against production`
отправляет запрос в оба окружения и выводит различия; он завершается с кодом 1,
если они различаются, так что конвейер может проверить, что два окружения
отвечают одинаково. История хранит тела до 256 КБ, поэтому более длинные
сравниваются в пределах сохранённого.

## ИИ-помощник

ИИ-помощник выключен, пока вы не включите его в **Файл › Настройки… ›
ИИ-помощник**. Apix — проект с открытым исходным кодом, и своего ИИ-аккаунта у
него нет: вы выбираете поставщика и указываете собственный ключ API.

- **Поставщик ИИ**: Claude (Anthropic), ChatGPT (OpenAI) или Gemini (Google).
- **Модель**: модель поставщика по умолчанию (Claude Opus 5.5, `gpt-5.5`,
  `gemini-2.5-flash`), или **↻** загружает модели, доступные вашему ключу, и вы
  выбираете одну.
- **Ключ API**: для выбранного выше поставщика; хранится в системном хранилище
  ключей, а не в файле; сохранение пустого поля удаляет его. Если ключа нет,
  используется `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` или `GEMINI_API_KEY`.

После этого у ответа появляется ещё одна кнопка:

- **ИИ-тесты** для успешного ответа: ИИ пишет скрипт «Тесты», проверяющий
  статус, тип содержимого и структуру тела, а Apix добавляет его в «Тесты»
  запроса (с пометкой, что он написан ИИ, без сохранения), чтобы вы прочитали
  его, прежде чем оставить.
- **Объяснить** для неудачного ответа (400 и выше): что означает ответ,
  вероятные причины и что проверить — на языке приложения.

![Объяснение неудачного ответа](../en/images/ai-explain.png)

Что отправляется поставщику: метод, URL, заголовки и тело запроса, а также
статус, заголовки и тело ответа (обрезанное до 12 КБ). Authorization, cookie и
заголовки, в имени которых есть key, token, secret или signature, маскируются
как •••. ИИ может ошибаться; без вас ничего не меняется и никуда больше не
отправляется. Снимок экрана сделан с локальным тестовым сервером, а не с
настоящим ответом.

## Плагины

Плагины добавляют то, чего нет в Apix изначально: тип авторизации, импортёр
для другого формата файлов или представление ответа. Плагин — это один файл
WebAssembly (`.wasm`), и он работает изолированно: получает JSON и отвечает
JSON, без сети, файлов и часов, а если работает слишком долго или использует
слишком много памяти, его останавливают. Плагин от другого автора может
изменить только запрос, который он подписывает, или коллекцию, которую он
импортирует, и ничего больше.

**Вид › Плагины…** показывает установленные плагины и что предлагает каждый.
**Установить из файла…** проверяет файл `.wasm` и копирует его в папку плагинов
(`<config>/Apix/plugins`), **Удалить** удаляет его, **Открыть папку**
показывает папку, а **Перезагрузить** перечитывает её после того, как вы сами
скопировали туда файлы.

![Окно «Плагины»](../en/images/plugins.png)

- **Типы авторизации** появляются в списке вкладки «Авторизация» как
  «… (плагин)» с полями, которые запрашивает плагин (`{{variables}}` в них
  работают). При отправке запроса плагин получает итоговый запрос (метод, URL,
  заголовки, тело) и добавляет заголовки или параметры запроса. Запрос, плагин
  которого не установлен, сообщает об этом и не отправляется.

  ![Запрос, подписанный плагином](../en/images/plugin-auth.png)

- **Представления** появляются рядом с «Текст», «Таблица» и «График» над
  JSON-ответом; плагин читает статус, заголовки и тело и отвечает таблицей или
  текстом.

  ![Представление от плагина](../en/images/plugin-view.png)

- У **импортёров** есть кнопка **Импортировать файл…** в окне «Плагины»: файл
  становится новой коллекцией рядом с ним, которая затем открывается.

В файле запроса авторизация через плагин выглядит так:

```toml
[auth.plugin]
plugin = "hmac-signature"

[auth.plugin.config]
key_id = "k1"
secret = "{{signing_secret}}"
```

Из терминала:

```sh
apix plugins list                     # установленные плагины и что они предлагают
apix plugins install my-plugin.wasm
apix plugins remove my-plugin
apix import endpoints.csv --plugin csv-endpoints --out shop
apix send posts/list-posts.apix --view json-stats
```

В папке `plugins/` репозитория есть три примера, собранные из
`crates/apix-plugin-sdk/examples`: **hmac-signature** (подписывает запросы
через HMAC-SHA256 по методу, пути и хешу тела), **csv-endpoints** (CSV-список
`method,url,name,folder` становится запросами) и **json-stats** (статистика
полей JSON-списка: типы, наличие, различные значения, диапазоны).

### Написание плагина

На Rust добавьте зависимость `apix-plugin-sdk`, реализуйте его трейт `Plugin` и
вызовите `export!`:

```rust
use apix_plugin_sdk::{Plugin, export, serde_json::{Value, json}};

struct Hello;

impl Plugin for Hello {
    fn manifest() -> Value {
        json!({ "name": "hello", "version": "1.0.0",
                "visualize": { "label": "Hello" } })
    }
    fn call(_hook: &str, input: Value) -> Result<Value, String> {
        let size = input["body"].as_str().unwrap_or("").len();
        Ok(json!({ "text": format!("{size} bytes") }))
    }
}

export!(Hello);
```

Соберите крейт как `cdylib` командой `cargo build --release --target
wasm32-unknown-unknown` и установите `.wasm`. По `name` из манифеста (строчные
буквы, цифры и `-`) запросы ссылаются на плагин; он может предлагать любое из
следующего:

| Ключ манифеста | Хук получает | Он отвечает |
|---|---|---|
| `auth: {label, fields: [{name, label, secret}]}` | `{method, url, headers, body, config}` | `{headers: [[name, value]], query: [[name, value]]}` |
| `import: {label, extensions}` | `{file_name, content}` | `{name, requests: [{folder, name, method, url, headers, body}]}` |
| `visualize: {label}` | `{status, headers, body}` | `{title, text}` или `{title, columns, rows}` |

Подходит любой язык, компилируемый в WebAssembly. Модуль экспортирует
`memory`, `apix_alloc(len) -> ptr`, `apix_manifest() -> i64` и
`apix_call(hook_ptr, hook_len, input_ptr, input_len) -> i64`, где `i64` — это
`ptr << 32 | len` ответа JSON в UTF-8, `{"ok": …}` или `{"error": "…"}`. Модуль
не может ничего импортировать, и каждый вызов выполняется в новом экземпляре.

## Настройка

При первом запуске Apix открывает окно **Настройка** — необязательные
дополнения в одном месте; **Справка › Настройка…** открывает его снова. Apix
работает и без них.

- **База геолокации IP**: размещает каждый маршрутизатор на карте маршрута и в
  `apix trace`. **Скачать** загружает бесплатную городскую базу DB-IP (около
  130 МБ, CC BY 4.0) в `<config>/Apix/geo`; **Обновить** загружает базу за
  последний месяц. В сети ничего не запрашивается. В терминале:
  `apix geo download`, `apix geo status`, `apix geo remove`.
- **ИИ-помощник**: показывает, включён ли он и с каким поставщиком; **Открыть
  настройки** переходит к его строкам.
- **Claude (MCP)**: **Подключить к Claude** (также **Справка › Подключить к
  Claude (MCP)…**) для открытой коллекции, см. ниже.

![Настройка](../en/images/setup.png)

### Подключение Claude

**Подключить к Claude** делает открытую коллекцию MCP-сервером для Claude,
чтобы Claude мог перечислять, отправлять и запускать её запросы с тестами, не
видя значений переменных (см.
[MCP](workflows.md#как-дать-ии-агенту-работать-с-коллекцией-mcp)).

- **Добавить в Claude Desktop** записывает запись `apix-<collection>` в
  `claude_desktop_config.json` Claude Desktop. Другие серверы и настройки
  сохраняются, а исходный файл в первый раз копируется в `.bak`; перезапустите
  Claude Desktop, чтобы использовать его. **Удалить** убирает запись.
- **Добавить в Claude Code** выполняет `claude mcp add --scope user …`, так что
  коллекция доступна во всех проектах.
- **Только список** даёт Claude только инструменты для перечисления
  (`--list-only`).
- Запись и команда показываются с кнопкой **Копировать**, чтобы добавить их
  вручную.

![Подключить к Claude](../en/images/claude-connect.png)

То же из терминала: `apix mcp my-api --add-to claude-desktop`,
`apix mcp my-api --add-to claude-code`,
`apix mcp my-api --remove-from-claude-desktop`.

## Настройки и язык

**Файл › Настройки…** (Ctrl+,):

- **Язык:** English, Türkçe, العربية, Deutsch, Français, Русский, 日本語,
  简体中文 или Español. Изменение применяется сразу. При первом запуске Apix
  следует языку системы. На арабском окно отражается зеркально: боковая панель
  справа, а меню, вкладки и формы идут справа налево, тогда как URL, код и
  таблицы ключ–значение остаются слева направо.
- **Блокировка зашифрованных коллекций:** через 5, 15 или 30 минут, через
  1 час или никогда.
- **Секреты окружений:** в файле `.local.toml` или в системном хранилище ключей
  (см. [Переменные и окружения](#переменные-и-окружения)).
- **Подтверждение в продакшене:** спрашивать перед DELETE, PUT или PATCH, пока
  активно окружение «prod» (по умолчанию включено).
- **Проверять обновления:** при запуске спрашивать GitHub, не вышла ли новая
  версия Apix (по умолчанию включено). Отправляется только этот один запрос,
  без каких-либо данных, по которым вас можно опознать, и ничего не
  скачивается: о новом выпуске сообщает уведомление с кнопкой **Скачать**,
  которая открывает его страницу. **Справка › Проверить обновления…**
  проверяет в любой момент, а `apix update` делает то же в терминале.

![Уведомление о новом выпуске](../en/images/update.png)

- **История:** включена или выключена (см. [История](#история)).

Раздел **Внешний вид** в настройках меняет то, как выглядит Apix, сразу, без
перезапуска:

- **Оформление:** тёмное, светлое или **Как в системе** — тогда оно
  переключается вместе с переключением Windows или macOS между светлым и
  тёмным режимом.
- **Тёмная тема:** Обсидиан (по умолчанию), Кибер-стекло, Dracula, Nord или
  Solarized Dark. **Светлая тема:** Дневной свет или Solarized Light. Выбор
  темы другого вида переключает на неё оформление.
- **Акцентный цвет:** цвет темы или бирюзовый, синий, фиолетовый, розовый,
  красный, оранжевый, жёлтый или зелёный — для кнопок, выделения, рамок фокуса
  и меток переменных. Светлые темы получают более насыщенный оттенок, а текст
  на акцентном цвете тёмный или белый — в зависимости от того, что лучше
  читается.
- **Прозрачность:** ползунок от 0 (непрозрачное окно) до 90 %: насколько
  рабочий стол просвечивает сквозь окно, размытый, как матовое стекло (acrylic
  в Windows, vibrancy в macOS). Фон окна становится прозрачнее вместе с ним,
  панели — медленнее, чтобы у текста оставалась подложка, а рамки светлеют,
  как край стекла; меню и диалоги остаются непрозрачными. Светлые темы
  становятся прозрачнее мягче, так как тёмному тексту нужна светлая подложка.
  По умолчанию — 20 %.
- **Размер текста:** 90 %, 100 %, 110 %, 125 % или 150 % от обычного размера,
  для всего текста в окне, сразу.
- **Размер шрифта кода:** от 11 до 18 px для редакторов кода (тела, скрипты,
  вид «Форматированный» ответа); просмотрщик очень больших тел сохраняет 13 px.
- **Плотность:** плотные, обычные или свободные строки на боковой панели.
- Редакторы кода берут цвета из темы: строки, числа и ключевые слова — как их
  задаёт тема, типы и функции — акцентным цветом, комментарии и пунктуация —
  приглушённо.

![Размер текста, размер шрифта кода и плотность](../en/images/look.png)

- **Свои темы:** **Открыть папку** открывает `<config>/Apix/themes` и в первый
  раз записывает туда `my-theme.toml`, с которого можно начать. Каждый файл
  `.toml` в этой папке — тема в списках; файл с именем встроенной темы
  (`nord.toml`) заменяет её. Файл, который не удалось прочитать, отмечается
  красным с указанием причины.

![Настройки](../en/images/settings.png)

Файл темы задаёт имя, является ли тема светлой, и любые из этих цветов
(`#RRGGBB` или `#RRGGBBAA` с непрозрачностью); не заданные цвета берутся из
Обсидиана или, для светлой темы, из Дневного света:

```toml
name = "Deep sea"
light = false

[colors]
background = "#03141FEE"      # окно, градиент до background_end
background_end = "#062A3AEE"
surface = "#05202DB3"         # панели
raised = "#0A2B3BF7"          # меню и диалоги
border = "#FFFFFF14"
accent = "#FF9F43"
text = "#E8F6FF"
muted = "#7FA3B8"
ok = "#34D399"                # 2xx, пройденные тесты
warning = "#FBBF24"
error = "#F87171"
string = "#86EFAC"            # JSON в просмотрщике больших тел
number = "#FDBA74"
keyword = "#C4B5FD"
```

Файлы тем — обычный текст, поэтому команда может делиться ими; Apix читает их
при запуске и при открытии настроек.

Настройки сохраняются в `settings.toml` в папке Apix системного каталога
конфигурации (`%APPDATA%\Apix` в Windows,
`~/Library/Application Support/Apix` в macOS, `~/.config/Apix` в Linux).

## Горячие клавиши

| Клавиши | Действие |
|---|---|
| Ctrl+Enter | Отправить |
| Esc | Отменить запрос |
| Ctrl+S | Сохранить |
| Ctrl+N | Новый запрос GET |
| Ctrl+O | Открыть папку, проект или коллекцию |
| Ctrl+K или Ctrl+P | Палитра команд |
| Ctrl+E | Переменные и окружения |
| Ctrl+, | Настройки |
| Ctrl+H | История |
| Ctrl+Shift+R | Runner |
| Alt+1…7 | Сменить метод |
| Ctrl+W | Закрыть вкладку |
| Ctrl+Tab / Ctrl+Shift+Tab | Следующая / предыдущая вкладка |
| Ctrl+Space | Подсказки в запросе GraphQL (после получения схемы) |

В macOS используйте ⌘ вместо Ctrl (Ctrl+Tab и Ctrl+Space остаются Ctrl).
