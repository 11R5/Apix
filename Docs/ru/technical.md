# Технические заметки

Как устроена сборка Apix, от чего он зависит и как его измерять.
[Архитектура](architecture.md) объясняет устройство; эта страница — практическая
сторона.

## Структура репозитория

```
crates/
├── apix-core       модель запроса, переменные, формат на диске, проекты, подписи (sign.rs), схемы GraphQL, git (git.rs, diff.rs)
├── apix-http       HTTP-движок (reqwest), сетевая трассировка, токены OAuth 2.0, SSE, WebSocket, Socket.IO, загрузка схемы GraphQL
├── apix-import     импорт из Postman, Insomnia, OpenAPI, HAR и WSDL
├── apix-codegen    документация API (HTML, Markdown), «Копировать как» (curl, curl.exe, PowerShell, код на 10 языках) и вставка curl
├── apix-vault      зашифрованные коллекции
├── apix-script     скрипты перед запросом и тестовые скрипты (QuickJS)
├── apix-runner     запуски коллекций, файлы данных, отчёты JUnit/JSON/HTML/Markdown
├── apix-grpc       вызовы gRPC: файлы .proto, рефлексия сервера или описания из кода и JSON, сообщения в виде JSON
├── apix-proto      другие протоколы: MQTT
├── apix-mock       локальный mock-сервер, отвечающий сохранёнными примерами
├── apix-capture    записывающий прокси, который сохраняет проходящие запросы
├── apix-route      маршрут до сервера и где находятся его узлы
├── apix-plugins    плагины WebAssembly (wasmi): загрузка, песочница, хуки авторизации, импорта и представлений
├── apix-plugin-sdk написание плагинов на Rust; его examples/ — это плагины из plugins/
├── apix-cli        команда `apix`
└── apix-desktop    настольное приложение (GPUI); тексты интерфейса в locales/
tools/
├── icongen         собирает иконки приложения из Logo/
└── docs-check      перечисляет устаревшие переводы документации
vendor/
└── gpui-pre-windows  Windows-бэкенд gpui с исправлением текста справа налево
scripts/
├── package-*.sh/.ps1  пакеты выпуска: установщик и zip для Windows, .dmg для macOS, .deb, tarball, пакет Arch
└── measure.ps1     замеры производительности для README
examples/
├── jsonplaceholder небольшая коллекция, которую приложение открывает при запуске из репозитория
└── ci/             примеры для GitHub Actions (также плановые мониторы), GitLab CI и Azure Pipelines
plugins/            примеры плагинов (.wasm), собранные из examples apix-plugin-sdk
site/               страница загрузки (GitHub Pages), читает последний выпуск с GitHub
action.yml          GitHub Action (`uses: 11R5/Apix@…`)
Dockerfile          командная строка `apix` в виде образа контейнера
.github/workflows/  CI на трёх системах и образ, публикуемый по тегам версий
Docs/
├── languages.toml  языки документации
├── en/ tr/         руководство пользователя, архитектура, технические заметки, рабочие процессы
└── IS-PLANI.md, ROADMAP.md   план (подробно на турецком, кратко на английском)
```

## Сборка

Требования: стабильный [Rust](https://rustup.rs) (репозиторий проверяется на 1.99).

- **Windows:** набор инструментов MSVC (Visual Studio или Build Tools с
  «Desktop development with C++» и Windows 10/11 SDK).
- **macOS:** инструменты командной строки Xcode.
- **Linux:** пакеты разработки X11/Wayland, Vulkan и fontconfig, которые нужны
  GPUI (README gpui-kit перечисляет их для каждого дистрибутива); пока не
  проверено.

```sh
cargo test                       # движок, CLI, импорт, генерация кода, vault, проверка документации
cargo run -p apix-desktop        # настольное приложение (debug)
cargo test -p apix-desktop       # модульные тесты приложения (переводы, пути, …)
cargo build --release            # оптимизированный CLI
cargo build --release -p apix-desktop
```

`cargo build` и `cargo test` без `-p` пропускают настольное приложение, которое
тянет за собой весь GPU-стек; собирайте его явно. Зависимости оптимизируются
даже в debug-сборках, чтобы интерфейс оставался плавным во время разработки.

Примерам плагинов в `plugins/` один раз нужна цель WebAssembly
(`rustup target add wasm32-unknown-unknown`), затем
`cargo build -p apix-plugin-sdk --examples --release --target wasm32-unknown-unknown`;
скопируйте `target/wasm32-unknown-unknown/release/examples/*.wasm` в `plugins/`
(заменив в именах `_` на `-`). Тесты `apix-plugins` загружают эти файлы.
`wasmi` оптимизируется и собирается без отладочных проверок и в debug-сборках
(`[profile.dev.package.wasmi]`): цикл его интерпретатора опирается на хвостовые
вызовы, которые иначе переполняют стек.

Профиль release использует полный (fat) LTO, одну единицу кодогенерации и
удалённые символы. Полная release-сборка настольного приложения занимает
несколько минут.

## Основные зависимости

| Область | Crates |
|---|---|
| Интерфейс | `gpui-kit` 0.7 (GPUI и его библиотека компонентов), грамматики tree-sitter для JSON и GraphQL |
| HTTP | `reqwest` 0.12 с rustls, `tokio`, `hyper-util`, слои `tower` для замеров времени |
| gRPC | `tonic` 0.14 (клиент, поверх тех же hyper и rustls), `prost-reflect` (сообщения, известные во время выполнения, JSON), `protox` (читает файлы .proto без `protoc`), `regex` (чтение сгенерированного кода и типов), `tonic-reflection` (клиент рефлексии), `rustls` и `tokio-rustls` для gRPC с выключенной проверкой сертификатов; `rcgen` создаёт тестовые сертификаты (только в тестах) |
| Сетевые подробности | `x509-parser` (сертификаты), `sha2` (отпечатки), `netdev` (интерфейсы, шлюз, DNS-серверы); подробности TLS через собственные хуки rustls (без лишнего crate); `flate2` и `brotli-decompressor` распаковывают сжатые тела (уже собраны для reqwest); маршрут из системных `tracert`, `traceroute` или `tracepath`, места из `maxminddb` |
| Подписи | `sha2`, `sha1`, `hmac`, `md-5`, `base64`, `rand_core` (AWS SigV4, OAuth 1.0, Digest, PKCE) |
| Шифрование | `chacha20poly1305` (XChaCha20-Poly1305), `argon2`, `zeroize`, `keyring` (хранилище учётных данных ОС) |
| Скрипты | `rquickjs` (QuickJS, собирается из C системным компилятором); библиотеки `require` — собственный JavaScript Apix, хеширование через `sha1`, `sha2`, `md-5`, `hmac` |
| Файлы | `serde`, `toml`, `serde_json`, `notify` (отслеживание файлов), `trash`; git через установленную программу `git` (без библиотеки) |
| Ответы | `serde_json_path` (JSONPath, RFC 9535) и `jaq-core`, `jaq-std`, `jaq-json` (jq) для фильтра; `regex` для поиска в больших телах |
| Плагины | `wasmi` 2 (интерпретатор WebAssembly с ограничениями топлива и памяти) |
| Языки | `rust-i18n` (общий с gpui-kit), `sys-locale` |

## Файлы, которые Apix пишет вне коллекций

| Файл | Содержимое |
|---|---|
| `<config>/Apix/settings.toml` | язык, внешний вид, тёмная и светлая темы, акцентный цвет, прозрачность, время автоблокировки, история включена или выключена, куда идут секреты окружений, работают ли мониторы, пока приложение открыто |
| `<config>/Apix/capture-ca.pem`, `capture-ca.key` | локальный центр сертификации прокси записи, создаётся при первом открытии HTTPS; ему доверяют, только если вы добавите его сами |
| `<config>/Apix/geo/*.mmdb` | база местоположений IP для карты маршрута (скачивается из окна «Маршрут и карта» или кладётся туда вручную) |
| `<config>/Claude/claude_desktop_config.json` | пишется только функцией «Подключить к Claude»: запись `apix-<collection>` в `mcpServers` (оригинал сохраняется как `.json.bak`) |
| `<config>/Apix/monitors/` | последние 500 результатов каждого монитора, одна строка JSON на запуск (`<hash of the collection folder>-<monitor name>.jsonl`), пишут `apix monitor` и приложение |
| `<config>/Apix/state.toml` | недавно открытые коллекции, выбранное окружение и открытые вкладки для каждой коллекции или проекта (не для зашифрованных коллекций) |
| `<config>/Apix/cookies.json` | хранилище cookie (сеансовые cookie не сохраняются) |
| `<config>/Apix/graphql/*.json` | последняя загруженная схема GraphQL для каждого адреса (ответ сервера на интроспекцию), имя — хеш URL |
| `<config>/Apix/themes/*.toml` | ваши собственные темы (пишется только когда вы нажимаете **Открыть папку** в настройках и папка пуста: один пример) |
| Хранилище учётных данных ОС, служба `Apix` | только по запросу: запомненные пароли зашифрованных коллекций (`vault:<folder>`) и секреты окружений (`env:<id>`, плюс `env:<id>#1`, … для длинных значений), ключи ИИ-помощника (`ai:anthropic-api-key`, `ai:openai-api-key`, `ai:google-api-key`) |
| `<config>/Apix/plugins/*.wasm` | установленные плагины (окно «Плагины», `apix plugins install`) |
| `<config>/Apix/history/` | отправленные запросы (`{{variables}}` не подставлены) и их ответы: `index.jsonl`, по одному `<id>.json` и `<id>.body` на запись; последние 300, тела обрезаются до 256 KB; вызов gRPC хранит свой журнал как тело |

`<config>` — это `%APPDATA%` в Windows, `~/Library/Application Support` в macOS
и `~/.config` в Linux. Токены OAuth 2.0 и пароли зашифрованных коллекций
никогда не записываются на диск.

## Переменные окружения

| Переменная | Действие |
|---|---|
| `APIX_PASSWORD` | Пароль зашифрованной коллекции для CLI (`--password-env` выбирает другую переменную). |
| `APIX_VAR_<NAME>` | Переменная для CLI: `APIX_VAR_TOKEN` заполняет `{{token}}` (сопоставляется с именами коллекции без учёта регистра); важнее окружений, `--var` важнее неё. |
| `APIX_THEME` | идентификатор темы (`obsidian`, `cyber`, `dracula`, `nord`, `solarized-dark`, `daylight`, `solarized-light` или имя файла темы); показывает эту тему независимо от настроек. |
| `APIX_BENCH` | `startup` или `json:<url>`: измерить и выйти (см. ниже). |
| `APIX_BENCH_OUT` | Файл, в конец которого дописываются замеры. |
| `APIX_BENCH_PHASES` | Вместе с `APIX_BENCH=startup`: также сообщать, когда был достигнут каждый шаг запуска (строки `phase_…`), чтобы видеть, куда уходит время. |
| `APIX_UPDATE_URL` | Куда обращается проверка обновлений вместо последнего выпуска на GitHub (форк, зеркало, тестовый сервер). |
| `OPENAI_API_KEY`, `GEMINI_API_KEY` (или `GOOGLE_API_KEY`), `ANTHROPIC_API_KEY` | Ключ ИИ-помощника, когда для этого провайдера в связке ключей ничего не хранится. |
| `APIX_CLAUDE_CONFIG` | Файл конфигурации Claude Desktop, который пишет «Подключить к Claude», вместо настоящего (для тестов). |
| `APIX_AI_URL` | Куда ИИ-помощник отправляет запросы Messages API вместо Anthropic (прокси, тестовый сервер). |
| `APIX_GEO_URL` | Откуда **Скачать DB-IP Lite** скачивает вместо DB-IP. |
| `APIX_PLUGINS_DIR` | Папка плагинов вместо `<config>/Apix/plugins`. |
| `GITHUB_BASE_REF` | Задаётся GitHub Actions в pull request: `apix run --changed` без значения сравнивает с `origin/<it>`. |

## Измерение производительности

`scripts/measure.ps1` собирает release-версию приложения и измеряет:

- **Размер release-бинарника.**
- **От запуска до первого кадра:** от `main` до отрисовки первого кадра
  (`APIX_BENCH=startup`), медиана нескольких запусков.
- **Память в простое:** рабочий набор через пять секунд после запуска с
  открытой коллекцией-примером.
- **Большой JSON на экране:** GET тела JSON размером 100 MB из локального
  примера `big_json_server`, от отправки до отрисовки ответа
  (`APIX_BENCH=json:<url>`), чтобы сеть не входила в число.

```powershell
powershell -File scripts/measure.ps1          # Windows PowerShell
pwsh scripts/measure.ps1 -NoBuild -Runs 7     # PowerShell 7, также в macOS/Linux
```

Скрипт печатает таблицу Markdown с машиной, на которой он работал; README
показывает последнюю. Замеры времени берутся из `crates/apix-desktop/src/bench.rs`,
который ничего не делает, если `APIX_BENCH` не задана.

Другие помощники:

```sh
cargo run -p apix-http --release --example big_json_server -- 100   # 100 MB JSON на :8765
cargo run -p apix-http --example oauth_server                       # тестовый сервер OAuth 2.0 на :8766
cargo run -p apix-http --example sse_server                         # server-sent events на :8767 (продолжает после Last-Event-ID)
cargo run -p apix-http --example ws_server                          # эхо WebSocket (и бинарное) и тикер на :8768
cargo run -p apix-http --example graphql_server                     # адрес GraphQL (схема и несколько пользователей) на :8769
cargo run -p apix-http --example socketio_server                    # Socket.IO 4: пространства имён /, /chat, /ticker, /private (auth) на :8771
cargo run -p apix-grpc --example grpc_server                        # gRPC Greeter с рефлексией на :8770
cargo run -p apix-http --example soap_server                        # калькулятор SOAP на :8773 (WSDL по ?wsdl; ошибки с 500 и 200)
cargo run -p apix-proto --example mqtt_broker                       # брокер MQTT на :8772 (`clock` тикает каждую секунду)
```

## Языки интерфейса

Тексты интерфейса находятся в `crates/apix-desktop/locales/<code>.yml`, по одной
плоской паре `key: value` на строку; их читает rust-i18n через макрос `tr!`.
Модульный тест падает, если в языке нет ключа или он использует другие
`%{placeholders}`, чем английский. Чтобы добавить язык, скопируйте `en.yml`,
переведите его и добавьте одну строку в `LANGUAGES` в `src/i18n.rs`.

## Языки документации

`Docs/languages.toml` перечисляет языки документации. Переводы начинаются
с метки, называющей английский текст, из которого они сделаны:

```
<!-- translated from en/user-guide.md sha256:0123456789abcdef -->
```

```sh
cargo run -p docs-check                      # перечисляет отсутствующие или устаревшие переводы и битые ссылки
cargo run -p docs-check -- stamps            # печатает текущую метку каждого английского документа
cargo run -p docs-check -- site site/docs    # документация в виде веб-страниц (GitHub Pages)
```

Изображения для руководства пользователя делает `scripts/docs-tour.ps1`. Он запускает примеры серверов и открывает настольное приложение по разу для каждого языка с `APIX_TOUR=Docs/tour/scenes.toml`: приложение само готовит каждую сцену (открывает запросы демонстрационной коллекции из `Docs/tour/demo`, отправляет их, открывает окно), а скрипт сохраняет окно как `Docs/<язык>/images/<сцена>.png`. `APIX_CONFIG_DIR` держит настройки, историю и cookie приложения на время обхода в отдельной папке, поэтому ваши не затрагиваются.

## Встроенная копия бэкенда gpui

Отрисовщик текста GPUI в Windows (crate `gpui-pre-windows` 0.3.9) располагал
каждую последовательность глифов слева направо, поэтому арабские слова
выглядели зеркально. `vendor/gpui-pre-windows` — это тот же crate с
исправленным `DrawGlyphRun` (изменение помечено «Apix patch»), и `Cargo.toml`
рабочего пространства подставляет его через patch. Его можно убрать, когда
исходный crate исправят.

## Непрерывная интеграция

`.github/workflows/ci.yml` запускается при каждом push и pull request:

| Задача | Что проверяет |
|---|---|
| Формат и документация | `cargo fmt --check`; `docs-check` (переводы следуют английской документации) |
| Движок и CLI | `cargo clippy -D warnings` и `cargo test` для всего, кроме настольного приложения, в Windows, macOS и Linux |
| Настольное приложение | то же самое для `apix-desktop` на трёх системах (в Linux сначала ставятся библиотеки окон, шрифтов и связки ключей) |
| GitHub Action | собственный action репозитория (`uses: ./`) на `examples/jsonplaceholder`, в Linux и Windows, и то, что он записал свои отчёты |

`.github/workflows/release.yml` собирает пакеты выпуска по тегу версии
(`v1.2.3`, который должен совпадать с `Cargo.toml`) и публикует их как выпуск
GitHub с `SHA256SUMS.txt`; при ручном запуске он только собирает их как
артефакты запуска. Windows: `scripts/package-windows.ps1` (Inno Setup 6,
`packaging/windows/apix.iss`: установка для пользователя или для компьютера,
необязательные PATH и связь с `.apix`, деинсталлятор). macOS:
`scripts/package-macos.sh` собирает обе архитектуры, объединяет их через `lipo`
в `Apix.app` (подпись ad-hoc) и делает `.dmg`. Linux (на Ubuntu 22.04, поэтому
достаточно glibc 2.35): `scripts/package-linux.sh` делает tarball с
`install.sh`, `.deb` (зависимости из `dpkg-shlibdeps`, плюс `libvulkan1`) и
заполненный `PKGBUILD`; `scripts/package-arch.sh` собирает из них пакет Arch в
контейнере `archlinux`. Пакет `.deb` и пакет Arch устанавливаются в workflow и
проверяются на отсутствующие библиотеки. `.github/workflows/pages.yml`
публикует `site/` на https://11r5.github.io/Apix/ .
Каждый выпуск также содержит заполненный cask для Homebrew (`apix.rb`, из
`packaging/homebrew`) и манифесты winget (`AhmetDemir.Apix*.yaml`, из
`packaging/winget`), которые делает `scripts/channel-manifests.sh`, чтобы
скопировать их в репозиторий tap ([11R5/homebrew-apix](https://github.com/11R5/homebrew-apix))
и в pull request к `microsoft/winget-pkgs`. `scripts/action-repo.sh` пишет
файлы [11R5/apix-action](https://github.com/11R5/apix-action) — копии
`action.yml` для Marketplace, которая всегда скачивает выпуск (Marketplace не
показывает репозиторий с файлами workflow); после каждого выпуска она получает
тег `v<version>`, а `v1` переносится на новый коммит.
`.github/workflows/docker.yml` публикует образ контейнера по тегам версий.
Action кэширует собранный им `apix` под хешем исходников движка, поэтому новый
коммит пересобирает его, а неизменённый использует повторно.
