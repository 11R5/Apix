# Apix ユーザーガイド

Apix はデスクトップの API クライアントです。HTTP リクエストを組み立てて送信し、レスポンスを読みます。リクエストはフォルダー内の小さなテキストファイルとして保存されるので、コレクションをコードと一緒に git で管理できます。このガイドではアプリを順に紹介します。よくある作業は[ワークフロー](workflows.md)で手順を追って説明しています。`apix` コマンドラインを使えば、同じリクエストをターミナルや CI で実行できます。

## Apix のインストール

ダウンロードページ **https://11r5.github.io/Apix/** では、お使いのシステム向けの最新リリースを提供しています。すべてのファイルは[リリースページ](https://github.com/11R5/Apix/releases)にもあります。どのファイルにもデスクトップアプリと `apix` コマンドラインが含まれています。

| システム | ファイル | 方法 |
|---|---|---|
| Windows 10/11 | `Apix-<version>-windows-x64-setup.exe` | 実行します。管理者権限なしで自分のユーザーにインストールされます（選べば全ユーザーにも）。Apix をスタートメニューに追加し、`apix` を PATH に入れたり `.apix` ファイルを開けるようにしたりできます。`…-windows-x64.zip` はインストールしない同じ内容です。 |
| macOS 11+ | `Apix-<version>-macos-universal.dmg` | 開いて Apix をアプリケーションフォルダーにドラッグします。Apple シリコンと Intel の両方に対応する 1 つのアプリです。コマンドラインは `/Applications/Apix.app/Contents/MacOS/apix` です。または `brew install --cask 11r5/apix/apix` を使うと、`apix` も PATH に入ります。 |
| Debian、Ubuntu、Mint など | `apix_<version>_amd64.deb` | `sudo apt install ./apix_<version>_amd64.deb` |
| Arch、Manjaro、EndeavourOS など | `apix-<version>-1-x86_64.pkg.tar.zst` | `sudo pacman -U ./apix-<version>-1-x86_64.pkg.tar.zst`、またはリリースの `PKGBUILD` で `makepkg -si` |
| その他の Linux (glibc 2.35+) | `apix-<version>-linux-x64.tar.gz` | 展開して `./install.sh` を実行します（自分のユーザー向け。全ユーザーなら `--system`、削除は `--uninstall`） |
| 任意の Linux、1 ファイル | `Apix-<version>-x86_64.AppImage` | `chmod +x` して実行します。`Apix-….AppImage cli …` でコマンドラインが動きます |

ビルドにはコード署名をしていません（署名には毎年費用がかかるため、今のところ予定はありません）。Windows では SmartScreen がインストーラーを止めることがあります。その場合は **詳細情報 › 実行** を選びます。macOS では、初回は右クリック › **開く** で Apix を開くか、`xattr -dr com.apple.quarantine /Applications/Apix.app` を実行します。Linux では Apix は Vulkan で描画するため、グラフィックスドライバーが Vulkan に対応している必要があります（ほとんどのシステムでは Mesa が対応しています）。各リリースの `SHA256SUMS.txt` にファイルのチェックサムが載っています。

## コレクションを開く

**コレクション**とは、`apix.toml` ファイルとリクエスト（`.apix` ファイル）を入れたフォルダーです。サブフォルダーに分けることもできます。**ファイル › 開く…**（Ctrl+O）で開くか、**ファイル › 新しいコレクション…** で新しく作ります。まだコレクションでないフォルダーを選ぶと、Apix はコレクションにするかどうか尋ねます。

最近開いたコレクションは **ファイル › 最近使ったものを開く** にあります。フォルダーを指定してアプリを起動すると（`apix-desktop path/to/collection`）、そのフォルダーが直接開きます。

## ウィンドウ

- **サイドバー（左）：** コレクションのフォルダーとリクエストです。ディスク上のファイルから読み込み、ファイルが変わると更新されます。コレクション名の下のピッカーでアクティブな環境を選びます。
- **タブ（上）：** 開いたリクエストごとにタブができます。
- **リクエストペイン：** メソッド、URL、そしてパラメーター、ヘッダー、認証、ボディ、設定の各タブです。
- **レスポンスペイン（右）：** ステータス、時間、サイズ、レスポンスボディです。
- **ステータスバー（下）：** コレクション、開いているリクエストのファイル、よく使うショートカットです。
- **メニューバー：** ファイル、リクエスト、環境、表示、ヘルプにすべてのコマンドがあります。

## リクエストを送信する

1. URL バーの左でメソッドを選びます（または Alt+1…7 で GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS）。
2. URL を入力します。`{{variables}}` はどこにでも書けます（[変数](#変数と環境)を参照）。
3. **送信** を押すか Ctrl+Enter を押します。Esc でまだ実行中のリクエストをキャンセルします。

名前に「prod」を含む環境がアクティブなとき、Apix は DELETE、PUT、PATCH を送る前に確認し、送信先の完全な URL を表示します。**設定 › 本番環境で確認する** でこれをオフにできます。

**新しいリクエスト**（Ctrl+N）は GET リクエストを開きます。サイドバーの **+** メニューではすべてのメソッドを選べ、POST、PUT、PATCH は JSON ボディで始まります。Ctrl+S で保存します。タブとサイドバーの点は未保存の変更を示します。

## パラメーターとヘッダー

**パラメーター** は URL のクエリ文字列で、**ヘッダー** はそのまま送信されます。行のチェックを外すと、ファイルには残したまま送信しません。キーのない行は無視されます。`Content-Type` は、自分で追加しない限りボディの種類から設定されます。キーと値の中の `{{variables}}` は URL バーと同じくチップとして表示され、マウスを重ねると値が見えます。

URL バーとパラメーターの表は連動します。URL に `?page=2&sort=name` と入力すると表が埋まり、行を編集、追加、チェック解除、削除すると URL が書き換わります。値はデコードされた形で表示され（`%20` は空白になります）、送信時にエンコードされます。ファイルにはクエリを除いた URL が保存され、行は `[[query]]` として保存されます。

**パス変数。** `{{base}}/users/:id/posts` のように `:name` と書いたパスセグメントは、パラメータータブの **パス変数** の下に行ができます。送信時にはその値がセグメントを置き換え、1 つのセグメントとしてエンコードされます（`a b/c` は `a%20b%2Fc` になります）。値には `{{variables}}` も使えます。空のままの変数は書いたとおりに送信されます。値はファイルに `[[path]]` として保存されます。Postman コレクションのパス変数もそのまま取り込まれます（エクスポート時にも戻ります）。

![パラメーターとパス変数](../en/images/path-variables.png)

**ヘッダーの候補。** ヘッダー名を入力していると、合う一般的なヘッダー名が行の下に表示されます（入力した文字で始まるものが先で、表にすでにあるものは出ません）。値には、`Content-Type` なら `application/json` のように、そのヘッダーでよく使う値が候補に出ます。Enter で最初の候補を、クリックで任意の候補を選びます。名前を入れたあとは値の入力に移ります。

![入力中に候補として表示されるヘッダー名](../en/images/header-hints.png)

## ボディ

ボディタブでは次の種類を選べます。

| 種類 | 送信される内容 |
|---|---|
| なし | ボディなし。 |
| JSON、テキスト、XML、HTML | 書いたとおりのテキスト。構文ハイライト付きです（ヘッダーで別の指定がない限り `application/json`、`text/plain`、`application/xml`、`text/html`）。 |
| フォーム | `application/x-www-form-urlencoded` のキーと値の行。 |
| Multipart | `multipart/form-data`。各フィールドは **テキスト** か **ファイル** です。フォルダーボタンで 1 つ以上のファイルを選びます。横の種類欄でフィールド自身の Content-Type（`application/json` や `image/png` など）を指定します。空なら Apix が選びます。 |
| バイナリ | 1 つのファイルのバイト列。ヘッダーで別の指定がない限り `application/octet-stream` として送信します。Apix はファイルサイズ、または「ファイルが見つかりません」を表示します。 |
| GraphQL | クエリエディターと JSON の変数エディター。`{"query", "variables"}` の JSON として送信します。 |

![Multipart ボディ](../en/images/body.png)

コレクション内のファイルパスはリクエストファイルからの相対パスで保存されるので、別のマシンでもコレクションがそのまま動きます。

### GraphQL スキーマと補完

クエリの上の **スキーマを取得** は、リクエストの URL、ヘッダー、認証、環境を使ってサーバーにスキーマを問い合わせます（標準のイントロスペクションクエリ）。そのため、トークンが必要なスキーマも取得できます。取得後は次のことができます。

- クエリを入力すると、カーソル位置に合う候補が出ます。選択中の型のフィールド（型付き）、`(` の後ならフィールドの引数、`:` の後なら enum の値と `true`/`false`、入力オブジェクトのフィールド、union やインターフェイスなら `... on Type` フラグメント、`on` の後や `$variable: Type` の中なら型名です。非推奨のフィールドは最後に並びます。Ctrl+Space で入力せずに候補を開けます。
- フィールド、引数、enum の値にマウスを重ねると、型と説明が表示されます。
- 変数エディターでは、クエリが宣言した変数（`$role: Role`）がキーとして候補に出ます。値には入力オブジェクトのフィールド、enum の値（JSON 文字列として）、`true`/`false` が候補に出ます。
- **スキーマを表示** でスキーマ全体を SDL としてクエリの横に表示します。

![スキーマからの補完](../en/images/graphql.png)

Apix はエンドポイントごとのスキーマを保存し（設定フォルダーの `graphql/` 内）、その URL へのリクエストを開くと再び読み込みます。そのため **スキーマを更新** が必要なのは API が変わったときだけです。イントロスペクションを無効にしたサーバーはエラーを返し、そのエラーがスキーマの状態の代わりに表示されます。

コマンドラインでは、`apix schema request.apix` がスキーマを SDL として出力します（`--json` はサーバーの応答をそのまま出力します）。

## 認証

認証タブでは、リクエストが自分を証明する方法を設定します。

| 種類 | 説明 |
|---|---|
| 親から継承 | 既定値です。認証を設定している最も近いフォルダー、コレクション、プロジェクトの認証を使います。タブにはそれが何で、どこから来ているかが表示されます。 |
| 認証なし | 親が認証を設定していても何も送りません。 |
| Bearer トークン | `Authorization: Bearer <token>`。 |
| Basic 認証 | ユーザー名とパスワード。 |
| API キー | 好きなヘッダーまたはクエリパラメーター。 |
| Digest 認証 | Apix がサーバーの Digest チャレンジ（MD5 または SHA-256）に応答します。 |
| OAuth 1.0 | HMAC-SHA1、HMAC-SHA256、PLAINTEXT。ヘッダーまたはクエリ文字列に入れます。送信のたびに新しい nonce とタイムスタンプを使います。 |
| OAuth 2.0 | クライアントクレデンシャル、パスワード、または PKCE 付きの認可コード。Apix が自分でトークンを取得し、Bearer トークンとして送信します。 |
| AWS Signature | アクセスキー、シークレットキー、任意のセッショントークン、リージョン、サービスを使う AWS Signature Version 4。 |

![認証タブの OAuth 2.0](../en/images/auth.png)

**OAuth 2.0 のトークン。** 最初の送信でトークンを取得し、以降の送信ではそれを再利用します。期限が切れるとリフレッシュトークンで更新します。**新しいトークンを取得** はすぐに取得し、**破棄** はトークンを捨てます。トークンはメモリにだけ保持され、ディスクには書き込まれません。認可コードグラントでは、Apix がブラウザーでサインインページを開き、`http://127.0.0.1`（空きポート、またはクライアントに登録した **リダイレクト URL**）で応答を受け取ります。

**共有の認証。** フォルダーまたはコレクションを右クリックして **認証…** を選ぶと、中のすべてに対して認証を一度で設定できます。**環境 › プロジェクトの認証…** はプロジェクト全体に対して同じことをします。認証が *親から継承* のリクエストはこれを使います。

## リクエスト設定

設定タブでは、リクエストの送り方を制御します。

| 設定 | 既定値 |
|---|---|
| タイムアウト（秒） | なし。リクエストは終わるかキャンセルするまで実行されます。`0` もタイムアウトなしを意味します |
| リダイレクトに従う | オン |
| 最大リダイレクト数 | 10 |
| TLS証明書を検証 | オン。オフにするのは信頼できるテストサーバーの場合だけにしてください |
| プロキシ | 環境変数から（`HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`）。*オフ* ならこれらを無視します。URL を書くとそのプロキシを明示的に使います |
| クライアント証明書 | なし。PEM ファイルで、鍵は同じファイルでも別のファイルでもかまいません |
| 信頼する CA | 通常のルート証明書のみ。PEM ファイルで独自の認証局（社内 CA や自己署名 CA）を追加できます。その場合もサーバーは検証されます |
| Cookieを送信 | オン |

空欄の項目（または *継承*）は、それを設定している最も近いフォルダー、コレクション、プロジェクトの値を使い、最後は上の既定値になります。認証と同じ連鎖です。フォルダーまたはコレクションを右クリックして **リクエスト設定…** を選ぶと、中のすべてに対して一度で設定できます。**環境 › プロジェクトのリクエスト設定…** はプロジェクト全体に対して同じことをします。フォームの下の行には、リクエストが最終的に使う値が表示されます。プロキシと証明書の欄では `{{variables}}` が使え、証明書の相対パスはそれを設定したファイルを基準に解決されます。

リクエストファイル（および `folder.toml`、`apix.toml`、`apix-project.toml`）では、設定は `[settings]` テーブルです。

```toml
[settings]
timeout_ms = 5000
tls_verify = false
proxy = ""          # "" = 環境変数で設定されていてもプロキシを使わない
client_cert = "certs/client.pem"
ca_cert = "certs/company-ca.pem"
```

**形式を指定してコピー** は対応する curl のフラグ（`-m`、`-L --max-redirs`、`-k`、`-x`、`--cert`、`--key`、`--cacert`）を書き出し、これらのフラグを含む curl コマンドを貼り付けるとタブが埋まります。`apix send` と `apix run` には `--timeout`、`--insecure`、`--proxy`、`--cacert` があり、ファイルの設定より優先されます。これらの設定は gRPC リクエストにも適用されます。Postman のリクエストごとのオプション（`protocolProfileBehavior`）もインポートされます。

## Cookie

Apix は Cookie ジャーを 1 つ持っています。`Set-Cookie` の応答は自動で保存され、同じサイトへの以降のリクエストで送信されます。再起動後も同様です（アプリ設定の隣の `cookies.json`。セッション Cookie はアプリの終了とともに消えます）。**リクエスト › Cookie…** で一覧を見たり、個別の Cookie を削除したり、ジャーを空にしたりできます。設定タブの **Cookieを送信** で、リクエスト、フォルダー、コレクション、プロジェクト単位でジャーをオフにできます。CLI は実行のたびに空のジャーで始まります。

## 変数と環境

URL、ヘッダー、ボディ、認証の欄に `{{name}}` と書くと、送信時に Apix が値を埋めます。URL バーでは各変数が色付きのチップになります。マウスを重ねると値とその出どころが表示されます。赤いチップはどこにも定義されていない変数です。

値は層になっており、後のものが優先されます。

1. **プロジェクト** の変数（プロジェクト内のすべてのコレクションで共有）
2. **コレクション** の変数（`apix.toml`）
3. アクティブな **環境**（`environments/<name>.toml`）

**環境 › 変数と環境…**（Ctrl+E）で編集します。トークンやパスワードには **シークレット** にチェックを入れます。シークレットの値は `environments/<name>.local.toml` に保存され、Apix がこのファイルを `.gitignore` に追加するので、コミットされることはありません。

ディスクにも残したくない場合は、**設定 › 環境のシークレット › システムキーチェーン** を選びます。値はシステムの資格情報ストア（Windows では資格情報マネージャー、macOS ではキーチェーン、Linux では Secret Service）に入り、`<name>.local.toml` にはそのエントリーの ID だけが残ります。そのため、環境の名前を変えたりフォルダーを移動したりしても動作します。`apix` コマンドラインも同じ方法で読み取ります。設定を変えると、開いているコレクションまたはプロジェクトのシークレットはすぐに移動し、その他は次に保存したときに移動します。暗号化されたコレクションのシークレットは常にその中に残ります。

![変数ダイアログ](../en/images/variables.png)

**動的変数** は使うたびに新しい値になります。`{{$guid}}`、`{{$timestamp}}`、`{{$isoTimestamp}}`、`{{$randomInt}}`、`{{$randomEmail}}` などがあります。変数ダイアログの **動的変数** ページに、すべての変数がサンプル値付きで一覧表示されます。

## レスポンス

レスポンスペインには、ステータス、最初のバイトまでの時間と合計時間、サイズが表示されます。**整形** は JSON を整形し（矢印でブロックを折りたためます）、XML と HTML をインデントして色付けします。**生データ** は受け取ったままのボディを、**ヘッダー** はレスポンスヘッダーを、**Hex** はバイト列を表示します。非常に大きなボディ（数十メガバイト）は、見えている行だけを描画する高速ビューアーで開きます。

Apix はボディの種類を `Content-Type` から判断し、そこから有用な情報が得られない場合はバイト列から判断します。画像（PNG、JPEG、GIF、WebP、BMP、SVG）は **整形** に表示されます。その他のバイナリデータ（PDF、zip など）は、読めないテキストの代わりに短い概要が表示されます。省略可能な閉じタグを省いた HTML は、整形せずに受け取ったまま表示されます。

ステータス行の末尾にある **↓** ボタンは、ボディを 1 バイトも変えずにファイルに保存します。提案されるファイル名はサーバーの `Content-Disposition` または URL から取り、内容に合った拡張子が付きます。

**検索。** ボディ内で Ctrl+F を押すか、ステータス行の虫眼鏡を使うと、**整形**、**生データ**、**Hex** を大文字小文字を区別せずに検索します。Enter（または F3）で次の一致へ、Shift+Enter（Shift+F3）で前へ移動します。件数表示で現在位置がわかります。非常に大きなボディ用の高速ビューアーはバックグラウンドで全体を検索し、100,000 件で数えるのをやめます。

**フィルター。** JSON レスポンスでは **整形** の上にフィルター欄があります。`$` で始まる式は JSONPath（RFC 9535）、それ以外は jq として扱われるので、次のどちらも使えます。

```text
$.users[?@.active].email
.users[] | select(.active) | {name, email}
```

![JSONPath でフィルターした JSON レスポンス](../en/images/response-filter.png)

欄に式がある間は、**整形** のボディが結果に置き換わります（横の件数は値の数です）。**生データ** と **Hex** は引き続きボディ全体を表示し、✕ で元に戻ります。JSONPath は一致したものの一覧を返し、jq は出力を順に返します。フィルターは同じリクエストの次のレスポンスにも残るので、1 つの値を見ながら何度でも送信できます。`apix send --filter '<expression>'` はフィルターが選んだものだけを出力します。

**表とグラフ。** フィルター行の末尾にある **テキスト**、**表**、**グラフ** で、JSON レスポンス（またはフィルターが選んだもの）をテキスト、レコードの表、棒グラフとして表示します。レコードはボディ内の配列、またはその中で最も長いオブジェクトの配列（`$.items`、`$.data`）です。各キーが列になり、ネストしたオブジェクトはコンパクトな JSON で表示されます。グラフは 1 つの数値の列（**値**）を、行の名前になる列（**ラベル**）に対して描きます。どちらも選べます。8 MB を超えるボディは表にしないので、先にフィルターしてください。`apix send --table` はターミナルに同じ表を出力します（`--filter` と併用すると、選んだものの表になります）。Apix には Web ビューがないため、Postman の `pm.visualizer.set` テンプレートは描画されません。これを呼ぶスクリプトにはコンソールに注記が出ます。

![フィルターしたレスポンスの表ビュー](../en/images/visual-table.png)

![グラフビュー](../en/images/visual-chart.png)

**例。** ステータス行のトレイボタンで、レスポンスをリクエストの例として保存します。ステータス、ヘッダー、ボディと、元のリクエストを書いたままの形で保存します（`{{variables}}` はそのまま残るので、トークンがファイルに入ることはありません）。サーバーが設定する Cookie は除外され、2 MB を超えるボディは保存できません。リクエストの **例** タブに一覧が出ます。その場で名前を変えられ、▷ でレスポンスペインに表示し（「例: …」と表示されます）、ゴミ箱アイコンで削除します。例はリクエストの一部なので、Ctrl+S でファイルに `[[example]]` として書き込まれます。Postman の保存済みレスポンスはインポート時に例として取り込まれ、エクスポート時にまた書き出されます。`apix send --save-example '<name>'` でコマンドラインからレスポンスを保存できます。

![レスポンスペインに表示した例](../en/images/examples.png)

ペインが狭くてリクエストのタブがすべて入らないときは、タブバーの末尾の矢印から全タブの一覧を開けます。

## ネットワークタブ

**ネットワーク** タブでは、時間がどこにかかったのか、接続がどうだったのかがわかります。

- DNS、TCP 接続、TLS ハンドシェイク、待機、ダウンロードに分けたタイミングバー
- DNS の応答、サーバーとローカルのアドレス、ネットワークインターフェイス（VPN 使用中はその旨のヒント付き）、ゲートウェイ、DNS サーバー、プロキシ
- すべてのリダイレクト
- 圧縮されたボディの場合は、エンコーディング、転送時のサイズ、デコード後のサイズ
- 暗号化：TLS バージョン、暗号スイート、鍵交換、ALPN（サーバーが HTTP/2 を話すなら `h2`）、送信したサーバー名（SNI）、ハンドシェイクにかかった時間
- サーバーが送ってきたとおりの証明書チェーン：各証明書について発行先、発行者、有効期間と残り日数、鍵。サーバー自身の証明書については名前と SHA-256 フィンガープリントも

![ネットワークタブ](../en/images/network.png)

![暗号化と証明書チェーン](../en/images/network-tls.png)

これらはすべて、調べるために別に張った接続ではなく、リクエスト自身の接続から得たものです。送信のたびに新しい接続を開き、Apix はそのハンドシェイクで合意した内容を記録します。リクエストが独自の `Accept-Encoding` を設定していない限り、Apix は圧縮された応答（`gzip`、`deflate`、`br`）を求め、`Content-Encoding` と `Content-Length` ヘッダーはサーバーが送ったとおりに表示します。

### 経路と地図

サーバーのアドレスの下にある **経路を追跡して地図で見る…**（または **表示 › 経路と地図…**）は、このコンピューターとサーバーの間にあるルーターを、それぞれまでの時間付きで一覧にし、世界地図上に描きます。ホップはシステム自身のツール（Windows では `tracert`、それ以外では `traceroute` または `tracepath`）から取るので、管理者権限は不要です。応答しないルーターは `*` と表示されます。自分のネットワーク内のアドレスにはその旨の印が付きます。

各ルーターの位置は、このコンピューター上の IP 位置データベースから求めます。オンラインで調べることはありません。データベースがなくても一覧は動きますが、地図は空のままです。**DB-IP Lite をダウンロード** で DB-IP の無料データベース（約 130 MB、CC BY 4.0）を `<config>/Apix/geo` に取得します（セットアップと `apix geo download` でも同じことができます）。または任意の `.mmdb` 都市データベース（DB-IP Lite、MaxMind GeoLite2 City）をそこに置きます。こうしたデータベースでわかるのはせいぜい都市単位で、バックボーンのルーターについては間違っていることもあります。ターミナルでは `apix trace <url or host>` が同じ一覧を出力します。

![地図上の経路](../en/images/route.png)

スクリーンショットは実際の検索結果ではなく、小さなデモ用データベース（`cargo run -p apix-route --example demo_geo`）を使っています。

## WebSocket と Server-Sent Events

**WebSocket。** URL が `ws://` または `wss://` で始まるリクエストは WebSocket です。**送信** は **接続** に、ボディタブは **メッセージ** に変わります。ハンドシェイクでは、他のリクエストと同じく、リクエストのパラメーター、ヘッダー、認証（Bearer、Basic、API キー、OAuth 2.0 など）を使います。

![WebSocket 接続とメッセージタブ](../en/images/websocket.png)

- メッセージを入力して **送信**（または Ctrl+Enter）を押します。`{{variables}}` は送信時に埋められます。接続していなければ、Apix は先に接続し、開いたところで送信します。
- **メッセージを保存** はメッセージをリクエストファイルに `[[message]]` として保存します。Ctrl+S でファイルを保存します。保存したメッセージをクリックすると編集でき、▷ でそのまま送信します。
- レスポンスペインはログです。↑ が送信、↓ が受信で、接続からの経過時間と、接続した時刻、切断の理由（コードと理由）も表示されます。上にスクロールしない限り、新しいメッセージに追従します。
- **切断**（または Esc）で接続を閉じます。ログは次に接続するまで残ります。タブが背面にあっても接続は動き続けます。
- **バイナリメッセージ：** ボタンの横で **Base64** または **Hex** を選び、その形式でバイトを書きます（`01 02 ff`。空白と `0x` も使えます）。バイトとして読めないメッセージは送信できません。保存したメッセージは形式を保持します。バイナリメッセージはログにサイズと先頭のバイトで表示されます。
- **サブプロトコル**（メッセージタブの上部、カンマ区切り）はハンドシェイクで提示されます。ログにはサーバーが選んだものが表示されます。どれも選ばないサーバーは、ブラウザーと同じく拒否されます。
- その下の **Ping 間隔 (秒)** は、接続中にその間隔で ping を送ります（ファイルでは `[websocket] ping_interval`）。各応答はログに `2 ms で pong` のように表示されます。次の ping の時刻になっても応答がない ping があると、エラーで接続を閉じます。そのため、静かに切れた接続は切れたものとして表示されます。サーバーからの ping には常に応答します。`apix send --ping 30` も同じことをし（`--ping 0` で保存された間隔をオフにします）、接続が切れていれば 0 以外で終了します。
- `wss://` はリクエスト設定に従います。信頼する CA、クライアント証明書、「TLS証明書を検証」のオフが使えます。

**Server-Sent Events。** レスポンスが `text/event-stream` のとき、イベントは届いたそばから時刻、イベントの種類と ID、データとともに表示されます。**停止**（または Esc）でストリームを終え、届いたものは残します。サーバーが終えたストリームは整形タブに同じ一覧を表示し、生データ、ヘッダー、ネットワーク、Hex は他のレスポンスと同じです。サーバーが必要とするなら `Accept: text/event-stream` を送ってください。設定のリクエストのタイムアウトもストリームを終わらせるので、開いたままのストリームでは空欄にしておいてください。

- イベントの種類が複数あると、一覧の上に種類ごとの件数が表示されます。1 つをクリックするとその種類だけを、**すべて** で全イベントを表示します。
- **再接続**（ライブ表示内）は、ストリームが終わったり接続が切れたりしたときに、ストリームを再開します。ブラウザーと同じく、サーバーの `retry:` の時間（指定がなければ 3 秒）の後に、最後に見た ID を `Last-Event-ID` に設定して再接続します。一覧には再接続のたびに記録が残ります。イベントストリームでない応答が来ると止まり、Esc でも止まります。

コマンドラインでは、`apix send` はイベントを届いたそばから出力します（`--event TYPE` は繰り返し指定でき、その種類だけを出力します。`--reconnect` は Ctrl+C まで再接続を続けます）。WebSocket の場合は接続して保存済みのメッセージ（または `--format text|base64|hex` として読む `--message` のテキスト）を送り、両方向を出力して、`--listen` 秒後に閉じます（既定は 3、`0` はサーバーを待ちます）。`apix run` は WebSocket リクエストをスキップします。

## Socket.IO

Socket.IO リクエストは、WebSocket 上で Socket.IO 3 と 4 のサーバーと通信します。リクエストの **メッセージ** タブを開き（タブを表示するには `ws://` の URL にします）、上部で **Socket.IO** を選びます。すると URL は Socket.IO クライアントと同じく `http://`、`https://`、`ws://`、`wss://` のどれでもよくなります。リクエストファイルには `[socketio]` テーブルが入り、Socket.IO リクエストはメッセージタブで開きます。

![Socket.IO 接続：イベント、ack、バイナリ添付](../en/images/socketio.png)

- **名前空間：** 参加する名前空間です（`/chat` など）。空欄なら URL のパス（`http://localhost:3000/chat` なら `/chat` に参加）、または `/` です。**パス** はサーバーが待ち受ける場所で、サーバーが変えていなければ `/socket.io/` です。ブラウザーのネットワークタブからコピーしたアドレス（`…/socket.io/?EIO=4&transport=websocket`）もそのまま使えます。
- **認証：** 参加時に送る JSON オブジェクトです（クライアントの `auth` オプション）。`{{variables}}` は埋められます。サーバーが拒否すると、サーバーが示した理由がエラーとして表示されます。
- **イベント** はメッセージを emit するときの名前です（空なら `message`）。テキストは 1 つの引数になります。JSON はそのまま、その他のテキストは文字列として送り、空なら引数なしです。**Base64** と **Hex** はバイトをバイナリ添付として送ります。**確認応答（ack）を求める** はサーバーに確認応答を求めます。保存したメッセージはイベントと ack を保持します。
- ログには各イベントが名前付きで表示されます。↑ は emit（ack を求めたときは `ack 0`、`ack 1` …付き）、↓ は受信（サーバーが ack を求めているときは `ack 9 を待っています` 付き）、✓ はサーバーの ack とその応答内容です。バイナリ添付はサイズと先頭のバイトで表示されます。ハンドシェイクのヘッダー、パラメーター、認証と TLS の設定は WebSocket と同じく使えます。
- Apix はサーバーの ping に応答します。サーバーがクライアントを名前空間から外すと、ログにその旨が表示され、接続が閉じます。**切断**（または Esc）で名前空間を離れて接続を閉じます。

`apix send` は参加して保存済みのメッセージを emit し、イベント、ack、バイナリ添付を届いたそばから出力します。`--message TEXT`（繰り返し可）を使うと代わりにそのテキストを emit します。イベント名は `--event NAME` で指定します（既定は `message`）。`apix run` は Socket.IO リクエストをスキップします。受信した添付は `{"$binary": "<base64>"}` として書き出されます。未対応：Socket.IO 2 サーバー（Engine.IO 3）、long-polling トランスポート、サーバーが求める ack への応答。

## MQTT

URL が `mqtt://`（TLS なら `mqtts://`）で始まるリクエストは、MQTT 3.1.1 ブローカーに接続します。URL バーとサイドバーには **MQTT** と表示され、**送信** は **接続** に、ボディタブは **メッセージ** に変わります。URL でポートを指定しない限り、ポートは 1883、TLS なら 8883 です。

![MQTT 接続：サブスクリプション、パブリッシュしたメッセージと受信したメッセージ](../en/images/mqtt.png)

- **ログイン：** ユーザー名とパスワードは、認証タブの Basic の種類か、URL（`mqtt://user:password@host`）から取ります。その他の認証の種類は MQTT には使えません。ブローカーが拒否すると、その理由が表示されます。URL 内のパスワードは Apix の出力から除かれます。
- **クライアント ID** は、空欄なら接続ごとに新しくなります。**セッションを保持** は接続をまたいでセッションを保持するようブローカーに求めます。これにはクライアント ID が必要です。ブローカーがまだセッションを持っていたときはログにそう表示されます。**キープアライブ** は、アイドル時の ping の間隔（秒）です（既定は 60、0 で ping なし）。
- **サブスクリプション** は接続時に、それぞれのサービス品質（QoS）で行われます。トピックでは `+` と `#` が使えます。接続中は、▷ でその行をすぐに購読し、✕ で購読をやめます。ログには、ブローカーが受け入れたもの、拒否したものが記録されます。
- パブリッシュするには、**トピック** を入力し、QoS を選び、後から購読する人のためにブローカーにメッセージを残してほしいなら **保持** にチェックを入れ、**送信**（または Ctrl+Enter）を押します。`{{variables}}` は埋められます。**Base64** と **Hex** はバイトを送ります。空のメッセージも送れます。保持付きで送ると、ブローカーが残していたものを消します。**メッセージを保存** でリクエストファイルに保存します。
- ログには各メッセージがトピックの下に表示されます。↑ はパブリッシュ、↓ は受信で、QoS と retain フラグ付きです。QoS 1 または 2 のメッセージをブローカーが確認すると ✓ が付きます。テキストでないペイロードはサイズと先頭のバイトで表示されます。
- `mqtts://` はリクエスト設定に従います。信頼する CA、クライアント証明書、「TLS証明書を検証」のオフが使えます。リクエストのタイムアウトは接続にかかる時間を制限します（なければ 10 秒）。

`apix send` は接続して購読し、保存済みのメッセージをパブリッシュし、両方向のやりとりを出力して、`--listen` 秒後に閉じます（既定は 3、`0` はブローカーを待ちます）。`--subscribe TOPIC`（繰り返し可）でサブスクリプションを追加します。`--message TEXT` と `--topic TOPIC` を使うと、保存済みのメッセージの代わりにそれをパブリッシュします。`--qos` と `--retain` はこれらに適用されます。ブローカーがサブスクリプションを拒否したとき、またはサブスクリプションに応答せずに、あるいはメッセージを確認せずに切断したとき、終了コードは 1 になります。`apix run` は MQTT リクエストをスキップします。未対応：MQTT 5、Last Will、WebSocket 上の MQTT。

## SOAP

SOAP 呼び出しは POST で送る XML エンベロープなので、SOAP リクエストは普通のリクエストです。スクリプト、テスト、実行、履歴も他のリクエストと同じく使えます。

**WSDL から。** WSDL 1.1 ファイルを **ファイル › インポート…** で、またはそのアドレス（`http://host/service?wsdl`）を **ファイル › URL からインポート…** でインポートします。操作ごとに 1 つのリクエストを持つコレクションができ、ポートが複数あればポートごとにフォルダーができます。通常は SOAP 1.1 用と 1.2 用の 2 つです。ポートのアドレスは `baseUrl` 変数になり（ポートごとにアドレスが違えばポートごとの変数）、WSDL がインポートしているドキュメントも読み込まれます。読み込めなかったものと、SOAP でないポートは、インポートの最後に一覧表示されます。

![WSDL から作った SOAP リクエストと、サーバーが返したフォールト](../en/images/soap.png)

- **ヘッダー** はバージョンに従います。SOAP 1.1 は `Content-Type: text/xml` と `SOAPAction` を送り、SOAP 1.2 はアクションを中に含めた `application/soap+xml` を送ります。
- **ボディ** は、スキーマから作ったサンプル値入りのエンベロープです。数値は `1`、テキストは `string`、列挙型は最初の値、choice は最初の選択肢です。コメントには、何が省略可能か、何が繰り返すか、他にどんな値があるかが書かれています。省略可能な属性は省かれます。値を書き換えるか `{{variables}}` を入れ、不要なものは削除してください。
- 自分自身を含む型は、2 段目でコメント付きで止まります。

**WSDL なしで。** ボディに **XML** を選びます。ボディが空の間は、横の **SOAP 1.1** と **SOAP 1.2** でエンベロープを始め、ヘッダーを設定できます。操作とアクション（`SOAPAction`、または `Content-Type` 内の `action=`）を入力します。

**フォールト。** 応答に SOAP フォールトが含まれると、レスポンスの上の赤い行にそのコードとメッセージが表示され、`apix send` もそれを出力します。サーバーによってはステータス 200 でフォールトを送るため、テストのないリクエストは、ステータスが 200 でもフォールトがあれば失敗になります。これは `apix send`、`apix run`、Runner で同じです。テストスクリプトがある場合は、スクリプトが判断します。

未対応：WSDL 2.0（その理由を示して拒否します）、WS-Security、MTOM 添付、SOAP エンコーディング用のサンプル内の `xsi:type`（インポート時に警告します）。

## gRPC

URL が `grpc://`（TLS なら `grpcs://`）で始まるリクエストは gRPC メソッドを呼び出します。URL バーには **gRPC** と表示され、ボディタブは **メッセージ** に変わります。

![gRPC 呼び出し](../en/images/grpc.png)

1. `grpc://localhost:50051` のようにアドレスを書きます。
2. **メソッドを読み込む** で、サーバーが提供するものを問い合わせます（gRPC サーバーリフレクション）。サーバーにリフレクションがなければ、**ファイルを追加** でサービスの `.proto` ファイルまたはディスクリプタセット（`protoc --descriptor_set_out`、`buf build`、バイナリまたは JSON）を選びます。インポートはそのファイルの隣から探し、Google の well-known types は組み込まれています。`protoc` は不要です。そうしたファイルがない場合は、[.proto ファイルなしで](#proto-ファイルなしで)を参照してください。
3. メソッドを選びます。横にその種類が表示されます：単項、サーバーストリーミング、クライアントストリーミング、双方向。
4. メッセージを JSON で書くか、**サンプルメッセージ** を押してすべてのフィールドを含むメッセージを作ります。ストリームを受け取るメソッドでは、JSON の配列を書くと要素ごとに 1 つのメッセージを送ります。
5. **送信**（Ctrl+Enter）。レスポンスペインには、送ったもの（↑）と返ってきたもの（↓）が時刻付きで並び、続いてステータス（`0 OK`、または `5 NOT_FOUND` のようなコードとメッセージ）、レスポンスメタデータ、トレーラーが表示されます。ストリームはメッセージが届くたびに表示され、Esc で止められます。

ヘッダーはメタデータとして送られます。認証は HTTP と同じく、Bearer、Basic、ヘッダーの API キー、OAuth 2.0 が使えます。リクエスト設定のタイムアウト、クライアント証明書、信頼する CA、「TLS証明書を検証」も適用されます（オフにすると `grpcs://` サーバーの証明書は検証されません）。`-bin` ヘッダーは base64 として読まれます。

コマンドラインでは、`apix send` がメソッドを呼び出し（ストリームは届くたびに 1 行 1 メッセージで出力します。ステータスが OK でなければ終了コードは 0 以外です）、`apix schema` がサービスとそのメッセージを出力します。

**実行とテストでは。** `apix run` と Runner も gRPC リクエストを呼び出し、そのテストスクリプトとチェックは呼び出しを HTTP レスポンスとして扱います。ステータスは gRPC コードに対応する HTTP ステータス（`OK` は 200、`INVALID_ARGUMENT` は 400、`NOT_FOUND` は 404、`UNAUTHENTICATED` は 401 など）です。gRPC のコードとメッセージは、メタデータとトレーラーと並んで `grpc-status` と `grpc-message` ヘッダーに入ります。ボディは応答そのもの、ストリームで応答するメソッドではメッセージの JSON 配列です。そのため `pm.response.json().message` や `body.message` へのチェックは、他のリクエストと同じく動きます。単発の **送信** では、スクリプトを実行せずに呼び出しを表示します。

すべての呼び出しはログ、ステータス、メタデータとともに **履歴**（Ctrl+H）に残ります。選ぶと、終わったときの状態で呼び出しが再表示されます。

### .proto ファイルなしで

通信上、gRPC が送るのはフィールドの名前ではなく番号で、呼び出し先は `package.Service/Method` です。何から始めるにしても、最終的にこれらが正しくなければなりません。**メッセージ** の隣の **定義** タブは、手元にあるものから定義を作ります。それを貼り付け（または **ファイルを読み込む** か **メッセージを使用**）、元のデータに書かれていなければ **呼び出すメソッド** を指定して、**変換** を押します。結果は編集できる `.proto` テキストで、リクエストに保存されます。**ファイルとして保存** でファイルに書き出せます。

![JSON の例から作った定義と、一致しないときの警告](../en/images/grpc-definition.png)

| 手元にあるもの | 得られるもの |
|---|---|
| `.proto` テキスト、ディスクリプタセット（バイナリまたは JSON） | 正確です。 |
| 記述を含む生成コード：`_pb2.py`、Java の outer class、それを通した Kotlin、`.cs`、`.pb.cc`、`.pb.go`、`_pb.rb`、PHP の `GPBMetadata`、protobuf-es の `_pb.ts` | 正確です。言語を問わず、中の記述を読み取ります。 |
| 番号はあるが記述のないコード：Go の `protobuf:"…"` タグ、Rust の `#[prost(…)]`、ts-proto、betterproto、`[ProtoMember(n)]`、`@ProtoNumber(n)` | 番号と型は正しくなります。元のコードに呼び出しが書かれていなければ、呼び出しを確認してください。 |
| 手書きの型：TypeScript、Go、Rust、C#、Java、Kotlin、Python、Swift、Dart、C++ | **推測です。** フィールドは出てきた順に番号が振られます。 |
| JSON のサンプルメッセージ（省略可能な 2 つ目の欄には応答を入れます） | **推測です。** 型は値から決まり、JSON の配列はストリームになります。 |

推測の良し悪しは番号しだいです。そして **番号が間違っていても失敗はしません。間違ったフィールドが埋まるだけです。** そのため Apix はそれを決して隠しません。

- サーバーがリフレクションを提供していれば、推測の代わりにその記述を使い、違いを 1 つずつ一覧にします（`number 1 here, 7 on the server`）。
- 提供していなければ、呼び出しのたびに番号が未確認だと表示します。定義が知らない応答のフィールドは番号と値で表示されます（`1:"o-1"`）。これは型のわからない応答を読み解く方法にもなります。まったく合わない応答は、定義が原因の可能性が高いという 1 行とともに失敗します。

`protoc` が生成するその他のファイルは記述を使うだけ（`.pb.h`、Kotlin のビルダー、`.pyi`）で、gRPC のスタブには呼び出ししか含まれていません。Apix は代わりにどのファイルを使えばよいかを示します。読み取らないもの：`.proto` テキストとしての Protobuf editions（ディスクリプタセットのままになります）、タグや型からの oneof（そのフィールドは普通のフィールドになり、通信上は同じです）、ジェネリクス。

コマンドラインでは：

```bash
apix proto service_pb2.py
```

```bash
apix proto order.json --method shop.v1.Orders/Create --response answer.json --out orders.proto
```

```bash
apix proto types.ts --method shop.v1.Orders/Create --into create.apix
```

`.proto` は標準出力または `--out` に出力され、`--into` はそれをリクエストに保存します。選ぶ必要があったことは標準エラーに出力されます。`apix send`、`apix run`、`apix schema` も同じように定義を使い、`apix send` は同じ警告を出力します。実行のレポートには含まれません。

## スクリプトとテスト

**スクリプト** タブには、リクエスト用の 2 つの JavaScript スクリプトがあります。

- **リクエスト前** はリクエストを送る前に実行されます。リクエストを変更したり（`pm.request.headers.upsert(…)`、`pm.request.url.query.add(…)`、`pm.request.body.raw = …`）、変数を設定したり（`pm.environment.set("token", …)`）できます。
- **テスト** はレスポンスが届いた後に実行され、レスポンスを検査します。

```js
pm.test("status is 200", () => pm.response.to.have.status(200));
pm.test("has users", () => {
  const body = pm.response.json();
  pm.expect(body.users).to.be.an("array").that.is.not.empty;
});
```

API は Postman の `pm.*`（`apix.*` としても使えます）なので、Postman からインポートしたスクリプトはそのまま動きます。`pm.environment`、`pm.collectionVariables`、`pm.globals`（プロジェクトの変数）、`pm.variables`、`pm.request`、`pm.response`、`pm.test`、Chai 形式のアサーションを使う `pm.expect`、`pm.info`、`console.log`、そして古い `tests["…"] = …` と `postman.setEnvironmentVariable(…)` があります。

`pm.sendRequest` はスクリプトから別のリクエストを送ります。たとえば先にトークンを取得するときに使います。`pm.sendRequest(req, (err, res) => …)` と `const res = await pm.sendRequest(req)` のどちらも使えます。`require(…)` では、API スクリプトがよく使う `crypto-js`（MD5、SHA-1、SHA-2 とその HMAC、Base64/Hex/UTF-8 エンコーダー）、`uuid`、`lodash`（`_` としても）、`moment`、`ajv`、`tv4`、`chai` の機能を使えます。これらは組み込まれているので、何もダウンロードしません。ライブラリにない関数を呼ぶと、わかりやすいメッセージとともに失敗します。

スクリプトタブの 3 つ目の部分 **チェック** は、コードなしでレスポンスを検査します。各行は対象と値を比較します。対象は `status`、`time`（ms）、`size`（バイト）、`body`、`body.users[0].id` のような JSON ボディ内のパス、または `header.Content-Type` です。比較は `==`、`!=`、`>`、`>=`、`<`、`<=`、`contains`、`not contains`、`exists`、`not exists`、`matches`（`/^ok/i` のような正規表現）、`is`（JSON の型）です。値には `{{variables}}` が使えます。チェックはリクエストファイルに `[[assert]]` として保存され、アプリでも `apix run` でもテストとして表示されます。

レスポンスの値を保存するには、ステータスの隣の **{x}** ボタンを使います。値（チェックと同じ対象）と変数名を指定すると、アクティブな環境に保存されます（環境がなければコレクションの変数に保存されます）。**送信のたびに更新** にチェックを入れると、対応する `pm.environment.set(…)` の行もテストスクリプトに追加されます。

スクリプトは、それが属するものの隣に置くファイルです。リクエストの隣に `<request>.prerequest.js` と `<request>.test.js`、フォルダー内に `_folder.prerequest.js` / `_folder.test.js`、コレクションのルートに `_collection.prerequest.js` / `_collection.test.js` を置きます。外側から内側へ、つまりコレクション、フォルダー、リクエストの順に実行されます。Ctrl+S でリクエストと一緒にそのスクリプトも保存します。保存前でもエディターのテキストが使われます。

送信後、レスポンスペインには **テスト** タブ（✓ は成功、✗ は失敗とその理由）と、`console.*` の出力を表示する **コンソール** タブができます。リクエスト前スクリプトが例外を投げると、リクエストは送信されず、エラーにはどのファイルで失敗したかが示されます。スクリプトは 10 秒で停止します。

スクリプトが設定した値はどのファイルにも書き込まれません。Apix を開いている間だけ有効で（環境を切り替えると `pm.environment.set` で設定したものは消えます）、変数カードに「スクリプトが設定」と表示されます。`pm.variables.set` は 1 回の送信の間だけ有効です。

## Runner

**Runner** は多くのリクエストをまとめて送り、すべてを検査します。今いるコレクションに対しては **表示 › Runner…** または Ctrl+Shift+R で開きます。その一部だけなら、サイドバーでコレクションやフォルダーの **実行…** を使います。

![データ駆動の実行後の Runner](../en/images/runner.png)

- **リクエスト**：サイドバーの順に並んだ全リクエストで、チェックが入っています。除外するものはチェックを外し、↑ ↓ で動かすとこの実行での順序を変えられます。
- **環境**：どの環境の変数を使うか。
- **反復回数**：リクエストを何周するか。空欄なら 1 回、データファイルがあれば行ごとに 1 回です。
- **待機 (ms)**：レート制限のある API のための、リクエスト間の待ち時間。
- **同時実行数**：同時に並行して走る反復の数です。API を同時に使う複数のユーザーのようなものです。各反復はリクエストを順に送り（そのためログインのトークンは次のリクエストに届きます）、自分のスクリプトが設定したものを保持します。結果は反復ごとに並びます。空欄なら 1 つずつ順に実行します。
- **データファイル**：データ駆動の実行に使う CSV または JSON ファイル。各行が 1 回の反復で、列が変数になります。リクエストでは `{{email}}`、スクリプトでは `pm.iterationData.get("email")` です。CSV にはヘッダー行が必要です。引用符とセミコロン区切りのファイル（多くの言語の Excel）も読めます。JSON は `[{"id": 1, "email": "a@x.test"}, …]` のようなオブジェクトの配列です。
- **最初の失敗で止める**：最初に失敗したリクエストで実行を終えます。

リクエストは、テスト（スクリプトとチェック）が成功すれば成功です。テストのないリクエストは、ステータスが 2xx または 3xx なら成功です。実行中は **一時停止**、**再開**、**停止**（送信中のリクエストの後で）ができます。ダイアログを閉じても実行は止まりません。Runner を再び開けば見られます。結果をクリックすると、そのテスト、送信されなかった理由、コンソールの行が見られます。Postman と同じく、`pm.execution.setNextRequest("name")` は実行内の別のリクエストに移り、`setNextRequest(null)` は反復を終えます。

Runner は各リクエストの保存済みの版を送ります。実行前にスクリプトが設定した値は使われ、実行中のスクリプトが設定したものは実行の中だけに残ります。

実行が終わったら、**レポートを保存** で **JUnit XML**（CI のテスト表示向け）、**JSON**（起きたことすべて）、**HTML**（どのブラウザーでも開けるページ、ライトとダーク対応）として書き出します。`apix run` はターミナルから同じことをします。[コレクションを CI で実行する](workflows.md#コレクションを-ci-で実行する)を参照してください。URL に書いたパスワード（`https://user:password@host`）は、レポート、コマンドラインの出力、ログ、エラーメッセージから除かれます。リクエストファイルと URL バーには残るので、本物のパスワードには変数か認証タブを使ってください。

## フロー

**フロー** はリクエストをグラフにつなぎます。ログインしてトークンを保持し、ジョブが終わるまでポーリングし、返ってきた内容で分岐する、といったことができます。各フローはコレクション内のリクエストの隣にある `.flow` ファイルなので、リクエストと一緒に git に入ります。**表示 › フロー…** を開き、名前を入力して **作成** を押すと新しいフローができます。

![フローウィンドウ](../en/images/flows.png)

ノードは 4 種類あります。

- **リクエスト** は、コレクションのリクエストをスクリプトとテスト付きで送ります。成功したとき（成功のステータス、またはすべてのテストが成功）の結果は **ok**、それ以外は **fail** です。**レスポンスから保持** は、レスポンスの値を後続のノード用の変数にします。1 行に 1 つ、`token = $.token` のように書きます。
- **チェック** は対象と値を比較し、**yes** か **no** になります。対象は `status`、`time`（ms）、`body`、`header:Name`、最後のレスポンスに対する JSONPath（`$.items[0].id`）または jq フィルター（`.items | length`）、あるいは `{{variables}}` を含むテキストです。比較：等しい、等しくない、含む、より大きい、より小さい（両辺が数値なら数値として）、ある、ない。
- **変数を設定** は変数を設定します（`name = value` の行。`{{variables}}` が使えます）。
- **待機** は一時停止します。ポーリングのループに使います。

ノードはドラッグで動かします。つなぐには、ノードの右にある結果の点をクリックし、次に行き先のノードをクリックします。点をもう一度クリックすると行き先を付け替え、パネルの **×** で接続を外します。右のパネルでは選んだノードを編集します。ID、設定、各結果の行き先、**ここから開始**、**ノードを削除** があります。実行は **開始** ノード（なければ、どこからも矢印が来ない最初のノード）から始まり、各結果をたどって、どこにもつながらない結果で終わります。**fail** の接続がないリクエストが失敗したとき、または保持する値がなかったときは失敗します。ループも使えます。実行は 1000 ステップで止まります。

**実行** は、コレクションの変数と選んだ環境でフローを実行します。各ノードは結果に応じて緑、黄、赤になり、キャンバスの下の一覧には、保持したものや比較したものとともに全ステップが表示されます。変更は **保存** を押したときと、ウィンドウを閉じたときに保存されます。

ターミナルからは、同じフローを CI で実行できます。

```sh
apix flow list my-api
apix flow run my-api/new-user.flow --env staging --junit flow.xml
```

`--junit`、`--html`、`--markdown` は、`apix run` と同じようにフローのリクエストをレポートします。`--json` は全ステップを書き出します。サンプルコレクションには `new-user.flow` があります。

フローファイルの例：

```toml
name = "New user"

[[node]]
id = "first-user"
kind = "request"
request = "users/list-users.apix"
x = 40.0
y = 40.0
extract = { user_id = "$[0].id" }

[[node]]
id = "found"
kind = "check"
subject = "{{user_id}}"
op = "exists"
x = 300.0
y = 40.0

[[edge]]
from = "first-user"
port = "ok"
to = "found"
```

## 負荷テスト

**リクエスト › 負荷テスト…**（またはコマンドパレット）は、開いているリクエストを多数のワーカーから同時に送り、サーバーがどれだけ耐えるかを表示します。リクエスト数と毎秒のリクエスト数、失敗、50・95・99 パーセンタイルと最も遅い時間、そして 1 秒ごとのリクエストのグラフ（失敗は赤）と、黄色の目盛りで示す平均レイテンシです。

![負荷テスト](../en/images/load-test.png)

- **同時数**：同時に処理中のリクエスト数（1 から 10 000）。
- **リクエスト数**：この数だけ送ったら止めます。空欄なら制限なし。
- **時間**：この時間がたったら止めます（`30s`、`2m`、`1500ms`）。どちらもなければ 10 秒。
- **毎秒**：1 秒あたりのリクエスト数の上限で、均等に分散させます。空欄ならサーバーが応答する限りの速さです。

実際のクライアントが負荷時にするのと同じく、接続は開いたまま再利用されます（単発の送信は新しい接続を開くので、そのネットワークタブにハンドシェイクが表示されます）。変数は 1 回だけ埋められます。スクリプトは実行されず、OAuth 2.0 はトークンを 1 回だけ取得し、Digest 認証には対応していません。応答がなかったか、ステータスが 400 以上のとき、リクエストは失敗と数えます。**停止** でテストを終えます。ウィンドウを閉じても止まります。負荷テストは許可されたサーバーにだけ行ってください。

ターミナルでは `apix bench` が同じことをし、CI のジョブを失敗させることもできます。

```bash
apix bench my-api/users/list.apix -c 50 -d 30s --max-p95 300 --max-failed 1 --json bench.json
```

95 パーセンタイルが `--max-p95` ミリ秒を超えたとき、`--max-failed` パーセントを超えるリクエストが失敗したとき、または 1 つも成功しなかったとき、終了コード 1 で終わります。

## モニター

**モニター** は、コレクション、またはその中のフォルダーやリクエストをスケジュールに従って実行し、失敗し始めたときや再び成功したときに知らせます。**表示 › モニター…** で開きます。

![モニター](../en/images/monitors.png)

- **モニターを追加** では、名前、間隔（`30s`、`5m`、`1h`、`1d`、または `1h30m` のような組み合わせ。最短 `10s`）、フォルダーまたはリクエスト（空欄ならコレクション全体）、環境、Webhook を指定します。⚙ ボタンでモニターを編集し、▷ ボタンですぐに実行します。
- 各モニターには最後の結果（成功、または失敗した件数と最初の失敗）が表示され、スケジュールがオンの間は次の実行時刻も表示されます。
- **Apix を開いている間、モニターをスケジュールどおりに実行** でスケジュールをオンにします（選ぶまではオフです）。すると Apix は期限の来たモニターをバックグラウンドで 1 つずつ実行し、失敗し始めたときや再び成功したときに通知を表示します。
- **Webhook** にも同じことが伝えられます。Apix は、Slack、Discord、Mattermost、Google Chat がメッセージとして表示する `text`（と `content`）の行に、詳細（`monitor`、`status`、`passed`、`failed`、`failures`）を加えた JSON を POST します。`{{variables}}` は埋められるので、アドレスは環境のシークレットに置いておけます。

モニターはコレクションの `apix.toml` に保存されるので、git で共有されます。

```toml
[[monitor]]
name = "Health"
every = "5m"
run = "users"            # フォルダーまたはリクエスト。コレクション全体なら省略
environment = "staging"
webhook = "{{alerts_url}}"
# enabled = false        # 一覧には出るが、スケジュールでは実行しない
```

アプリを閉じているときに API を監視するには、ターミナルで、cron やタスク スケジューラから、または CI のスケジュールで `apix monitor` を実行します。[モニターで API を監視する](workflows.md#モニターで-api-を監視する)を参照してください。アプリと `apix monitor` は同じ結果のログを共有するので、どちらからでももう一方が見つけたものを確認できます。

## モックサーバー

**モックサーバー** は、コレクションのリクエストと一緒に保存された例（「例」を参照）で応答します。そのため、本物の API ができる前にフロントエンドを作ったりテストを実行したりできます。**表示 › モックサーバー…** を開き、ポートを選んで **開始** を押します。

![モックサーバー](../en/images/mock.png)

- リクエストはメソッドとパスで照合されます。パスはリクエストの URL のうちホストの後、または先頭の `{{variable}}` の後の部分なので、`{{base_url}}/users/:id` は `/users/7` に応答します。`:name` と `{{name}}` のセグメントは任意の 1 セグメントに一致し、最も文字どおりのパスが優先されます。例自身の保存されたリクエストが別の URL を持つ場合、その例はその URL に応答します。
- 例が複数あれば、ステータスが 2xx の最初の例が応答します。リクエストは `x-mock-response-name: <example>` または `x-mock-response-code: 404` ヘッダー（Postman のモックサーバーが読むもの）で別の例を選べます。
- どの応答もすべてのオリジンを許可し（CORS）、どの例から来たかを `X-Apix-Mock` で示します。`OPTIONS` のプリフライトにも応答します。
- 一致しなければ、提供中のものを JSON の一覧にして `404` を返します。
- ウィンドウには提供中のものと最近のリクエストが表示されます。追加・編集した例はすぐに提供されます。ウィンドウを閉じてもサーバーは動き続け、**停止** を押すかアプリを終了するまで止まりません。

使うには、`base_url` が `http://127.0.0.1:4010` の環境（たとえば `mock`）を追加します。ターミナルからは `apix mock my-api --port 4010` です（他のコンピューターから届くようにするには `--host 0.0.0.0`、遅いサーバーを再現するには `--delay 300`）。

## API ドキュメント

**ファイル › ドキュメントをエクスポート…**（またはサイドバーのコレクションの **ドキュメントをエクスポート…**）は、コレクションを API ドキュメントとして書き出します。どのブラウザーでも開ける目次付きの 1 つの HTML ページ（ライトとダーク対応）か、ファイル名が `.md` で終わる場合はリポジトリ向けの Markdown です。

![生成されたドキュメント](../en/images/api-docs.jpg)

内容は、コレクションの説明（Markdown）、その変数と各環境にコミットされた変数、続いてサイドバーの順にフォルダーの下に並ぶ全リクエストです。リクエストごとに、メソッド、URL、説明、パス変数、クエリ、ヘッダー、認証の種類、ボディ、チェック、保存した例が載ります。秘密の情報は出力されません。`.local.toml` ファイルとキーチェーンは読まず、認証は種類だけを示し、`Authorization`、`Cookie`、API キーのヘッダーは値が `{{variable}}` の場合にだけ値を表示します。説明内の生の HTML は除かれます。

ターミナルからは `apix docs my-api --out api.html`（または `--out API.md`。`--out` がなければ標準出力に Markdown）です。

## キャプチャ プロキシ

**キャプチャ プロキシ** は実際の通信をリクエストに変えます。**表示 › キャプチャ プロキシ…** を開き、ポート（8888）を選んで **開始** を押し、ブラウザー、アプリ、スクリプトのプロキシに `http://127.0.0.1:8888` を設定します（`HTTP_PROXY` と `HTTPS_PROXY`）。通過したリクエストはすべて、応答を例 `Captured` として付けたリクエストファイルとしてコレクションの `captured/` フォルダーに保存され、ウィンドウに一覧表示されます。

![キャプチャ プロキシ](../en/images/capture.png)

- **対象** は記録するホストを絞ります（`example.com` は `api.example.com` も含みます）。それ以外は記録されずに通過します。
- 秘密の情報は書き込まれません。`Cookie` は捨てられ、`Authorization` と API キーのヘッダーの値は変数（`{{authorization}}`）になります。
- HTTPS はプロキシが読めないトンネルを通るので、既定ではそのまま中継し、ホストだけを一覧に出します。**Apix のローカル認証局で HTTPS を開いて記録する** にチェックを入れると、Apix はローカル認証局（`<config>/Apix/capture-ca.pem`）が署名したそのホスト用の証明書で TLS ハンドシェイクに応答し、リクエストも記録します。これはその認証局が信頼されている場合にだけ動きます。ウィンドウには認証局を信頼させるコマンド（Windows では `certutil -user -addstore Root …`）が表示されます。Apix が自分で認証局をインストールすることはありません。Firefox は独自の一覧を持っています。

ターミナルからは `apix capture my-api/captured --port 8888 --only example.com` です（HTTPS を開くには `--https`、見るだけなら `--no-save`）。

## タブ

各タブは、未保存の編集、最後のレスポンス、さらにはまだ実行中のリクエストも保持します。Ctrl+Tab と Ctrl+Shift+Tab でタブ間を移動し、Ctrl+W または中クリックでタブを閉じます。未保存の変更があるタブを閉じる前には Apix が確認します。開いていたタブは、次に同じコレクションやプロジェクトを開いたときに戻ります（暗号化されたコレクションのタブは記憶されません。ファイル名も秘密だからです）。

## リクエストの整理

サイドバー上部の **リクエストを検索** 欄は、名前、メソッド、URL に入力したすべての語を含むリクエストに絞り込み（`get users` は `/users` への GET リクエストを見つけます）、そこに至るフォルダーを開きます。名前が一致したフォルダーは中身をすべて表示します。Esc または ✕ で検索を消すと、フォルダーは元の状態に戻ります。

サイドバーで右クリックすると、リクエストとフォルダーの作成、名前の変更、複製、削除ができます。削除したファイルはシステムのゴミ箱に入ります。リクエストやフォルダーを別のフォルダーの中央にドラッグすると、そこに移動します。行の上端または下端にドロップすると、その行の前または後に置かれます。どこに入るかは線で示されます。順序は `order` リストとして `apix.toml`（コレクションの最上位）と `folder.toml`（フォルダー）に保存されるので、git で共有されます。リストにない項目は名前順で後に続きます。Postman からのインポートは Postman の順序を保ち、Postman へのエクスポートはあなたの順序に従います。

## プロジェクト

**プロジェクト** は、関連する複数のコレクションをまとめ、環境と認証を共有します。**ファイル › 新しいプロジェクト…** で作成します。プロジェクトでは、**環境 › サイドバーのグループ化** でサイドバーを プロジェクト › 環境 › コレクション の形で表示できます。

- コレクションのヘッダーを別のコレクションの上または下にドラッグすると、順序が変わります。
- コレクションを右クリック › **色** で色を付けられます。サイドバーとそのリクエストのタブに点で表示されます。色は `apix-project.toml` に保存されます。
- **ファイル › プロジェクトに移動…**（コレクションを 1 つだけ開いているとき）は、そのコレクションのフォルダーを選んだプロジェクトに移動します。プロジェクトを開いているときは、ファイルマネージャーからコレクションのフォルダーをウィンドウにドロップしても同じことができます。

## Git

コレクションはただのファイルなので、コードと同じく git で管理できます。開いているコレクション（またはプロジェクト）が git リポジトリ内にあると、ステータスバーにブランチと、前回のコミット以降に変更されたファイルの数が表示され、サイドバーでは変更されたリクエストに印が付きます。**M** は変更（ファイルまたはそれ自身のスクリプト）、**A** は新規です。これらは保存のたびとディスク上の変更のたびに更新され、ウィンドウが前面に戻ったときにも再読み込みされるので、ターミナルでコミットすると消えます。

![ブランチと変更されたリクエスト](../en/images/git-status.png)

ステータスバーのブランチ（または **表示 › Git…**）をクリックすると Git ウィンドウが開きます。左側には前回のコミット以降に変更されたファイルと最近のコミットがあります。ファイルを選ぶと、`apix diff` と同じ形で変更内容が表示されます。リクエストはフィールドごと（`query._limit: 5 → 10`、追加されたヘッダーなど）、スクリプトやその他のテキストは行ごとで、書式だけが変わった場合は何も表示されません。その下でメッセージを書いて **コミット** を押します。開いているフォルダー内のすべての変更が対象で、フォルダーの外のものは含みません。ブランチメニューでブランチを切り替え、**新しいブランチ** は横に入力した名前でブランチを作って切り替えます。**Pull**（fast-forward のみ）と **Push**（初回は upstream を設定）は、あなた自身の設定、フック、認証情報で git を実行します。ブランチを切り替えるとサイドバーもすぐに追従します。

![Git ウィンドウ](../en/images/git-window.png)

コマンドラインでは、`apix run --changed` が変更に関係するリクエストだけを送り、`apix diff` がその変更内容をフィールドごとに表示します。プルリクエストでは GitHub Action が結果をコメントできます。[変更されたものだけ](workflows.md#変更分だけgit-を考慮した実行)を参照してください。

## 暗号化されたコレクション

暗号化されたコレクションは、すべてのリクエスト、環境、さらにはファイル名までディスク上で暗号化して保存します（Argon2id のパスワード鍵を使う XChaCha20-Poly1305）。git からは、どの暗号化された blob が変わったかしか見えません。

- **ファイル › このコレクションを暗号化…** またはコレクションを右クリック › **暗号化…** で、既存のコレクションをその場で暗号化します。
- **ファイル › 新しい暗号化コレクション…** はプロジェクト内に新しく作ります。
- **回復キー** は一度だけ表示されます。安全な場所に保管してください。パスワードを失ったときにコレクションを開けます。
- コレクションを開くとパスワードを求められます。**ファイル › 暗号化されたコレクションをロック** を選んだとき、Apix を終了したとき、または設定で決めた時間（既定は 15 分）操作しなかったときに再びロックされます。
- ロック解除の画面で **このコンピューターで記憶する** にチェックを入れると、パスワードがシステムの資格情報ストア（Windows では資格情報マネージャー、macOS ではキーチェーン、Linux では Secret Service）に保存されます。以後、サインインしている間はコレクションが確認なしで開き、`apix` コマンドラインも保存したパスワードを使います。**ファイル › 保存したパスワードを削除**（またはコレクションを右クリック）で削除します。パスワードが他の場所で変更された場合は、保存したパスワードは捨てられ、Apix が再び尋ねます。

## 形式を指定してコピーと curl の貼り付け

**送信** の隣のコピーボタン（または **リクエスト › 形式を指定してコピー**）は、変数を埋めた状態で、リクエストを bash や fish 用の `curl`、Windows コマンドプロンプト用の `curl.exe`、PowerShell の `Invoke-RestMethod` 呼び出し、HTTPie の `http` コマンド（HTTPie 3.0 以降）、GNU の `wget` コマンドとしてコピーします。wget は multipart フォームを送れないので、コピーしたコマンドにその旨が書かれます。送信ごとに署名するリクエスト（OAuth 1.0、PowerShell とコードでの AWS）は、コピーした時点で署名されます。

同じメニューで、リクエストをプログラムとしてもコピーできます。JavaScript の `fetch`、Node.js の axios、Python の requests、Go の `net/http`、Rust の reqwest、C# の `HttpClient`、Java の `HttpClient`、PHP の cURL、Swift の `URLSession`、Kotlin の OkHttp です。どれも Apix が送るもの（URL、ヘッダー、認証、すべてのボディの種類）を送り、その言語で表せるリクエスト設定（タイムアウト、リダイレクト、TLS の検証、プロキシ、クライアント証明書）も含みます。言語に簡単な切り替えがない設定は、黙って捨てずに、先頭の `Not in this snippet` コメントに列挙されます。サイドバーでは、リクエストを右クリックして **コードとしてコピー** を使います。

CLI も同じものを書き出します：`apix code request.apix --as python`（`apix shell` は同じコマンドです。`--as` には `bash`、`cmd`、`powershell`、`fetch`、`axios`、`python`、`go`、`rust`、`csharp`、`java`、`php`、`swift`、`kotlin` を指定します）。

`curl` コマンド（たとえばブラウザーの「cURL としてコピー」で得たもの）を URL 欄に貼り付けると、Apix がメソッド、URL、クエリ、ヘッダー、認証、ボディを含むリクエスト全体を埋めます。

## Postman からのインポート

**ファイル › インポート…** を使うか、Postman のエクスポートをウィンドウにドロップします。コレクション（v2.0 と v2.1）と環境に対応しています。フォルダー、リクエスト、ボディ、認証、変数が引き継がれ、Apix がまだ引き継げないものはレポートに一覧表示されます。リクエスト前スクリプトとテストスクリプトは、リクエストの隣の `.js` ファイルとして保存され、環境のシークレットは gitignore された `.local.toml` に入ります。

**多数のファイルを一度に。** Postman のエクスポートを入れたフォルダー（または Postman の *Export data* が作る zip）を開くかドロップすると、Apix はファイルを名前ではなく内容で見分け、すべてを 1 つのプロジェクトとしてインポートすることを提案します。Postman のコレクションごとに 1 つのコレクション、すべてで共有する環境、そしてプロジェクトの変数としてのグローバル変数です（プロジェクトの変数はコミットされるので、シークレットのグローバル変数は除かれます）。同じ名前の環境が 2 つあれば、`name` と `name-2` として残します。

**Postman へのエクスポート。** コレクションを右クリックして **Postman にエクスポート…**（または **ファイル › Postman にエクスポート…**）を選ぶと、Postman v2.1 のコレクションファイルと、環境ごとに 1 つの環境ファイルを書き出します。Postman を使うチームメイトも引き続き作業できます。フォルダー、認証、ボディ、スクリプト、変数、そしてリダイレクト、TLS、Cookie の設定が引き継がれます。Postman にはリクエストごとのタイムアウト、プロキシ、クライアント証明書がなく、環境のシークレットの値は名前だけがエクスポートされます。除かれたものは通知に一覧表示されます。

コマンドラインでは、`apix import <file, folder or zip>` と `apix export <collection> --out <folder>` です。

## Insomnia, OpenAPI, HAR からのインポート

**ファイル › インポート…**（またはウィンドウへのファイルのドロップ）はこれらの形式も読み込みます。形式は内容で判別され、フォルダーや zip に混在していてもかまいません。

| 形式 | 得られるもの |
|---|---|
| Insomnia v4（JSON エクスポート） | ワークスペースごとに 1 つのコレクション、認証付きのフォルダー、コレクションの変数としてのベース環境、そして環境としての各サブ環境。`{{ _.name }}` は `{{name}}` になります。 |
| OpenAPI 3 / Swagger 2（JSON または YAML） | 操作ごとに 1 つのリクエスト、タグごとに 1 つのフォルダー。サーバーは `baseUrl` 変数になり（サーバーが複数なら、それぞれ環境に）、パスパラメーターはサンプル値付きの変数になり、必須のクエリパラメーターとヘッダーパラメーターはオンになります。ボディは例から取るか、スキーマから作ります。セキュリティスキームは、環境で埋めるための空の認証情報変数（`bearerToken`、`apiKey` など）を使う認証になります。 |
| WSDL 1.1 | 操作ごとに、サンプルのエンベロープ付きのリクエストを 1 つ作ります。[SOAP](#soap) を参照してください。 |
| HAR（ブラウザーの DevTools の「Save all as HAR」） | API 呼び出しのみで、ホストごとに 1 つのフォルダー。スクリプト、スタイル、画像、フォント、`data:` URL、繰り返しは除かれます。`Cookie` ヘッダーもブラウザーのセッションを運ぶので除かれます。 |

1 つのファイルから得た 1 つのコレクションはコレクションとしてインポートされ、複数あればプロジェクトになります。引き継げなかったものはすべてレポートに一覧表示されます。

## 履歴

送信したリクエストは、すべてレスポンスとともに保存されます。**表示 › 履歴…**（Ctrl+H）は、新しい順に、メソッド、名前、URL、ステータス、送信日時とともに一覧表示します。入力すると、これらのどれでも検索できます。項目を選ぶと、リクエストは送信元のタブに未保存の編集として、受け取ったレスポンスと一緒に戻ってきます。Ctrl+Enter で再送信し、Ctrl+S でその版を保存します。リクエストファイルがなくなっている場合は、タブなしでエディターに開きます。

履歴はこのコンピューター（設定の隣の `history` フォルダー）に残り、コレクションの中に入ることはありません。リクエストは `{{variables}}` を解決しない書いたままの形で保存されるので、環境のシークレットが履歴にコピーされることはありません。最新の 300 件のリクエストを保存し、レスポンスボディはそれぞれ 256 KB までです。暗号化されたコレクションのリクエストは履歴に書き込まれません。ウィンドウの **履歴を消去** で空にでき、**ファイル › 設定… › 履歴** でオフにできます。

## レスポンスの比較

レスポンスの横の **⇄**（または **リクエスト › レスポンスを比較…**）は、今のレスポンスを同じリクエストの別のレスポンスと並べます。

- **以前のレスポンス**：履歴にあるそのリクエストのレスポンスで、新しい順です。1 つを選ぶと、それ以降に何が変わったかがわかります。昨日の応答にさかのぼるにはこれを使います。
- **他の環境**：別の環境でリクエストを送り直したもの（本番環境に対するステージング、本物の API に対するモックなど）。

違いの数、続いてステータス、名前ごとのヘッダー、ボディが表示されます。JSON はフィールドごとに比較します（リスト内のレコードは `id`、`_id`、`uuid`、`key` で対応付けるので、順序の違うリストは変更になりません。フィールドは `[id=1].email` のように示します）。その他のテキストは行ごとに比較します。レスポンスごとに変わるヘッダー（Date、リクエスト ID、キャッシュ、ボディの送り方）は除かれ、最後に一覧表示されます。**テキストとしてコピー** で結果をコピーします。

![以前のレスポンスとの比較](../en/images/compare.png)

ターミナルでは、`apix compare <request> --env staging --against production` が両方の環境でリクエストを送り、違いを出力します。違いがあれば終了コード 1 で終わるので、パイプラインで 2 つの環境が同じように応答するかを確認できます。履歴は 256 KB までのボディを保存するので、それより長いボディは保存された範囲で比較されます。

## AI アシスト

AI アシストは、**ファイル › 設定… › AI アシスト** でオンにするまでオフです。Apix はオープンソースで、自前の AI アカウントは持っていません。提供元を選び、自分の API キーを指定します。

- **AI の提供元**：Claude（Anthropic）、ChatGPT（OpenAI）、Gemini（Google）。
- **モデル**：提供元の既定のモデル（Claude Opus 5.5、`gpt-5.5`、`gemini-2.5-flash`）。または **↻** で自分のキーが使えるモデルを読み込んで選びます。
- **API キー**：上の提供元用のキーで、ファイルではなくシステムキーチェーンに保存されます。空欄で保存すると削除されます。キーがなければ `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`GEMINI_API_KEY` が使われます。

すると、レスポンスにボタンが 1 つ増えます。

- 成功したレスポンスには **AI テスト**：AI がステータス、コンテンツタイプ、ボディの形を検査するテストスクリプトを書き、Apix がそれをリクエストのテストに追加します（AI が書いたことを示す印付きで、未保存のまま）。保存する前に読んで確認できます。
- 失敗したレスポンス（400 以上）には **説明**：レスポンスの意味、考えられる原因、確認すべきことをアプリの言語で説明します。

![失敗したレスポンスの説明](../en/images/ai-explain.png)

提供元に送るもの：リクエストのメソッド、URL、ヘッダー、ボディと、レスポンスのステータス、ヘッダー、ボディ（12 KB で切り詰め）。Authorization、Cookie、そして名前に key、token、secret、signature を含むヘッダーは ••• で伏せられます。AI は間違えることがあります。あなたの操作なしに何かが変更されたり、他の場所に送られたりすることはありません。スクリーンショットは本物の応答ではなく、ローカルのテストサーバーに対して撮ったものです。

## プラグイン

プラグインは、Apix に組み込まれていないものを追加します。認証の種類、別のファイル形式のインポーター、レスポンスのビューです。プラグインは 1 つの WebAssembly（`.wasm`）ファイルで、サンドボックス内で動きます。JSON を受け取って JSON を返し、ネットワーク、ファイル、時計は使えません。実行時間が長すぎたりメモリを使いすぎたりすると停止されます。他人のプラグインが変更できるのは、署名するリクエストかインポートするコレクションだけで、それ以外には触れません。

**表示 › プラグイン…** は、インストール済みのプラグインと、それぞれが提供するものを一覧表示します。**ファイルからインストール…** は `.wasm` ファイルを検査してプラグインフォルダー（`<config>/Apix/plugins`）にコピーし、**削除** はそれを削除し、**フォルダーを開く** はフォルダーを表示し、**再読み込み** は自分でファイルをコピーした後にフォルダーを読み込み直します。

![プラグインウィンドウ](../en/images/plugins.png)

- **認証の種類** は、認証タブの一覧に「… (プラグイン)」として、プラグインが求める欄とともに表示されます（欄では `{{variables}}` が使えます）。リクエストの送信時に、プラグインは最終的なリクエスト（メソッド、URL、ヘッダー、ボディ）を受け取り、ヘッダーやクエリパラメーターを追加します。プラグインがインストールされていないリクエストはその旨を表示し、送信されません。

  ![プラグインが署名したリクエスト](../en/images/plugin-auth.png)

- **ビュー** は、JSON レスポンスの上のテキスト、表、グラフの隣に表示されます。プラグインはステータス、ヘッダー、ボディを読み、表かテキストで応答します。

  ![プラグインのビュー](../en/images/plugin-view.png)

- **インポーター** には、プラグインウィンドウに **ファイルをインポート…** ボタンがあります。ファイルはその隣に新しいコレクションとして作られ、そのまま開きます。

リクエストファイルでは、プラグインの認証は次のようになります。

```toml
[auth.plugin]
plugin = "hmac-signature"

[auth.plugin.config]
key_id = "k1"
secret = "{{signing_secret}}"
```

ターミナルからは：

```sh
apix plugins list                     # インストール済みのプラグインと提供するもの
apix plugins install my-plugin.wasm
apix plugins remove my-plugin
apix import endpoints.csv --plugin csv-endpoints --out shop
apix send posts/list-posts.apix --view json-stats
```

リポジトリの `plugins/` フォルダーには、`crates/apix-plugin-sdk/examples` からビルドした 3 つの例があります。**hmac-signature**（メソッド、パス、ボディのハッシュに対する HMAC-SHA256 でリクエストに署名）、**csv-endpoints**（`method,url,name,folder` の CSV リストがリクエストになる）、**json-stats**（JSON リストのフィールド統計：型、出現、異なる値の数、範囲）です。

### プラグインを書く

Rust では、`apix-plugin-sdk` に依存し、その `Plugin` トレイトを実装して `export!` を呼びます。

```rust
use apix_plugin_sdk::{Plugin, export, serde_json::{Value, json}};

struct Hello;

impl Plugin for Hello {
    fn manifest() -> Value {
        json!({ "name": "hello", "version": "1.0.0",
                "visualize": { "label": "Hello" } })
    }
    fn call(_hook: &str, input: Value) -> Result<Value, String> {
        let size = input["body"].as_str().unwrap_or("").len();
        Ok(json!({ "text": format!("{size} bytes") }))
    }
}

export!(Hello);
```

クレートを `cdylib` として `cargo build --release --target wasm32-unknown-unknown` でビルドし、`.wasm` をインストールします。マニフェストの `name`（英小文字、数字、`-`）は、リクエストがプラグインを参照するときの名前です。プラグインは次のどれでも提供できます。

| マニフェストのキー | フックが受け取るもの | 応答 |
|---|---|---|
| `auth: {label, fields: [{name, label, secret}]}` | `{method, url, headers, body, config}` | `{headers: [[name, value]], query: [[name, value]]}` |
| `import: {label, extensions}` | `{file_name, content}` | `{name, requests: [{folder, name, method, url, headers, body}]}` |
| `visualize: {label}` | `{status, headers, body}` | `{title, text}` または `{title, columns, rows}` |

WebAssembly にコンパイルできる言語なら何でも使えます。モジュールは `memory`、`apix_alloc(len) -> ptr`、`apix_manifest() -> i64`、`apix_call(hook_ptr, hook_len, input_ptr, input_len) -> i64` をエクスポートします。`i64` は UTF-8 の JSON 応答（`{"ok": …}` または `{"error": "…"}`）の `ptr << 32 | len` です。モジュールは何もインポートしてはならず、呼び出しはそれぞれ新しいインスタンスで実行されます。

## セットアップ

初回起動時、Apix は **セットアップ** を開きます。任意の追加機能を 1 か所にまとめたものです。**ヘルプ › セットアップ…** で再び開けます。どれもなくても Apix は動きます。

- **IP 位置データベース**：経路の地図と `apix trace` で各ルーターの位置を示します。**ダウンロード** で DB-IP の無料の都市データベース（約 130 MB、CC BY 4.0）を `<config>/Apix/geo` に取得し、**更新** で最新月の版を取得します。オンラインで調べることはありません。ターミナルでは `apix geo download`、`apix geo status`、`apix geo remove` です。
- **AI アシスト**：オンかどうか、どの提供元かを表示します。**設定を開く** でその設定項目に移動します。
- **Claude (MCP)**：開いているコレクションに対する **Claude に接続**（**ヘルプ › Claude に接続 (MCP)…** からも）です。下で説明します。

![セットアップ](../en/images/setup.png)

### Claude に接続する

**Claude に接続** は、開いているコレクションを Claude 用の MCP サーバーにします。これで Claude は変数の値を見ることなく、リクエストを一覧表示し、送信し、テスト付きで実行できます（[MCP](workflows.md#ai-エージェントにコレクションを使わせるmcp) を参照）。

- **Claude Desktop に追加** は、Claude Desktop の `claude_desktop_config.json` に `apix-<collection>` というエントリーを書き込みます。他のサーバーと設定はそのまま残り、初回は元のファイルが `.bak` にコピーされます。使うには Claude Desktop を再起動してください。**削除** でエントリーを取り除きます。
- **Claude Code に追加** は `claude mcp add --scope user …` を実行するので、コレクションはすべてのプロジェクトで使えます。
- **一覧のみ** は、一覧表示のツールだけを Claude に与えます（`--list-only`）。
- エントリーとコマンドはどちらも **コピー** ボタン付きで表示されるので、手で追加することもできます。

![Claude に接続](../en/images/claude-connect.png)

ターミナルからも同じことができます：`apix mcp my-api --add-to claude-desktop`、`apix mcp my-api --add-to claude-code`、`apix mcp my-api --remove-from-claude-desktop`。

## 設定と言語

**ファイル › 設定…**（Ctrl+,）：

- **言語：** English、Türkçe、العربية、Deutsch、Français、Русский、日本語、简体中文、Español。変更はすぐに反映されます。初回起動時、Apix はシステムの言語に従います。アラビア語ではウィンドウが左右反転します。サイドバーは右にあり、メニュー、タブ、フォームは右から並びますが、URL、コード、キーと値の表は左から右のままです。
- **暗号化されたコレクションのロック：** 5 分、15 分、30 分、1 時間後、またはしない。
- **環境のシークレット：** `.local.toml` ファイルまたはシステムキーチェーン（[変数と環境](#変数と環境)を参照）。
- **本番環境で確認する：** 「prod」環境がアクティブな間、DELETE、PUT、PATCH の前に確認します（既定はオン）。
- **アップデートを確認：** 起動時に、新しい Apix がリリースされているかを GitHub に問い合わせます（既定はオン）。送るのはその 1 つのリクエストだけで、あなたを識別する情報は含まず、何もダウンロードしません。新しいリリースがあると、そのページを開く **ダウンロード** ボタン付きの通知が表示されます。**ヘルプ › アップデートを確認…** でいつでも確認でき、ターミナルでは `apix update` が同じことをします。

![新しいリリースのお知らせ](../en/images/update.png)

- **履歴：** オンまたはオフ（[履歴](#履歴)を参照）。

設定の **外観** の部分では、Apix の見た目を再起動なしですぐに変えられます。

- **外観モード：** ダーク、ライト、または **システムに従う**。最後のものは、Windows や macOS がライトモードとダークモードを切り替えると一緒に切り替わります。
- **ダークテーマ：** オブシディアン（既定）、サイバーグラス、Dracula、Nord、Solarized Dark。**ライトテーマ：** デイライト、Solarized Light。もう一方の種類のテーマを選ぶと、外観モードもそちらに切り替わります。
- **アクセントカラー：** テーマの色、またはシアン、ブルー、パープル、ピンク、レッド、オレンジ、イエロー、グリーン。ボタン、選択範囲、フォーカスリング、変数のチップに使われます。ライトテーマでは濃い色合いになり、アクセント上の文字は読みやすいほうの黒か白になります。
- **透明度：** 0（不透明なウィンドウ）から 90% までのスライダーです。デスクトップがどれだけ透けて見えるかを決め、すりガラスのようにぼかされます（Windows ではアクリル、macOS ではバイブランシー）。ウィンドウの背景はそれに合わせて透け、パネルは文字の下地が残るようにゆるやかに透け、枠線はガラスの縁のように明るくなります。メニューとダイアログは不透明のままです。暗い文字には明るい下地が必要なので、ライトテーマはより控えめに透けます。既定は 20% です。
- **文字サイズ：** 通常サイズの 90%、100%、110%、125%、150%。ウィンドウ内のすべての文字に一度に適用されます。
- **コードの文字サイズ：** コードエディター（ボディ、スクリプト、レスポンスの整形ビュー）用の 11〜18 px。非常に大きなボディ用のビューアーは 13 px のままです。
- **表示密度：** サイドバーの行をコンパクト、標準、ゆったりのいずれかにします。
- コードエディターは色をテーマから取ります。文字列、数値、キーワードはテーマの指定どおり、型と関数はアクセントカラー、コメントと句読点は控えめな色です。

![文字サイズ、コードの文字サイズ、表示密度](../en/images/look.png)

- **自作テーマ：** **フォルダーを開く** で `<config>/Apix/themes` を開き、初回はそこに出発点となる `my-theme.toml` を書き込みます。そのフォルダー内のすべての `.toml` ファイルが一覧にテーマとして並びます。組み込みテーマと同じ名前のファイル（`nord.toml`）はそのテーマを置き換えます。読み込めないファイルは、理由とともに赤字で表示されます。

![設定](../en/images/settings.png)

テーマファイルでは、名前、ライトかどうか、そして次の色を任意に設定します（`#RRGGBB`、または不透明度付きの `#RRGGBBAA`）。省いた色は Obsidian から、ライトテーマなら Daylight から取ります。

```toml
name = "Deep sea"
light = false

[colors]
background = "#03141FEE"      # ウィンドウ。background_end へのグラデーション
background_end = "#062A3AEE"
surface = "#05202DB3"         # パネル
raised = "#0A2B3BF7"          # メニューとダイアログ
border = "#FFFFFF14"
accent = "#FF9F43"
text = "#E8F6FF"
muted = "#7FA3B8"
ok = "#34D399"                # 2xx、成功したテスト
warning = "#FBBF24"
error = "#F87171"
string = "#86EFAC"            # 大きなボディ用ビューアーの JSON
number = "#FDBA74"
keyword = "#C4B5FD"
```

テーマファイルはただのテキストなので、チームで共有できます。Apix は起動時と設定を開いたときに読み込みます。

設定は、システムの設定ディレクトリにある Apix フォルダーの `settings.toml` に保存されます（Windows では `%APPDATA%\Apix`、macOS では `~/Library/Application Support/Apix`、Linux では `~/.config/Apix`）。
