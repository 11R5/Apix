# ملاحظات تقنية

كيف يُبنى Apix، وعلى ماذا يعتمد، وكيف يُقاس أداؤه. تشرح
[البنية](architecture.md) التصميم؛ وهذه الصفحة هي الجانب العملي.

## بنية المستودع

```
crates/
├── apix-core       نموذج الطلب، المتغيرات، صيغة الملفات على القرص، المشاريع، التوقيع (sign.rs)، مخططات GraphQL، git (git.rs، diff.rs)
├── apix-http       محرك HTTP (reqwest)، تتبع الشبكة، رموز OAuth 2.0، SSE، WebSocket، Socket.IO، جلب مخطط GraphQL
├── apix-import     استيراد Postman وInsomnia وOpenAPI وHAR وWSDL

├── apix-runner     تشغيل المجموعات، ملفات البيانات، تقارير JUnit/JSON/HTML/Markdown
├── apix-grpc       استدعاءات gRPC: ملفات .proto، انعكاس الخادم أو تعريفات من الشيفرة ومن JSON، الرسائل بصيغة JSON
```

## البناء

المتطلبات: [Rust](https://rustup.rs) بنسخته المستقرة (المستودع مختبَر مع 1.99).

- **Windows:** سلسلة أدوات MSVC ‏(Visual Studio أو Build Tools مع حزمة العمل
  "Desktop development with C++" وحزمة Windows 10/11 SDK).
- **macOS:** أدوات سطر الأوامر الخاصة بـ Xcode.
- **Linux:** حزم التطوير لـ X11/Wayland وVulkan وfontconfig التي يحتاجها GPUI
  (يسردها ملف README الخاص بـ gpui-kit لكل توزيعة)؛ لم تُختبر بعد.

```sh
cargo test                       # المحرك، سطر الأوامر، الاستيراد، توليد الشيفرة، الخزنة، فحص التوثيق
cargo run -p apix-desktop        # تطبيق سطح المكتب (نسخة تصحيح)
cargo test -p apix-desktop       # اختبارات وحدات سطح المكتب (الترجمات، المسارات، …)
cargo build --release            # سطر أوامر مُحسَّن
cargo build --release -p apix-desktop
```

يتخطى `cargo build` و`cargo test` دون `-p` تطبيقَ سطح المكتب، لأنه يجلب معه
حزمة الرسوميات كاملة؛ ابنه صراحةً. تُحسَّن الاعتماديات حتى في نسخ التصحيح كي
تبقى الواجهة سلسة أثناء التطوير.

تحتاج الإضافات الأمثلة في `plugins/` إلى هدف WebAssembly مرة واحدة
(`rustup target add wasm32-unknown-unknown`)، ثم
`cargo build -p apix-plugin-sdk --examples --release --target wasm32-unknown-unknown`؛
انسخ `target/wasm32-unknown-unknown/release/examples/*.wasm` إلى `plugins/`
(مع `-` بدل `_` في الأسماء). تحمّل اختبارات `apix-plugins` هذه الملفات.
يُحسَّن `wasmi` ويُبنى دون تأكيدات التصحيح في نسخ التصحيح أيضًا
(`[profile.dev.package.wasmi]`): فحلقة المفسّر فيه تعتمد على استدعاءات ذيلية
تتجاوز المكدس لولا ذلك.

يستخدم ملف تعريف الإصدار fat LTO ووحدة توليد شيفرة واحدة ورموزًا محذوفة. يستغرق
بناء إصدار كامل لتطبيق سطح المكتب بضع دقائق.

## الاعتماديات الرئيسية

| المجال | الحزم (crates) |
|---|---|
| الواجهة | `gpui-kit` 0.7 (GPUI ومكتبة مكوناته)، قواعد tree-sitter لـ JSON وGraphQL |
| HTTP | `reqwest` 0.12 مع rustls، `tokio`، `hyper-util`، طبقات `tower` للتوقيت |
| gRPC | `tonic` 0.14 (العميل، فوق hyper وrustls نفسيهما)، `prost-reflect` (رسائل تُعرف وقت التشغيل، JSON)، `protox` (يقرأ ملفات .proto دون `protoc`)، `regex` (قراءة الشيفرة المولَّدة والأنواع)، `tonic-reflection` (عميل الانعكاس)، `rustls` و`tokio-rustls` لـ gRPC مع إيقاف فحص الشهادات؛ `rcgen` يصنع شهادات الاختبار (للاختبارات فقط) |
| تفاصيل الشبكة | `x509-parser` (الشهادات)، `sha2` (البصمات)، `netdev` (الواجهات، البوابة، خوادم DNS)؛ تفاصيل TLS عبر خطافات rustls نفسها (دون حزمة إضافية)؛ `flate2` و`brotli-decompressor` يفكّان ضغط المتون (مبنيّتان أصلًا لـ reqwest)؛ المسار من أداة النظام `tracert` أو `traceroute` أو `tracepath`، والمواقع من `maxminddb` |
| التوقيع | `sha2`، `sha1`، `hmac`، `md-5`، `base64`، `rand_core` ‏(AWS SigV4، OAuth 1.0، Digest، PKCE) |
| التشفير | `chacha20poly1305` ‏(XChaCha20-Poly1305)، `argon2`، `zeroize`، `keyring` (مخزن بيانات الاعتماد في النظام) |
| السكربتات | `rquickjs` ‏(QuickJS، مبني من C بمترجم النظام)؛ مكتبات `require` هي شيفرة JavaScript خاصة بـ Apix، والتجزئة عبر `sha1` و`sha2` و`md-5` و`hmac` |
| الملفات | `serde`، `toml`، `serde_json`، `notify` (مراقبة الملفات)، `trash`؛ git عبر برنامج `git` المثبّت (دون مكتبة) |
| الاستجابات | `serde_json_path` ‏(JSONPath، RFC 9535) و`jaq-core` و`jaq-std` و`jaq-json` ‏(jq) للتصفية؛ `regex` للبحث في المتون الكبيرة |
| الإضافات | `wasmi` 2 (مفسّر WebAssembly بحدود للوقود والذاكرة) |
| اللغات | `rust-i18n` (مشتركة مع gpui-kit)، `sys-locale` |

## الملفات التي يكتبها Apix خارج المجموعات

| الملف | المحتوى |
|---|---|
| `<config>/Apix/settings.toml` | اللغة، المظهر، السمة الداكنة والفاتحة، لون التمييز، الشفافية، مدة القفل التلقائي، تشغيل السجل أو إيقافه، أين تُحفظ أسرار البيئات، وهل تعمل المراقِبات ما دام التطبيق مفتوحًا |
| `<config>/Apix/capture-ca.pem`، `capture-ca.key` | سلطة الشهادات المحلية لوكيل الالتقاط، تُصنع أول مرة يُفتح فيها HTTPS؛ ولا يُوثق بها إلا إذا أضفتها بنفسك |
| `<config>/Apix/geo/*.mmdb` | قاعدة بيانات مواقع IP لخريطة المسار (تُنزَّل من نافذة **المسار والخريطة**، أو توضع هناك يدويًا) |
| `<config>/Claude/claude_desktop_config.json` | لا يكتبه إلا **الاتصال بـ Claude**: المدخل `apix-<collection>` تحت `mcpServers` (مع حفظ الأصل باسم `.json.bak`) |
| `<config>/Apix/monitors/` | آخر 500 نتيجة لكل مراقِب، سطر JSON واحد لكل تشغيل (`<hash of the collection folder>-<monitor name>.jsonl`)، يكتبها `apix monitor` والتطبيق |
| `<config>/Apix/state.toml` | المجموعات المفتوحة مؤخرًا، والبيئة المختارة، والألسنة المفتوحة لكل مجموعة أو مشروع (لا ينطبق على المجموعات المشفّرة) |
| `<config>/Apix/cookies.json` | وعاء ملفات تعريف الارتباط (لا تُحفظ ملفات تعريف ارتباط الجلسة) |
| `<config>/Apix/graphql/*.json` | آخر مخطط GraphQL جُلب من كل نقطة نهاية (إجابة الخادم على الاستبطان)، مسمّى بتجزئة الرابط |
| `<config>/Apix/themes/*.toml` | سماتك الخاصة (لا يُكتب فيها شيء إلا مثال واحد، حين تضغط **فتح المجلد** في **الإعدادات** والمجلد فارغ) |
| مخزن بيانات الاعتماد في النظام، الخدمة `Apix` | عند الطلب فقط: كلمات مرور المجموعات المشفّرة المحفوظة (`vault:<folder>`) وأسرار البيئات (`env:<id>`، ثم `env:<id>#1`، … للقيم الطويلة)، ومفاتيح مساعد الذكاء الاصطناعي ‏(`ai:anthropic-api-key`، `ai:openai-api-key`، `ai:google-api-key`) |
| `<config>/Apix/plugins/*.wasm` | الإضافات المثبّتة (نافذة **الإضافات**، `apix plugins install`) |
| `<config>/Apix/history/` | الطلبات المرسلة (مع بقاء `{{variables}}` دون استبدال) واستجاباتها: `index.jsonl`، وملف `<id>.json` وملف `<id>.body` لكل مدخل؛ آخر 300، والمتون مقطوعة عند 256 KB؛ استدعاء gRPC يحفظ سجله كمتن |

`<config>` هو `%APPDATA%` على Windows، و`~/Library/Application Support` على macOS
و`~/.config` على Linux. لا تُكتب رموز OAuth 2.0 ولا كلمات مرور المجموعات
المشفّرة على القرص أبدًا.

## متغيرات البيئة

| المتغير | الأثر |
|---|---|
| `APIX_PASSWORD` | كلمة مرور مجموعة مشفّرة لسطر الأوامر (`--password-env` يختار متغيرًا آخر). |
| `APIX_VAR_<NAME>` | متغير لسطر الأوامر: `APIX_VAR_TOKEN` يملأ `{{token}}` (يُطابَق مع أسماء المجموعة أيًّا كانت حالة الأحرف)؛ يتقدّم على البيئات، و`--var` يتقدّم عليه. |
| `APIX_THEME` | معرّف سمة (`obsidian`، `cyber`، `dracula`، `nord`، `solarized-dark`، `daylight`، `solarized-light` أو اسم ملف سمة)؛ يعرض تلك السمة بغض النظر عن الإعدادات. |
| `APIX_BENCH` | `startup` أو `json:<url>`: يقيس ثم يُغلق (انظر أدناه). |
| `APIX_BENCH_OUT` | ملف تُضاف إليه القياسات. |
| `APIX_BENCH_PHASES` | مع `APIX_BENCH=startup`: يذكر أيضًا متى بُلغت كل خطوة من خطوات بدء التشغيل (أسطر `phase_…`)، لمعرفة أين يذهب الوقت. |
| `APIX_UPDATE_URL` | الجهة التي يسألها فحص التحديثات بدل أحدث إصدار على GitHub (نسخة متفرعة، مرآة، خادم اختبار). |
| `OPENAI_API_KEY`، `GEMINI_API_KEY` (أو `GOOGLE_API_KEY`)، `ANTHROPIC_API_KEY` | مفتاح مساعد الذكاء الاصطناعي حين لا يكون هناك مفتاح محفوظ في سلسلة المفاتيح لذلك المزوّد. |
| `APIX_CLAUDE_CONFIG` | ملف إعداد Claude Desktop الذي يكتبه **الاتصال بـ Claude**، بدل الملف الحقيقي (للاختبارات). |
| `APIX_AI_URL` | الجهة التي يرسل إليها مساعد الذكاء الاصطناعي طلبات Messages API بدل Anthropic (وكيل، خادم اختبار). |
| `APIX_GEO_URL` | الجهة التي ينزّل منها **تنزيل DB-IP Lite** بدل DB-IP. |
| `APIX_PLUGINS_DIR` | مجلد الإضافات، بدل `<config>/Apix/plugins`. |
| `GITHUB_BASE_REF` | يضبطه GitHub Actions في طلبات الدمج: `apix run --changed` دون قيمة يقارن مع `origin/<it>`. |

## قياس الأداء

يبني `scripts/measure.ps1` نسخة الإصدار من التطبيق ويقيس:

- حجم **الملف التنفيذي للإصدار**.
- **من البدء إلى أول إطار:** من `main` حتى رسم أول إطار
  (`APIX_BENCH=startup`)، الوسيط لعدة تشغيلات.
- **الذاكرة في حالة الخمول:** مجموعة العمل بعد خمس ثوانٍ من البدء مع فتح
  مجموعة المثال.
- **JSON كبير على الشاشة:** طلب GET لمتن JSON بحجم 100 MB من المثال المحلي
  `big_json_server`، من الإرسال حتى رسم الاستجابة
  (`APIX_BENCH=json:<url>`)، فلا تدخل الشبكة في الرقم.

```powershell
powershell -File scripts/measure.ps1          # Windows PowerShell
pwsh scripts/measure.ps1 -NoBuild -Runs 7     # PowerShell 7، وعلى macOS/Linux أيضًا
```

يطبع السكربت جدول Markdown مع الجهاز الذي شُغّل عليه؛ ويعرض ملف README آخرها.
تأتي التوقيتات من `crates/apix-desktop/src/bench.rs`، الذي لا يفعل شيئًا ما لم
يُضبط `APIX_BENCH`.

أدوات مساعدة أخرى:

```sh
cargo run -p apix-http --release --example big_json_server -- 100   # ‏100 MB من JSON على :8765
cargo run -p apix-http --example oauth_server                       # خادم اختبار OAuth 2.0 على :8766
cargo run -p apix-http --example sse_server                         # أحداث مرسلة من الخادم على :8767 (يستأنف بعد Last-Event-ID)
cargo run -p apix-http --example ws_server                          # صدى WebSocket (والثنائي أيضًا) ومؤشر نبض على :8768
cargo run -p apix-http --example graphql_server                     # نقطة نهاية GraphQL (مخطط وبضعة مستخدمين) على :8769
cargo run -p apix-http --example socketio_server                    # Socket.IO 4: مساحات الأسماء /، /chat، /ticker، /private (مصادقة) على :8771
cargo run -p apix-grpc --example grpc_server                        # خدمة Greeter بـ gRPC مع الانعكاس على :8770
cargo run -p apix-http --example soap_server                        # آلة حاسبة SOAP على :8773 (WSDL عند ?wsdl؛ أخطاء مع 500 و200)
cargo run -p apix-proto --example mqtt_broker                       # وسيط MQTT على :8772 (`clock` ينبض كل ثانية)
```

## لغات الواجهة

نصوص الواجهة موجودة في `crates/apix-desktop/locales/<code>.yml`، بصيغة
`key: value` مسطحة في كل سطر، يقرؤها rust-i18n عبر الماكرو `tr!`. يفشل اختبار
وحدة حين ينقص لغةً مفتاحٌ أو تستخدم `%{placeholders}` غير التي في الإنجليزية.
لإضافة لغة، انسخ `en.yml` وترجمه وأضف سطرًا واحدًا إلى `LANGUAGES`
في `src/i18n.rs`.

## واجهة gpui الخلفية المضمّنة في المستودع

كان عارض النصوص في GPUI على Windows (الحزمة `gpui-pre-windows` 0.3.9) يضع كل
سلسلة من الحروف من اليسار إلى اليمين، فكانت الكلمات العربية تظهر معكوسة.
`vendor/gpui-pre-windows` هو تلك الحزمة مع إصلاح `DrawGlyphRun` (التغيير مُعلَّم
بعبارة "Apix patch")، ويستبدلها بها ملف `Cargo.toml` الخاص بمساحة العمل. يمكن
إزالتها حين تُصلح الحزمة الأصلية.

## التكامل المستمر

يعمل `.github/workflows/ci.yml` عند كل دفع وكل طلب دمج:

| المهمة | ما الذي تفحصه |
|---|---|
| التنسيق والتوثيق | `cargo fmt --check`؛ `docs-check` (الترجمات تتبع التوثيق الإنجليزي) |
| المحرك وسطر الأوامر | `cargo clippy -D warnings` و`cargo test` لكل شيء عدا تطبيق سطح المكتب، على Windows وmacOS وLinux |
| تطبيق سطح المكتب | الأمر نفسه لـ `apix-desktop` على الأنظمة الثلاثة (يثبّت Linux مكتبات النوافذ والخطوط وسلسلة المفاتيح أولًا) |
| GitHub Action | إجراء المستودع نفسه (`uses: ./`) على `examples/jsonplaceholder`، على Linux وWindows، والتحقق من أنه كتب تقاريره |

يبني `.github/workflows/release.yml` حزم الإصدار عند وسم إصدار
(`v1.2.3`، ويجب أن يطابق `Cargo.toml`) وينشرها كإصدار على GitHub
مع `SHA256SUMS.txt`؛ وإذا شُغّل يدويًا فإنه يبنيها فقط، كمخرجات للتشغيل.
Windows: ‏`scripts/package-windows.ps1` ‏(Inno Setup 6،
`packaging/windows/apix.iss`: تثبيت لكل مستخدم أو لكل جهاز، مع إضافة اختيارية إلى PATH
وربط ملفات `.apix`، ومزيل تثبيت). macOS: ‏`scripts/package-macos.sh`
يبني المعماريتين، ويجمعهما بـ `lipo` في `Apix.app` (موقَّع توقيعًا مخصّصًا ad-hoc)
ويصنع ملف `.dmg`. Linux (على Ubuntu 22.04، فيكفي glibc 2.35):
`scripts/package-linux.sh` يصنع أرشيف tarball مع `install.sh`، وحزمة `.deb`
(الاعتماديات من `dpkg-shlibdeps`، إضافة إلى `libvulkan1`) وملف `PKGBUILD` مملوءًا؛
ويبني `scripts/package-arch.sh` منها حزمة Arch داخل
حاوية `archlinux`. تُثبَّت حزمة `.deb` وحزمة Arch داخل
سير العمل ويُفحص نقص المكتبات فيهما. ينشر `.github/workflows/pages.yml`
المجلد `site/` على https://11r5.github.io/Apix/ .
يحمل كل إصدار أيضًا وصفة Homebrew cask مملوءة (`apix.rb`، من
`packaging/homebrew`) وبيانات winget ‏(`AhmetDemir.Apix*.yaml`، من
`packaging/winget`)، يصنعها `scripts/channel-manifests.sh`، لتُنسخ إلى
مستودع الـ tap ‏([11R5/homebrew-apix](https://github.com/11R5/homebrew-apix))
وإلى طلب دمج في `microsoft/winget-pkgs`. يكتب `scripts/action-repo.sh`
ملفات [11R5/apix-action](https://github.com/11R5/apix-action)، وهي
نسخة Marketplace من `action.yml` التي تنزّل إصدارًا دائمًا (لا يُدرج
Marketplace مستودعًا فيه ملفات سير عمل)؛ وبعد كل إصدار يحصل على وسم `v<version>`
وينتقل `v1` إلى الإيداع الجديد.
ينشر `.github/workflows/docker.yml` صورة الحاوية عند وسوم الإصدارات.
يخزّن الإجراء نسخة `apix` التي يبنيها مؤقتًا تحت تجزئة لمصادر المحرك،
فيعيد الإيداع الجديد بناءها ويعيد الإيداع غير المتغيّر استخدامها.
